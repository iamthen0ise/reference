Конспект к вопросу «какую версию Python используете и что в ней появилось»: по версиям 3.11–3.15 только то, что реально спрашивают и что пригодится бэкенд-разработчику, без пересказа release notes. Сверено с официальными «What's New» (docs.python.org/3/whatsnew); примеры с выводом запущены на самих версиях (3.11, 3.12, 3.13, 3.14, 3.15).
Рядом: [[Типизация и модели данных]] · [[Потоки и процессы]] · [[Исключения]]
Разделы: [[#Python 3.11]] · [[#Python 3.12]] · [[#Python 3.13]] · [[#Python 3.14]] · [[#Python 3.15]] · [[#Что спросят дальше]]

**База (до 3.11).** Считается, что это знают: 3.8 — walrus `:=` (только там, где иначе значение считается дважды), 3.10 — `match`/`case` и `X | Y` в аннотациях (3.9 — `list[int]` и `dict | dict`). Всё ниже — сверх этого.

**Как отвечать.** Назвать версию, затем 2–3 пункта, которые влияют на работу: скорость (3.11), синтаксис дженериков (3.12), `TaskGroup`/`except*` (3.11), `t`-строки и отложенные аннотации (3.14), free-threaded (3.13 экспериментально, 3.14 официально). Не перечислять всё подряд: интервьюер ждёт, что вы знаете, зачем это нужно и что сломается при апгрейде.

## Python 3.11

Главное — скорость и исключения для async-кода.

- **Быстрее на 10–60%** (в среднем около 1,25× на наборе бенчмарков) за счёт Faster CPython: специализирующий адаптивный интерпретатор (PEP 659), вызовы Python→Python не занимают C-стек, «бесплатные» исключения (`try` без исключения не стоит ничего), старт на 10–15% быстрее. Код менять не надо — просто обновить версию.
- **`ExceptionGroup` и `except*`** (PEP 654) — несколько несвязанных исключений одним объектом; `except*` отбирает подгруппы по типам. Нужны из-за `TaskGroup`.
- **`asyncio.TaskGroup`** — структурная конкурентность: упала одна задача — остальные отменяются, ошибки собираются в `ExceptionGroup`. Замена `gather` в новом коде.
- **`asyncio.timeout()`** — контекстный менеджер вместо `wait_for`; можно ставить на блок кода.
- **`tomllib`** (PEP 680) — чтение TOML из стандартной библиотеки (только чтение, запись не поддерживается).
- **`typing.Self`** (PEP 673) — тип «экземпляр своего класса» для `return self` и фабрик; плюс `LiteralString`, `Required`/`NotRequired` для `TypedDict`, `TypeVarTuple`.
- **Точные места ошибок в трейсбеке** (PEP 657) — `^^^^` указывает на конкретное выражение, а не на строку.
- **`add_note()`** (PEP 678) — дописать контекст к исключению, не теряя его; заметка печатается в трейсбеке.
- Мелочи: `enum.StrEnum`, `hashlib.file_digest()`, `datetime.UTC`, ключ `-P` / `PYTHONSAFEPATH` (не добавлять каталог скрипта в `sys.path`).

`TaskGroup` и `except*` вместе (запущено на 3.11):

```python
import asyncio

async def fail(name, exc):
    raise exc(name)

async def main():
    try:
        async with asyncio.TaskGroup() as tg:
            tg.create_task(fail("a", ValueError))
            tg.create_task(fail("b", KeyError))
    except* ValueError as eg:
        print("ValueError:", eg.exceptions)
    except* KeyError as eg:
        print("KeyError:", eg.exceptions)

asyncio.run(main())
```

```text title="Вывод"
ValueError: (ValueError('a'),)
KeyError: (KeyError('b'),)
```

Обычный `except ValueError` здесь ничего не поймал бы: наружу вылетает `ExceptionGroup`, а не `ValueError`. Подробнее — [[Исключения#ExceptionGroup и except*]].

Точное место ошибки (запущено на 3.11):

```python
d = {"user": {"name": None}}
print(d["user"]["name"].upper())
```

```text title="Вывод"
    print(d["user"]["name"].upper())
          ^^^^^^^^^^^^^^^^^^^^^^^
AttributeError: 'NoneType' object has no attribute 'upper'
```

Подчёркнуто всё выражение `d["user"]["name"]`, значение которого оказалось `None`: раньше пришлось бы гадать, какое из обращений в цепочке дало `None`.

Что убрали или объявили устаревшим: модули PEP 594 («мёртвые батарейки»: `cgi`, `telnetlib`, `pipes`, `crypt` и др.) в 3.11 только помечены, удалены в 3.13; `asynchat`, `asyncore`, `smtpd` — на удаление в 3.12.

## Python 3.12

Главное — синтаксис дженериков и f-строки; производительность в мелочах.

- **Синтаксис параметров типа** (PEP 695): `def first[T](xs: list[T]) -> T`, `class Repo[T]:`, оператор `type Pair[K] = tuple[K, K]`. Не нужны `TypeVar`/`Generic`; дисперсия выводится автоматически. Для generic-репозиториев и сервисов — самое заметное изменение.
- **F-строки по PEP 701** — внутри можно те же кавычки, переносы строк, комментарии и обратный слеш, вложенность произвольная. Сообщения об ошибках в f-строках стали точнее.
- **Инлайнинг comprehensions** (PEP 709) — comprehension больше не создаёт функцию на каждый запуск, до 2× быстрее; в трейсбеке нет отдельного кадра `<listcomp>`.
- **`itertools.batched(iterable, n)`** — режет итерируемое на кортежи длины `n` (последний может быть короче). Раньше писали руками для пакетной вставки в БД.
- **`@typing.override`** (PEP 698) — type checker ругается, если метод ничего не переопределяет (переименовали в базе — подкласс молча «отвалился»).
- **`asyncio`**: eager task factory (`asyncio.eager_task_factory`) — задача начинает выполняться сразу при создании и, если не блокируется, завершается без захода в цикл; на некоторых нагрузках в 2–5× быстрее.
- **Per-interpreter GIL** (PEP 684) — у субинтерпретаторов свой GIL, но только через C API; из Python это стало доступно в 3.14.
- **`sys.monitoring`** (PEP 669) — дешёвый API для профайлеров, отладчиков и покрытия.
- **Улучшенные сообщения об ошибках**: подсказки «Did you mean» для `NameError` (в том числе `self.attr` внутри метода) и `import x from y`.
- **Удалено**: `distutils` (PEP 632; нужен `setuptools`), `imp`, `asyncore`, `asynchat`; `venv` больше не ставит `setuptools`.
- **Устарело**: `datetime.utcnow()` и `utcfromtimestamp()` — вместо них `datetime.now(UTC)`; `os.fork()` в многопоточном процессе даёт `DeprecationWarning`.

Дженерики, `type`, `batched` и f-строка с теми же кавычками (запущено на 3.12):

```python
from itertools import batched

def first[T](xs: list[T]) -> T:
    return xs[0]

class Repo[T]:
    def __init__(self) -> None:
        self.items: list[T] = []

type Pair[K] = tuple[K, K]

print(first([1, 2]), Repo[int]().items, Pair.__value__)
print(list(batched(range(7), 3)))
songs = ["a", "b"]
print(f"{", ".join(songs)}")
```

```text title="Вывод"
1 [] tuple[K, K]
[(0, 1, 2), (3, 4, 5), (6,)]
a, b
```

До 3.12 последняя строка была синтаксической ошибкой: внутри `f"..."` нельзя было использовать `"`. Подробности про `TypeVar` и дисперсию — в [[Типизация и модели данных]].

## Python 3.13

Главное — задел на будущее: free-threaded и JIT, оба экспериментальные и выключены по умолчанию.

- **Free-threaded сборка** (PEP 703) — режим без GIL, отдельный исполняемый файл `python3.13t`. Экспериментальный; на одном потоке медленнее. Проверка: `sys._is_gil_enabled()`; включить GIL обратно — `PYTHON_GIL=1` или `-X gil=1`. Расширения на C должны явно заявить поддержку. Подробнее — [[Потоки и процессы#GIL]].
- **Экспериментальный JIT** (PEP 744) — copy-and-patch, включается при сборке (`--enable-experimental-jit`), выигрыш скромный. В продакшн не берут.
- **Новый REPL** — многострочное редактирование, цветной промпт, `exit` и `help` без скобок, режим вставки F3. Цветные трейсбеки по умолчанию (управление: `NO_COLOR`, `PYTHON_COLORS`).
- **`locals()`** (PEP 667) — в функциях возвращает независимый снимок, запись в него не влияет на локальные переменные; `frame.f_locals` для отладчиков стал write-through-прокси. Код с `exec()` и расчётом на изменение локальных надо переписать на явное пространство имён.
- **Типизация**: значения по умолчанию у параметров типа (PEP 696), `typing.TypeIs` (PEP 742, сужение типа в обе ветки), `typing.ReadOnly` для `TypedDict` (PEP 705), `warnings.deprecated()` (PEP 702).
- **Удалено**: 19 модулей PEP 594 (`cgi`, `telnetlib`, `crypt`, `pipes`, `uu`, `imghdr` и др.), `lib2to3`; если код их импортирует, ставится из PyPI или заменяется.
- **Мобильные платформы**: iOS (PEP 730) и Android (PEP 738) — tier 3.

Разница `locals()` между 3.12 и 3.13 (запущено на обеих):

```python
def f():
    x = 1
    snap = locals()
    x = 2
    locals()
    return snap["x"]
print(f())
```

```text title="Вывод"
3.12: 2
3.13: 1
```

В 3.12 функция `locals()` обновляла один и тот же словарь при каждом вызове, поэтому `snap` «поумнел» после второго вызова; в 3.13 `snap` — замороженная копия.

## Python 3.14

Главное — отложенные аннотации, `t`-строки, субинтерпретаторы и официальный free-threaded.

- **Отложенные аннотации** (PEP 649, PEP 749) — аннотации не вычисляются при определении функции или класса, а вычисляются при первом обращении. Строки в кавычках для forward-ссылок больше не нужны; `from __future__ import annotations` для этого не требуется. Модуль `annotationlib` отдаёт аннотации в форматах `VALUE`, `FORWARDREF`, `STRING`. Ломается код, который читал `__annotations__` во время импорта и рассчитывал на строки.
- **`t`-строки** (PEP 750) — `t"hi {name}"` даёт не `str`, а `string.templatelib.Template` со статическими частями и интерполяциями отдельно. Ради безопасных шаблонов: HTML, SQL, логи — подстановки можно экранировать до склейки.
- **`return`/`break`/`continue` в `finally`** (PEP 765) — `SyntaxWarning`: `return` в `finally` проглатывает исключение.
- **`except A, B:` без скобок** (PEP 758) — если нет `as`; семантика та же, что у `except (A, B):`.
- **Субинтерпретаторы** (PEP 734) — модуль `concurrent.interpreters` и `InterpreterPoolExecutor`: параллелизм без общего GIL и без накладных расходов процесса, но данные передаются копированием.
- **Free-threaded поддерживается официально** (PEP 779) — перестал быть экспериментальным, специализирующий интерпретатор работает и без GIL, замедление на одном потоке около 5–10%. Включается отдельной сборкой, расширения должны быть совместимы.
- **`multiprocessing`**: на Unix (кроме macOS) метод запуска по умолчанию теперь `forkserver`, а не `fork`; код, полагавшийся на наследование состояния при `fork`, перестаёт работать.
- **Отладка живого процесса**: `python -m asyncio ps PID` — таблица задач, `python -m asyncio pstree PID` — дерево ожидания; `python -m pdb -p PID` — подключиться отладчиком (PEP 768, `sys.remote_exec`).
- **`uuid.uuid7()`** (а также `uuid6`, `uuid8`, RFC 9562) — идентификаторы, упорядоченные по времени: лучше для первичных ключей и B-tree-индексов, чем случайный `uuid4`. `uuid4()` стал быстрее примерно на 30%.
- **`asyncio.iscoroutinefunction()` устарел**, удаляется в 3.16 — использовать `inspect.iscoroutinefunction()`. Там же устарела система политик цикла событий (`get_event_loop_policy()` и т. п.): вместо неё `asyncio.run(..., loop_factory=...)`. `asyncio.get_event_loop()` без текущего цикла теперь бросает `RuntimeError`, а не создаёт цикл молча.
- **Прочее**: `compression.zstd` (PEP 784, Zstandard в стандартной библиотеке), опциональный интерпретатор с хвостовыми вызовами (на 3–5% быстрее при сборке Clang 19+), сообщения об ошибках с подсказками опечаток в ключевых словах. Инкрементальный GC из 3.14.0–3.14.4 откатили к поколенческому в 3.14.5.

Отложенные аннотации и `t`-строка (запущено на 3.14):

```python
def f(x: Later) -> Later:
    return x

class Later: ...

print(f.__annotations__)
```

```text title="Вывод"
{'x': <class '__main__.Later'>, 'return': <class '__main__.Later'>}
```

На 3.11 тот же код падает на самом `def`: `NameError: name 'Later' is not defined`. В 3.14 определение функции не вычисляет `Later`, обращение к `__annotations__` происходит позже, когда класс уже есть.

```python
from string.templatelib import Template
name = "<b>x</b>"
t = t"hi {name}"
print(type(t).__name__, t.strings, [i.value for i in t.interpolations])
```

```text title="Вывод"
Template ('hi ', '') ['<b>x</b>']
```

Статические куски (`strings`) и значения (`interpolations`) лежат раздельно — обработчик сам решает, как экранировать `name`. Про `return` в `finally` — [[Исключения#try, except, else, finally]].

## Python 3.15

Данные ниже сверены с What's New 3.15 и запущены на 3.15.0.

- **Явные ленивые импорты** (PEP 810) — мягкое ключевое слово `lazy`: `lazy import json` не загружает модуль, пока имя не понадобится. Уменьшает время старта CLI и воркеров; также включается глобально через `-X lazy_imports` или `PYTHON_LAZY_IMPORTS`.
- **UTF-8 по умолчанию** (PEP 686) — `open()` без `encoding` теперь читает и пишет в UTF-8, не в кодировке локали; отключается `PYTHONUTF8=0` или `-X utf8=0`. Убирает класс ошибок «на Windows читает в cp1251».
- **`frozendict`** (PEP 814) — встроенный неизменяемый словарь, хешируемый, если ключи и значения хешируются; не подкласс `dict`.
- **`sentinel`** (PEP 661) — встроенный способ создать уникальный маркер «значения нет» вместо `_MISSING = object()`.
- **Распаковка в comprehensions** (PEP 798) — `[*p for p in parts]`, `{**d for d in dicts}`: сплющить список списков без `chain`.
- **Пакет `profiling`** (PEP 799) — `profiling.tracing` (прежний `cProfile`) и `profiling.sampling` (сэмплирующий профайлер Tachyon, низкие накладные расходы, подключается к работающему процессу); модуль `profile` устарел, удаляется в 3.17.
- **JIT** заметно улучшен: по данным документа около 7–8% на x86-64 Linux по сравнению со стандартным интерпретатором; по-прежнему экспериментальный. `mimalloc` — аллокатор по умолчанию.
- **Файлы запуска пакетов** (PEP 829) — `.start`-файлы вместо строк `import` в `.pth`; последние тихо объявлены устаревшими.
- **Frame pointers по умолчанию** (PEP 831) — внешние профайлеры (perf и др.) видят стек Python-кода.
- **Стабильный ABI для free-threaded** (PEP 803, `abi3t`) — расширения собираются один раз под free-threaded сборки.
- **Библиотека**: `asyncio.TaskGroup.cancel()`, `tomllib` с TOML 1.1.0, `re.prefixmatch()` (синоним `match()`, который не удалят), `argparse` по умолчанию подсказывает похожие команды при ошибке, `json` с параметром `array_hook`, `math.integer`.
- **Типизация**: `TypeForm` (PEP 747), `@disjoint_base` (PEP 800), `TypedDict` с `closed` и `extra_items` (PEP 728). `typing.ByteString` убран из `__all__`, keyword-синтаксис `NamedTuple("P", x=int)` удалён.
- **Сборщик мусора**: поколенческий GC из 3.13 возвращён (инкрементальный из 3.14.0–3.14.4 откатили).

Новое одной проверкой (запущено на 3.15):

```python
lazy import json
import sys
print("json" in sys.modules)
print(json.dumps({"a": 1}))
print("json" in sys.modules)

fd = frozendict(a=1, b=2)
print(fd, hash(fd) is not None)
parts = [[1, 2], [3]]
print([*p for p in parts])
```

```text title="Вывод"
False
{"a": 1}
True
frozendict({'a': 1, 'b': 2}) True
[1, 2, 3]
```

Модуль не попал в `sys.modules` после `lazy import` и загрузился только при первом `json.dumps`. Это одновременно и риск: ошибки импорта и побочные эффекты модуля переезжают на момент первого использования.

## Что спросят дальше

- **Какую версию используете и зачем обновлялись?** Названная версия плюс причина: скорость (3.11), `TaskGroup` и `except*`, дженерики `[T]` (3.12). Хороший ответ — что сломалось при апгрейде: `distutils`, `datetime.utcnow()`, `locals()`, метод запуска `multiprocessing`.
- **Что такое `ExceptionGroup` и чем `except*` отличается от `except`?** Группа хранит несколько исключений; `except*` разбирает её по типам, может сработать несколько веток, непойманное остаётся в новой группе. Обычный `except` на группе ловит только если подходит сама группа. См. [[Исключения]].
- **Free-threaded: что это и можно ли в продакшн?** Сборка без GIL (3.13 — экспериментально, 3.14 — официально, замедление на одном потоке порядка 5–10%); выигрыш только для CPU-bound кода на нескольких потоках, расширения должны быть совместимы, код всё равно нужно защищать локами. См. [[Потоки и процессы]].
- **Чем отложенные аннотации (3.14) отличаются от `from __future__ import annotations`?** Future-import превращает аннотации в строки, а в 3.14 они вычисляются лениво при первом обращении и остаются настоящими объектами; строки в кавычках для forward-ссылок не нужны. См. [[Типизация и модели данных]].
- **Зачем нужны `t`-строки, если есть f-строки?** f-строка склеивает сразу и отдаёт `str`, `t`-строка сохраняет части раздельно, и код может экранировать подстановки для SQL/HTML до склейки.
- **Чем новый синтаксис дженериков PEP 695 лучше `TypeVar`?** Не нужно объявлять переменную отдельно, область видимости ограничена функцией или классом, дисперсия выводится; плюс оператор `type` для алиасов.
- **Почему в декораторе проверять `inspect.iscoroutinefunction`, а не `asyncio.iscoroutinefunction`?** Второй устарел в 3.14 и удаляется в 3.16.
