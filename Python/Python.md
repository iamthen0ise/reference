## Короткие ответы

**Изменяемость и ссылки.** Имя — ссылка на объект, присваивание ничего не копирует; `is` сравнивает объекты, `==` — значения. Аргумент передаётся как ссылка на объект: `append` внутри функции виден снаружи, перепривязка имени — нет. Значение по умолчанию вычисляется один раз при `def`, поэтому `def f(x=[])` копит данные между вызовами — пишут `x=None`. `copy` копирует только верхний уровень, `deepcopy` — всё дерево. Ключом словаря может быть только хэшируемый объект: кортеж со списком внутри — нет. → [[Типы и изменяемость]]

**Области видимости и замыкания.** Имя ищется по LEGB: локальная, объемлющая функция, модуль, встроенные. Что имя локальное, решается при компиляции: присваивание ниже по функции даёт `UnboundLocalError` на чтении выше. Замыкание хранит ссылку на переменную, а не значение: `[lambda: i for i in range(3)]` вернёт `2, 2, 2`; лечат аргументом по умолчанию `lambda i=i: i` или `partial`. Тело класса не является объемлющей областью для методов и comprehension. → [[Области видимости и замыкания]]

**Исключения.** `except Exception` не ловит `KeyboardInterrupt`, `SystemExit` и `asyncio.CancelledError` — они наследуют `BaseException`, а голый `except:` ловит и их. `raise X from err` пишет причину в `__cause__`, неявная цепочка — в `__context__`, `from None` её прячет. `else` выполняется, если исключения не было; `return` в `finally` глотает исключение, с 3.14 это `SyntaxWarning`. → [[Исключения]]

**Импорт.** Модуль выполняется один раз и кэшируется в `sys.modules`. Циклический импорт падает, когда `from a import x` просит имя у модуля, который ещё не дошёл до его определения; лечат выносом общего кода, импортом внутри функции или `import a` вместо `from a import x`. `from x import y` копирует ссылку: подмена `x.y` потом не видна — поэтому патчат там, где имя используют. → [[Импорт и модули]]

**Типизация и модели данных.** Аннотации в рантайме не проверяются — это работа mypy или pyright. Generics с 3.12 пишут `def first[T](xs: list[T]) -> T`. `Protocol` — структурная типизация (подходит любой объект с нужными методами), ABC — номинальная (нужно наследование). `dataclass` — контейнер без валидации, `NamedTuple` — кортеж (равен обычному кортежу, доступен по индексу), pydantic `BaseModel` — валидация и приведение на входе. Вместо `tuple[Decimal, Decimal]` в возврате берут frozen dataclass: поля не перепутать. → [[Типизация и модели данных]]

**Что нового.** 3.11 — заметно быстрее, `ExceptionGroup` и `except*`, `TaskGroup`, `asyncio.timeout`, точное место ошибки в трейсбеке. 3.12 — generics через `def f[T]` и `type Alias = ...`, f-строки без ограничений на кавычки. 3.13 — экспериментальные сборка без GIL и JIT, новый REPL, определённая семантика `locals()`. 3.14 — отложенные аннотации, t-строки, `except A, B` без скобок, предупреждение на `return` в `finally`, сборка без GIL официально поддерживается. 3.15 — `lazy import`, `frozendict`. → [[Что нового в Python]]

**Декоратор.** Функция, которая принимает функцию и возвращает обёртку; `@d` над `def f` — это `f = d(f)`, выполняется один раз при импорте. Обёртке всегда ставят `functools.wraps`, иначе теряются имя, документация и сигнатура (ломаются логи, FastAPI, Celery). Декоратор с параметрами — лишний уровень вложенности. Для `async def` нужна асинхронная обёртка с `await`, иначе декоратор работает с корутиной, а не с выполнением. → [[Декораторы]]

**Повтор с задержкой (retry).** Ловить только переданные временные ошибки, задержка растёт экспоненциально с потолком и случайным разбросом (jitter), на последней попытке — голый `raise`. Не ловить `BaseException`, чтобы не глушить отмену. Повторять только идемпотентные операции. → [[Декораторы#Декоратор с параметрами: повтор при ошибках с экспоненциальной задержкой]]

**Итератор и генератор.** Итерируемый объект отдаёт итератор через `__iter__`; итератор отдаёт элементы через `__next__` и одноразовый. Генератор — функция с `yield`, самый короткий способ написать итератор: состояние хранится в замороженном кадре функции. Ленивый, держит в памяти один элемент. Асинхронный вариант — `__aiter__`/`__anext__` или `async def` с `yield`, обходится через `async for`. → [[Итераторы и генераторы]]

**Контекстный менеджер.** `__enter__` на входе, `__exit__` на выходе при любом исходе; `True` из `__exit__` глотает исключение. Если упал `__enter__`, `__exit__` не вызовется. Асинхронный — `__aenter__`/`__aexit__` и `async with`. → [[Контекстные менеджеры]]

**contextlib.** `@contextmanager` превращает генератор с одним `yield` в менеджер; очистку обязательно оборачивать в `try/finally`, иначе при исключении она не выполнится. `ExitStack` — когда число ресурсов заранее неизвестно. Ещё `suppress`, `closing`/`aclosing`, `nullcontext`. → [[Контекстные менеджеры#contextlib]]

**`__new__`, `__init__`, `__call__`.** `C()` вызывает `type.__call__`, тот — `__new__` (создать объект), потом `__init__` (заполнить), если `__new__` вернул экземпляр `C`. `__new__` нужен для наследования от неизменяемых типов и контроля числа экземпляров. `__call__` делает объект вызываемым как функцию. → [[Создание объектов]]

**MRO и C3.** Порядок, в котором ищутся методы при наследовании. C3: потомок раньше родителей, порядок родителей сохраняется, порядок у родителя не ломается у потомка. Считается слиянием MRO родителей: берём первую голову списка, которой нет ни в одном хвосте. `super()` идёт к следующему классу в MRO объекта, а не к родителю. → [[MRO и super]]

**`__slots__`.** Фиксированный набор атрибутов вместо `__dict__`: меньше памяти (с 3.11 выигрыш около 40%, а не в разы), опечатка в имени атрибута сразу даёт ошибку. Ловушки: подкласс без слотов возвращает `__dict__`, два родителя со слотами несовместимы, `cached_property` не работает. Удобно — `@dataclass(slots=True)`. → [[Атрибуты и дескрипторы#Слоты]]

**Виды параллелизма.** Потоки — для блокирующего ввода-вывода; процессы — для вычислений; asyncio — для тысяч соединений в одном потоке; субинтерпретаторы и сборка без GIL — новые способы считать параллельно в одном процессе. → [[Потоки и процессы#Виды параллелизма]]

**GIL.** Блокировка в CPython: Python-байткод в каждый момент выполняет один поток. Отпускается на вводе-выводе и в C-расширениях, поэтому потоки ускоряют ожидание, но не вычисления. Не делает код потокобезопасным: «проверить, потом действовать» ломается. С 3.14 есть официально поддерживаемая сборка без GIL, но не по умолчанию. → [[Потоки и процессы#GIL]]

**GC.** Основной механизм — подсчёт ссылок: счётчик дошёл до нуля — объект удалён сразу. Циклы находит поколенческий сборщик: он смотрит только контейнеры и удаляет группы, на которые нет ссылок снаружи. Утечки в Python — это почти всегда забытые ссылки (кэши, глобальные списки), а не баг сборщика. → [[Память и сборка мусора]]

**Синхронизация потоков и процессов.** Потоки: `Lock`, `RLock`, `Semaphore`, `Event`, `Condition`, а лучше всего — `queue.Queue` вместо общего состояния. Блокировки всегда в одном порядке, чтобы избежать deadlock. Процессы: `Queue`/`Pipe`, `Value` с `get_lock()`, общая память. Между независимыми процессами и серверами — база, Redis или брокер сообщений. → [[Потоки и процессы#Синхронизация потоков]]

**Async под капотом.** Корутина — функция, которая умеет приостанавливаться на `await`, устроена как генератор. Future — обещание результата с колбэками. Task — ведёт корутину и продолжает её, когда готов Future, которого она ждёт. Цикл событий — однопоточный планировщик: выполняет готовые колбэки, ждёт сокеты через `epoll`/`kqueue` и срабатывание таймеров. Блокирующий вызов в корутине останавливает всех. → [[asyncio под капотом]]

**asyncio: ошибки, таймауты, масштаб.** Во вложенных `TaskGroup` ошибка приходит `ExceptionGroup` внутри `ExceptionGroup`: `eg.exceptions[0]` — внутренняя группа, до исходной ошибки доходят обходом дерева. `httpx.Timeout(3)` — лимит на каждую фазу (соединение, чтение, запись), а не на запрос: сервер, который шлёт байты понемногу, его не превышает; дедлайн попытки — `asyncio.timeout`. На 100 000 задач `gather` сразу создаёт все корутины, а N воркеров в `TaskGroup`, читающих общий итератор, держат в памяти только N. → [[asyncio на практике]] · [[Ошибки и отмена в asyncio]] · [[Таймауты и нагрузка в asyncio]]

**Деньги.** Не float: `0.1 + 0.2 != 0.3`, `round(2.675, 2)` даёт `2.67`. Хранят целое в минимальных единицах плюс код валюты (у JPY ноль знаков, у KWD три), считают на `Decimal` из строки, округляют `quantize(..., ROUND_HALF_UP)` один раз в конце; по умолчанию и `round`, и `quantize` округляют банковски (`ROUND_HALF_EVEN`). pydantic v2 отдаёт `Decimal` в JSON строкой. → [[Деньги и числа]]

**Логирование.** Запись проходит порог логгера, затем порог каждого хендлера и всплывает к родителям, пока `propagate=True`. Аргументы передают отдельно (`log.info("x=%s", x)`): форматирование ленивое. В `extra` нельзя ключи, совпадающие с полями `LogRecord` (`message`, `args`) — `KeyError`. Исключение — `log.exception` внутри `except`. → [[Логирование]]

**Моки.** Патчат имя там, где его ищут: после `from time import sleep` нужен `patch("mod.sleep")`, а не `patch("time.sleep")`. `patch("mod.asyncio.sleep")` подменяет атрибут общего модуля `asyncio` для всех. `autospec=True` ловит опечатку в имени метода и неверные аргументы. Тест проверяют на ложное срабатывание: сломай код — тест должен упасть. → [[pytest и моки#Что и где патчить]]

**SQLAlchemy async.** Первый запрос в сессии сам открывает транзакцию (autobegin), и соединение висит `idle in transaction`, пока код ходит во внешний API — закрывают транзакцию до сетевого вызова. `expire_on_commit=False` не спасает от `rollback`: после него чтение атрибута в async падает с `MissingGreenlet`. Ленивая загрузка связей в async не работает — `selectinload`/`joinedload`, заодно уходит N+1. → [[SQLAlchemy async]]

## Python против других языков

### Сильные стороны

- **Скорость разработки и читаемость.** Мало шаблонного кода, рабочий прототип за часы, код легко читать новому человеку. Для бизнеса это часто важнее скорости выполнения: время разработчика дороже серверов.
- **Экосистема.** Веб и API (Django, FastAPI, SQLAlchemy, pydantic, Celery), данные и ML (numpy, pandas, PyTorch, scikit-learn), автоматизация, DevOps-скрипты. В ML и работе с LLM Python — стандарт де-факто.
- **Язык-«клей».** Узкие места легко вынести в нативный код: Cython, расширения на Rust через PyO3, C через cffi. numpy и PyTorch — Python-интерфейс к C, C++ и CUDA, поэтому «медленный Python» в ML обычно не узкое место.
- **Постепенная типизация.** Аннотации типов и проверка mypy/pyright добавляются по мере роста проекта; pydantic проверяет данные в рантайме на границе с внешним миром.
- **Найм и порог входа.** Много разработчиков, язык учат в вузах, легко перейти из аналитики и QA.

### Слабые стороны

- **Скорость CPython на вычислениях.** Интерпретатор, динамическая типизация, каждое число — объект в куче. На циклах с арифметикой Python в десятки раз медленнее Go, Java и Rust. Что смягчает: специализирующий интерпретатор (PEP 659, с 3.11 в среднем на четверть быстрее), экспериментальный JIT с 3.13, PyPy, вынос горячего кода в нативные расширения.
- **Параллелизм.** Из-за GIL потоки не ускоряют вычисления, процессы дороги по памяти и требуют сериализации. Ситуация меняется (сборка без GIL, субинтерпретаторы), но библиотеки догоняют годами.
- **Память.** Объект с тремя полями — около 100 байт, `int` — 28 байт. Миллионы объектов в памяти обходятся дорого.
- **Ошибки типов — в рантайме.** Аннотации не проверяются при выполнении; опечатка в имени атрибута или `None` там, где не ждали, вылезет в проде, если не настроены тайпчекер и тесты.
- **Деплой.** Нет единого бинарника, как у Go: нужен интерпретатор, зависимости, виртуальное окружение; образы контейнеров больше, холодный старт медленнее. Пакетный менеджмент долго был больным местом; сейчас его в основном закрывает uv.
- **Два мира: sync и async.** Асинхронная функция «заражает» всех, кто её вызывает (проблема «цветных функций»). Многие библиотеки существуют в двух версиях, а один синхронный вызов в асинхронном сервисе тормозит всех.

### Как ответить на собеседовании

«Python беру, когда важны скорость разработки и экосистема, а узкое место — ввод-вывод: база, сеть, очереди. Большинство бэкендов именно такие, и там время ответа определяет SQL-запрос, а не язык. Когда узкое место — вычисления, есть варианты: numpy или нативное расширение, процессы, задачи в очереди. Если весь сервис упирается в CPU или нужна гарантированно низкая задержка с высокой конкурентностью (шлюз, стриминг, обработка миллионов событий в секунду), такой сервис пишу на Go или Rust рядом с Python-сервисами, а не переписываю всё».
