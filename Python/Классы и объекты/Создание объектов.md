**Суть.** В Python всё — объекты, включая классы и функции. Класс — это объект типа `type` (или другого метакласса), поэтому `MyClass()` — это обычный вызов объекта: срабатывает `type.__call__`, который сначала создаёт пустой объект через `__new__`, а потом заполняет его через `__init__`.

## Как создаётся объект

### __new__, __init__ и кто их вызывает

`Point(1, 2)` — вызов объекта `Point`. Вызов любого объекта ищет метод `__call__` у его типа, а тип класса — `type`. Поэтому выполняется `type.__call__(Point, 1, 2)`, и он устроен примерно так:

```python
def type_call(cls, *args, **kwargs):
    obj = cls.__new__(cls, *args, **kwargs)  # 1. создать объект
    if isinstance(obj, cls):
        obj.__init__(*args, **kwargs)        # 2. инициализировать его
    return obj
```

- **`__new__(cls, ...)`** создаёт и возвращает новый объект. Первым аргументом получает класс, а не экземпляр: объекта ещё нет. Это статический метод, хотя `@staticmethod` писать не нужно, Python делает это сам. Внутри почти всегда вызывают `super().__new__(cls)`, и в итоге память выделяет `object.__new__`.
- **`__init__(self, ...)`** получает уже созданный объект и заполняет его атрибутами. Должен вернуть `None`; если вернуть что-то другое — `TypeError`.
- Если `__new__` вернул объект **не этого класса** (например, кэшированный объект другого типа или `None`), `__init__` не вызывается.

Порядок вызовов и случай, когда `__init__` пропускается:

```python
class Point:
    def __new__(cls, x, y):
        print("__new__", cls.__name__, x, y)
        return super().__new__(cls)

    def __init__(self, x, y):
        print("__init__", x, y)
        self.x, self.y = x, y


p = Point(1, 2)


class Fake:
    def __new__(cls):
        print("__new__")
        return 42  # не экземпляр Fake

    def __init__(self):
        print("__init__")  # не будет вызван


print(Fake())
```

```text title="Вывод"
__new__ Point 1 2
__init__ 1 2
__new__
42
```

Переопределять `__new__` нужно редко. Типичные случаи:

- **Наследование от неизменяемого типа** (`int`, `float`, `str`, `tuple`, `frozenset`). Значение такого объекта задаётся в момент создания, и в `__init__` его уже не поменять.

```python
class Celsius(float):
    def __new__(cls, value: float):
        if value < -273.15:
            raise ValueError("ниже абсолютного нуля")
        return super().__new__(cls, value)


class Upper(str):
    def __new__(cls, value: str):
        return super().__new__(cls, value.upper())


print(Celsius(36.6) + 1, Upper("usd"))  # 37.6 USD
```

- **Контроль количества экземпляров**: одиночка (singleton) или кэш одинаковых объектов (`Currency("USD") is Currency("USD")`).
- **Фабрика**, которая по аргументам возвращает объект подходящего подкласса. Обычно понятнее сделать это через `@classmethod` (`Payment.from_dict(data)`), а не через `__new__`.

Подвох с аргументами: если переопределён `__new__`, но не `__init__` (или наоборот), лишние аргументы конструктора `object` молча проигнорирует. Если переопределены оба, а в `object.__new__` передали аргументы (`super().__new__(cls, *args)`), будет `TypeError`. Правильно — `super().__new__(cls)` без аргументов.

### Одиночка (singleton) через __new__ и его ловушка

```python
class Settings:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self, env: str = "prod") -> None:
        self.env = env  # выполняется при КАЖДОМ вызове Settings(...)


a = Settings("prod")
b = Settings("test")
print(a is b, a.env)  # первый объект тихо перезаписан
```

```text title="Вывод"
True test
```

`__new__` возвращает тот же объект, он того же класса, значит `type.__call__` каждый раз заново вызывает `__init__` и сбрасывает состояние. Варианты лучше:

- **метакласс с `__call__`**: он перехватывает весь вызов `Settings(...)` целиком, и `__init__` выполняется только при первом создании;

```python
class SingletonMeta(type):
    _instances: dict[type, object] = {}

    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]


class Settings(metaclass=SingletonMeta):
    def __init__(self, env: str = "prod") -> None:
        self.env = env


print(Settings("prod") is Settings("test"), Settings().env)
```

```text title="Вывод"
True prod
```

- **проще и чаще в реальном коде** — объект на уровне модуля (`settings = Settings()`; модуль импортируется один раз, и все получают один объект) или функция-фабрика с `@functools.cache`, как `get_settings()` во FastAPI. Такой объект легко подменить в тесте.

Все три варианта не потокобезопасны в строгом смысле: «проверить, что объекта нет, и создать» — две операции, и два потока могут создать по объекту. Если создание дорогое или с побочными эффектами — защищать блокировкой, см. [[Потоки и процессы#Синхронизация потоков]].

### __call__: вызываемый объект

`obj(...)` превращается в `type(obj).__call__(obj, ...)`. Объект с `__call__` ведёт себя как функция, но может хранить состояние и настройки в атрибутах.

```python
class Multiplier:
    def __init__(self, k: int) -> None:
        self.k = k

    def __call__(self, x: int) -> int:
        return x * self.k


double = Multiplier(2)
print(double(21), callable(double))  # 42 True
```

Где встречается:

- **функция с настройками, заданными заранее**: зависимость во FastAPI вида `Depends(RequireRole("admin"))` — экземпляр запоминает роль, а FastAPI вызывает его на каждый запрос;
- **класс-декоратор** со счётчиком или кэшем (см. [[Декораторы#Класс как декоратор и декоратор класса]] и пример с `__get__` в [[Атрибуты и дескрипторы#Как Python ищет атрибут]]);
- **стратегия** — объект, который передают как функцию (`key=`, `callback=`), но с конфигурацией;
- `torch.nn.Module`: `model(x)` вызывает `__call__`, а тот — `forward` плюс хуки.

Специальные методы Python ищет **у типа, а не у экземпляра**. `a.__call__ = lambda: "hi"` на обычном объекте ничего не даст: `a()` всё равно упадёт с `TypeError: 'A' object is not callable`. То же верно для `__len__`, `__enter__`, `__iter__` и остальных.

### __init_subclass__: реакция на создание подкласса

Если нужно что-то сделать в момент объявления подкласса (зарегистрировать его, проверить, что нужные атрибуты заданы), метакласс не нужен: с Python 3.6 есть `__init_subclass__`.

```python
class Handler:
    registry: dict[str, type["Handler"]] = {}

    def __init_subclass__(cls, *, event: str, **kwargs):
        super().__init_subclass__(**kwargs)
        Handler.registry[event] = cls


class PaymentCreated(Handler, event="payment.created"):
    pass


print(Handler.registry)
```

```text title="Вывод"
{'payment.created': <class '__main__.PaymentCreated'>}
```

Хук срабатывает в момент выполнения `class`-блока, а не при создании экземпляра; обязательный `event` проверяется там же:

```python
class Handler:
    def __init_subclass__(cls, *, event: str, **kwargs):
        super().__init_subclass__(**kwargs)
        print("зарегистрирован", cls.__name__)


print("до объявления")


class PaymentCreated(Handler, event="payment.created"):
    pass


print("после объявления")

try:
    class Bad(Handler):  # event не передан
        pass
except TypeError as e:
    print(e)
```

```text title="Вывод"
до объявления
зарегистрирован PaymentCreated
после объявления
Handler.__init_subclass__() missing 1 required keyword-only argument: 'event'
```

| Метод | Чей | Когда вызывается | Что возвращает |
| --- | --- | --- | --- |
| `__new__(cls, ...)` | класса | при `C(...)`, первым | новый объект |
| `__init__(self, ...)` | класса | при `C(...)`, если `__new__` вернул экземпляр `C` | `None` |
| `__call__(self, ...)` | класса объекта | при `obj(...)` | что угодно |
| `type.__call__` / метакласса `__call__` | метакласса | при `C(...)`, вызывает `__new__` и `__init__` | готовый объект |
| `__init_subclass__(cls, ...)` | родителя | при объявлении подкласса | `None` |

## Метаклассы

Класс — тоже объект, и его класс называется метаклассом. По умолчанию это `type`: `type(int)` это `type`, а `type(type)` — снова `type`. Оператор `class` — сахар над вызовом `type(имя, базы, пространство_имён)`.

```python
print(type(int), type(type))
print(type(type("A", (), {})))


def hello(self):
    return "hi"


A = type("A", (), {"x": 1, "hello": hello})
print(A, A().hello(), A.x)
```

```text title="Вывод"
<class 'type'> <class 'type'>
<class 'type'>
<class '__main__.A'> hi 1
```

Свой метакласс — подкласс `type`. Его `__new__` получает имя, базы и пространство имён **до** того, как класс создан, поэтому может проверить или изменить тело; `__init__` метакласса вызывается уже с готовым классом. Метакласс наследуется подклассами.

```python
class Meta(type):
    def __new__(mcs, name, bases, ns, **kw):
        print("Meta.__new__", name)
        for attr, val in ns.items():
            if callable(val) and not attr.startswith("__") and not val.__doc__:
                raise TypeError(f"{name}.{attr}: нужен docstring")
        return super().__new__(mcs, name, bases, ns, **kw)

    def __init__(cls, name, bases, ns, **kw):
        print("Meta.__init__", name)
        super().__init__(name, bases, ns, **kw)


class Service(metaclass=Meta):
    def run(self):
        """запуск"""


try:
    class Bad(metaclass=Meta):
        def run(self):
            pass
except TypeError as e:
    print(e)


class Child(Service):  # метакласс наследуется
    pass


print(type(Child))
```

```text title="Вывод"
Meta.__new__ Service
Meta.__init__ Service
Meta.__new__ Bad
Bad.run: нужен docstring
Meta.__new__ Child
Meta.__init__ Child
<class '__main__.Meta'>
```

Метакласс нужен, когда надо менять **сам процесс** создания класса или поведение класса как объекта: подменить пространство имён (`__prepare__`), перехватить `C(...)` через метаклассовый `__call__` (как в синглтоне выше), добавить методы на уровне класса (`len(MyEnum)`, `for x in MyEnum`). Так устроены `ABCMeta`, `EnumType`, декларативные модели ORM. Если нужно лишь отреагировать на объявление подкласса (зарегистрировать, проверить атрибуты), хватает `__init_subclass__` (раздел выше), а чтобы дополнить один конкретный класс, — декоратор класса. У метаклассов есть цена: два родителя с разными метаклассами не совмещаются.

```python
class X(type): pass
class Y(type): pass
class A(metaclass=X): pass
class B(metaclass=Y): pass

try:
    class C(A, B): pass
except TypeError as e:
    print(e)
```

```text title="Вывод"
metaclass conflict: the metaclass of a derived class must be a (non-strict) subclass of the metaclasses of all its bases
```

## Что спросят дальше

- **Что такое метакласс?** Класс, экземплярами которого являются классы; по умолчанию это `type`. Метакласс может менять класс при создании (`__new__`, `__init__` метакласса) и перехватывать создание экземпляров (`__call__`). Примеры: `ABCMeta`, `EnumType`, декларативные модели SQLAlchemy и Django. В своём коде почти всегда хватает `__init_subclass__` или декоратора класса.
- **`__del__` — это деструктор?** Нет, это финализатор: вызывается, когда объект собирается сборщиком мусора, и момент не гарантирован (в PyPy и при циклических ссылках — когда-нибудь потом). Ресурсы освобождают через контекстные менеджеры, см. [[Контекстные менеджеры]].
- **`classmethod` или `staticmethod`?** `classmethod` получает класс и подходит для альтернативных конструкторов (`User.from_row(row)`): в подклассе он создаст подкласс. `staticmethod` ничего не получает, это обычная функция в пространстве имён класса.
- **`ABC` или `Protocol`?** `ABC` — номинальная типизация: класс обязан явно наследоваться, и проверка идёт при создании экземпляра (нельзя создать объект с нереализованными абстрактными методами). `Protocol` — структурная: подходит любой класс с нужными методами, проверяет только тайпчекер (или `isinstance` с `@runtime_checkable`, но только по наличию имён).
- **Как сравнить `dataclass`, `NamedTuple` и pydantic?** `NamedTuple` неизменяемый, это кортеж, его можно распаковать и сравнить с кортежем. `dataclass` — обычный класс без проверок типов в рантайме. pydantic проверяет и приводит данные при создании объекта; его место — на границе с внешним миром (API, конфиг), а не внутри логики.
