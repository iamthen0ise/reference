# kafka-lab

Kafka 4.1 (KRaft): отдельный контроллер и три брокера, веб-интерфейс kafka-ui. Стенд для проверки крайних случаев репликации.

```sh
make kafkalab-up      # из корня репозитория
open http://127.0.0.1:8089
make kafkalab-down    # остановить и удалить тома
```

| Сервис | Порт на хосте | Что это |
|---|---|---|
| controller | — | KRaft-контроллер, `node.id` 100, `controller:9093` |
| kafka1, kafka2, kafka3 | — | брокеры, `node.id` 1–3, `kafkaN:9092` |
| kafka-ui | 8089 | kafbat/kafka-ui v1.4.2, кластер `lab`, редактирование включено |

Брокеры и контроллер на хост не публикуются. Bootstrap для клиентов внутри сети compose: `kafka1:9092,kafka2:9092,kafka3:9092`.

## Настройки

- `replica.lag.time.max.ms=10000`: отставший брокер выпадает из ISR за 10 с.
- `auto.create.topics.enable=false`: топики создаются явно.
- Внутренние топики с RF 3, `transaction.state.log.min.isr=2`.
- Данные брокеров лежат в именованных томах: переживают `kill`, удаляются `down -v`.
- Контроллер отдельно от брокеров: кворум не пропадает, пока остановлены брокеры.

## Раннер сценариев

Раннер (`runner/`, контейнер `runner`) читает сценарии из `scenarios/*.yaml`, гоняет нагрузку aiokafka, применяет сбои по расписанию и сверяет подтверждённое с перечитанным логом. Отчёты — в `reports/<дата_время>_<имя>.md` (в git не попадают).

```sh
make kafkalab-run S=smoke                              # пересобирает образ раннера и запускает сценарий
make kafkalab-run S=smoke ARGS="--set producer.acks=1" # переопределение настроек
./Labs/kafka-lab/lab list                              # сценарии
./Labs/kafka-lab/lab state                             # раскладка партиций, ISR, обрывы, остановленные брокеры
./Labs/kafka-lab/lab kill|stop|start kafka2
./Labs/kafka-lab/lab cut kafka1 kafka2 [--one-way]
./Labs/kafka-lab/lab heal                              # снять все обрывы и запустить остановленные брокеры
```

`lab` — обёртка над `docker compose exec runner python -m lab`. Ошибка сценария (неверное значение, неизвестный ключ) — код 2 и сообщение, кластер не затронут.

Как идёт прогон: снять обрывы и поднять остановленные брокеры, пересоздать топик, запустить наблюдателей и продюсера, применить сбои (цель разрешается в момент сбоя по текущей раскладке), по концу `seconds` — снять обрывы, поднять брокеры, дождаться ISR, перечитать лог (`read_committed`), записать отчёт.

- Прерванный прогон (Ctrl-C, исключение) всё равно снимает обрывы и поднимает брокеры; отчёт при этом не пишется. Если очистка не сработала, `lab heal` делает то же вручную.
- Партиция без лидера при проверке (например, `unclean.leader.election.enable=false` и мёртвый лидер) попадает в «недоступные партиции»: её подтверждённые сообщения потерянными не считаются.
- Транзакционный режим: один продюсер с фиксированным `transactional_id` на прогон; подтверждения пишутся после `commit_transaction`, откаченные seq не считаются потерянными.
- Зависшая транзакция (`hang_transaction`) шлёт сообщение с seq `-1`; наблюдатели и проверка его пропускают.
