# kafka-lab

Kafka 4.1 (KRaft): отдельный контроллер и три брокера, веб-интерфейс kafka-ui. Стенд для проверки крайних случаев репликации.

```sh
make kafkalab-up      # из корня репозитория
open http://127.0.0.1:8089
make kafkalab-down    # остановить и удалить тома
```

| Сервис | Порт на хосте | Что это |
|---|---|---|
| controller | — | KRaft-контроллер, `node.id` 100, `controller:9093` |
| kafka1, kafka2, kafka3 | — | брокеры, `node.id` 1–3, `kafkaN:9092` |
| kafka-ui | 8089 | kafbat/kafka-ui v1.4.2, кластер `lab`, редактирование включено |

Брокеры и контроллер на хост не публикуются. Bootstrap для клиентов внутри сети compose: `kafka1:9092,kafka2:9092,kafka3:9092`.

## Настройки

- `replica.lag.time.max.ms=10000`: отставший брокер выпадает из ISR за 10 с.
- `auto.create.topics.enable=false`: топики создаются явно.
- Внутренние топики с RF 3, `transaction.state.log.min.isr=2`.
- Данные брокеров лежат в именованных томах: переживают `kill`, удаляются `down -v`.
- Контроллер отдельно от брокеров: кворум не пропадает, пока остановлены брокеры.
