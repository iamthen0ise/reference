# Идеи новых разделов

Черновик, не план. Решение по каждой теме — через brainstorming → writing-plans, как у SQL-рецептов
(`docs/superpowers/plans/2026-11-20-sql-cookbook.md`). Предлагаемый порядок: Kafka → Linux → Redis.

## Kafka-рецепты (`Бэкенд/Очереди/Kafka-рецепты/`)

Теория уже есть: «Эксплуатация Kafka и CLI» → «Сброс offset», «Когда двигать offset» (автокоммит, inbox).
Не хватает прогоняемого инцидента. Песочница — одна нода Kafka в KRaft в Docker, цели `make kafka-*`
по образцу `.site/scripts/sql-pg.sh`.

Главная страница — «Консьюмер подтвердил и упал»:

1. Продюсер пишет платежи; консьюмер коммитит offset до обработки и падает на 10-м. Лаг 0, в базе пусто.
2. Найти, откуда перечитывать: по времени сбоя (`--to-datetime`), по offset из логов (`--to-offset`),
   назад на N (`--shift-by`), по партициям.
3. Проверить retention: нужный offset старше earliest — перечитывать нечего.
4. Остановить группу (иначе reset откажет), `--dry-run`, затем `--execute`.
5. Запустить консьюмер. Главный вывод: без идемпотентности перечитывание платежей = второе списание.
   Сначала проверка по inbox, потом сброс.
6. Безопаснее: перечитать диапазон отдельной группой (новый `group.id`), не трогая боевую.

Ещё страницы:

- вернуть сообщения из DLQ в основной топик;
- найти сообщение по ключу или времени;
- консьюмер завис, лаг растёт — почему.

## Redis-рецепты

Теория есть (`Бэкенд/Базы данных/Redis/`), рецептов-инцидентов нет.

- «Redis тормозит»: `SLOWLOG`, `LATENCY DOCTOR`, большие ключи (`--bigkeys`, `MEMORY USAGE`), O(N)-команды вроде `KEYS *`, горячие ключи.
- «Кончилась память»: `maxmemory`, политики вытеснения, OOM на запись при `noeviction`, ключи без TTL (`SCAN` + `TTL`), фрагментация.
- «Массовые операции без остановки»: удаление по маске `SCAN` + `UNLINK` вместо `KEYS` + `DEL`, массовая простановка TTL.
- «Кто держит соединения»: `CLIENT LIST`, утечка соединений и `maxclients`, `CLIENT KILL`.

## Linux (новая рубрика верхнего уровня, шпаргалки)

Формат страницы: симптом → команда → как читать вывод, не пересказ man. Песочница — контейнер Debian,
чтобы выводы были настоящими. На каждой странице — отличия GNU от macOS (`sed -i`, `date -d`, `grep -P`).

- Процессы: кто ест CPU, сигналы `TERM`/`KILL`, зомби, systemd и `journalctl`.
- Память: «Linux съел память» (page cache), RSS против VSZ, OOM killer в `dmesg`.
- Диск: место кончилось, а `du` не видит (удалённый открытый файл, `lsof +L1`), inode (`df -i`), `iostat`.
- Сеть: кто слушает порт (`ss -tlnp`), тайминги `curl -w`, `dig`, `TIME_WAIT`, `nc`, азы `tcpdump`.
- Текст и логи: готовые конвейеры `grep`, `awk`, `sed`, `jq`, `find`, `xargs`.
- Лимиты и права: «too many open files» и `ulimit`, `chmod`, `umask`, `sudo`.
- Внутри контейнера без утилит: `/proc`, `nsenter`.
