## Review Focus

1. **Блок с недетерминированным выводом** (порядок задач, время, адреса объектов) вставлен как точный. Читатель запускает код, видит другое и перестаёт доверять странице. Каждая задача проверяет это в шаге «Прогон»: всё, что меняется между запусками, помечено под блоком.
2. **Код работает на 3.15, но падает на 3.12** без пометки (`TaskGroup`, `batched`, `asyncio.timeout`, новые методы). Каждая задача прогоняет все блоки ещё и на `uv run --python 3.12`. Если блок падает, под ним пишется минимальная версия.
3. **Таблица симптомов на телефоне.** Три колонки с длинным текстом растягивают страницу на 390px. Каждая задача запускает `make check-browser` и проверяет, что её страницы нет в списке нарушений.
4. **Демонстрация, которая виснет или течёт** (deadlock, незакрытый клиент, сервер замера, оставшийся висеть). Шаг «Прогон» запускает каждый блок через `timeout 60 python3 …`, и код возврата не должен быть 124.
5. **Вредный совет как «исправление»**: повтор неидемпотентного запроса, `return_exceptions=True` без разбора результатов, `except Exception: pass`. Ревью задачи отдельно сверяет каждый раздел «Что сделать» с анти-целями спеки.

### Task 2: Починка декораторов

Риск: высокий — эталонный декоратор обязан правильно работать с async, генераторами и исключениями, а читатель будет копировать его в прод.

**Files:**
- Create: `Python/Рецепты/Починка декораторов.md`
- Modify: `.site/astro.config.mjs` — добавить страницу в группу «Рецепты».

**Interfaces:**
- Produces: эталонный декоратор `measured(*, memory: bool = False, logger: logging.Logger | None = None)`. Используется как `@measured()` и `@measured(memory=True)`. Поддерживает `def`, `async def`, генератор и async-генератор. Пишет одну строку в лог: имя функции, стена в мс, CPU в мс, пик памяти в КиБ при `memory=True`, исход (`ok` или имя исключения). Исключение пробрасывает дальше. Возвращает то же, что исходная функция. Типизирован через `ParamSpec`. Рядом — `measure_block(name: str)` как контекстный менеджер для замера блока кода. Задача 4 может сослаться на этот раздел.

**Обязательно на странице:**
- Десять поломок из спеки. На каждую: сломанный код → прогон, показывающий симптом → как заметить → исправление. Для «синхронная обёртка на async» и «обёртка на генераторе» вывод показывает замер около 0 мс против реального.
- Эталон `measured`. Его прогон показывает все четыре вида функций и падающую функцию, а в логе по строке на вызов. Тип вызова определяется через `inspect.iscoroutinefunction`, `inspect.isgeneratorfunction`, `inspect.isasyncgenfunction`. Обёртки генераторов мерят полную итерацию, включая ранний выход потребителя (`close`): исход записывается и в этом случае.
- Тест на pytest для проверки любого декоратора. Файл целиком на странице, запускается `pytest -q <файл>` во временном venv. Проверяет:
  - `__name__` и `__wrapped__`;
  - `inspect.signature` совпадает;
  - результат `async def` после декорирования — корутина, `await` даёт значение;
  - исключение проходит наружу того же типа;
  - декорированный генератор отдаёт те же элементы.
  
  Тест прогнать против `measured` (зелёный) и против сломанного декоратора без `wraps` (красный). Оба вывода — на странице.
- Чек-лист «как проверить любой декоратор» на 5–6 пунктов.
- Ссылки на [[Декораторы]], без повтора её разделов.

### Task 3: Потерянные исключения в async

Риск: высокий — asyncio, отмена, логирование; ошибка в рецепте означает, что у читателя исключения теряются по-прежнему.

**Files:**
- Create: `Python/Рецепты/Потерянные исключения в async.md`
- Modify: `.site/astro.config.mjs` — добавить страницу в группу «Рецепты».

**Interfaces:**
- Produces: рецепт `spawn(coro, *, name: str) -> asyncio.Task` — фоновая задача без потерь. Хранит ссылку на задачу в множестве модуля, логирует исключение задачи через `add_done_callback` (без `CancelledError`). Плюс `async def shutdown(timeout: float)` — дожидается или отменяет оставшиеся задачи. Ещё `TraceIdFilter(logging.Filter)` и `trace_id: ContextVar[str]`. Задача 4 может сослаться на этот раздел.

**Обязательно на странице:**
- Модель каждого симптома из спеки, с выводом, где видно, что ошибка потерялась или где именно появилось сообщение (stderr или лог, сразу или при сборке мусора). Для «Task exception was never retrieved» показать, что сообщение появляется только при сборке задачи.
- Те же модели под `python -X dev`: что добавилось в выводе. Под `PYTHONASYNCIODEBUG=1` — предупреждение о медленном колбэке.
- `loop.set_exception_handler` с рабочим примером.
- `sys.excepthook`, `threading.excepthook`, `sys.unraisablehook` — по короткому примеру, когда какой срабатывает.
- `spawn`/`shutdown`. Прогон показывает: исключение фоновой задачи попало в лог с её именем, при выходе ни одна задача не потерялась молча.
- `trace_id` через `ContextVar` + `logging.Filter`. Прогон с двумя параллельными «запросами» показывает, что строки лога разделяются по `trace_id`.
- Разбор `gather(return_exceptions=True)`: отделение исключений от результатов и логирование каждого с traceback.
- Логирование `ExceptionGroup` целиком и `exc.add_note()`.
- Ссылки на [[Ошибки и отмена в asyncio]] и [[Логирование]].

### Task 4: Скачать много ссылок

Риск: высокий — asyncio, сеть, повторы; вредный совет (повтор неидемпотентного запроса, отсутствие лимита) бьёт по чужим сервисам.

**Files:**
- Create: `Python/Рецепты/Скачать много ссылок.md`
- Modify: `.site/astro.config.mjs` — добавить страницу в группу «Рецепты».

**Interfaces:**
- Consumes: при желании — ссылки на разделы задач 2 (`measured`) и 3 (`spawn`). Код оттуда не копировать.
- Produces: рецепт `async def download_all(urls: Iterable[str], *, workers: int, deadline: float) -> AsyncIterator[Result]` — пул из `workers` воркеров на `asyncio.Queue(maxsize=workers * 2)`. `Result` — `dataclass(url: str, status: int | None, size: int, error: str | None, attempts: int)`.

**Обязательно на странице:**
- Локальный сервер для замеров на stdlib (`asyncio.start_server` или `ThreadingHTTPServer`): отвечает с задержкой `DELAY` и отдаёт 429 с `Retry-After`, если одновременно больше `LIMIT` соединений. Код сервера — на странице, чтобы замер можно было повторить.
- Таблица замера четырёх вариантов из спеки на одном наборе (числа подобрать так, чтобы прогон шёл секунды; условия — под таблицей): время, число 429, пик соединений.
- `download_all`:
  - `httpx.AsyncClient` с `httpx.Limits(max_connections=…)` и `httpx.Timeout` по фазам;
  - повтор только на сетевые ошибки, 429 и 5xx — для `GET`, с экспоненциальной задержкой, джиттером и `Retry-After`; максимум попыток — параметр;
  - выдача результатов по мере готовности (async-генератор и `contextlib.aclosing` у потребителя);
  - прогресс раз в N результатов;
  - запись на диск через `asyncio.to_thread`;
  - общий дедлайн `asyncio.timeout(deadline)`;
  - остановка по Ctrl+C без «Task was destroyed but it is pending». Показать прогоном: `signal.raise_signal(SIGINT)` через короткую паузу.
- Почему не задача на каждый URL: модель с 1 000 000 URL, где видна память при «задаче на URL» и при пуле. Числа — `tracemalloc` peak. Ссылка на раздел про 100 000 задач в [[Таймауты и нагрузка в asyncio]].
- Раздел «как искать проблемы» — четыре симптома из спеки, каждый с проверкой.
- Одна фраза, что тот же пул переносится на `aiohttp`.
