Быстрые ответы к собеседованию по [[PostgreSQL]] (задачи на запросы — в [[SQL-задачи]]), [[Kafka]], [[Redis]], [[RabbitMQ]] и [[Celery]]: каждый пункт — короткий ответ и ссылка на подробный разбор.

## Как пользоваться

Каждая тема в конспектах разбита на четыре слоя: **суть** (короткий ответ на 30 секунд), **техника** (SQL или код), **бизнес-кейс** (продуктовое решение, которое тянет за собой вопрос) и **что спросят дальше** (follow-up вопросы интервьюера). На собеседовании отвечай сверху вниз: сначала суть, потом пример, потом кейс — это показывает и знание, и инженерную зрелость.

## Быстрые ответы

Проговори каждый пункт за 30 секунд и отметь галочкой.

- [ ] Уровни изоляции: 4 уровня, 5 аномалий; PG — RC по умолчанию, RR = snapshot (без фантомов, с write skew), Serializable = SSI + retry на 40001. → [[PostgreSQL#Транзакции и уровни изоляции]]
- [ ] Lost update лечится атомарным UPDATE, `FOR UPDATE`, версией или строгим уровнем. → [[PostgreSQL#Техника: lost update и 4 способа лечения]]
- [ ] Upsert: `ON CONFLICT` по уникальному индексу вместо SELECT перед INSERT; `MERGE` на гонке может упасть. → [[PostgreSQL#Техника: upsert и ON CONFLICT]]
- [ ] Индексы: B-tree по умолчанию; GIN — jsonb/массивы/FTS; GiST — гео/диапазоны; BRIN — огромные append-only. Составной: равенство → диапазон, левый префикс. → [[PostgreSQL#Индексы]]
- [ ] Минусы индексов: запись, потеря HOT, место/кэш, bloat, планировщик, блокировка при создании. Индексы — под запросы. → [[PostgreSQL#Минусы индексов и почему нельзя индексировать всё]]
- [ ] EXPLAIN — оценка без выполнения; ANALYZE — выполняет (DML в BEGIN/ROLLBACK). Смотрим rows оценка vs факт, Buffers, Rows Removed by Filter. → [[PostgreSQL#EXPLAIN vs EXPLAIN ANALYZE]]
- [ ] Смена типа колонки: новая колонка → триггер → бэкфилл батчами → индекс CONCURRENTLY → CHECK NOT VALID + VALIDATE → короткое переключение с lock_timeout → drop старой. → [[PostgreSQL#Zero-downtime миграции]]
- [ ] JSONB: для полуструктурированного; горячие поля — в колонки; GIN для `@>`, индекс по выражению для `->>`. → [[PostgreSQL#JSON и JSONB]]
- [ ] Блокировки: MVCC; 4 строчных режима; ACCESS EXCLUSIVE у DDL; SKIP LOCKED для очередей; deadlock — единый порядок; lock queue. → [[PostgreSQL#Блокировки]]
- [ ] Порядок в Kafka только в партиции; ломают ключ, число партиций, ретраи без идемпотентности, параллелизм, retry-топики, ребаланс, несколько продюсеров. Защита — версия в событии. → [[Kafka#Порядок событий]]
- [ ] БД упала: классификация ошибок, pause + backoff + jitter + circuit breaker, retry на одном уровне, Kafka как буфер, идемпотентность, плавный разгон. → [[Kafka#Ретраи при падении базы]]
- [ ] Offset: после COMMIT в БД, auto-commit выключен, коммит в `on_partitions_revoked`, непрерывный префикс при параллелизме, poison → DLQ → commit. → [[Kafka#Когда двигать offset]]
- [ ] Outbox для DB → Kafka, inbox для Kafka → DB. → [[Kafka#Смежное: transactional outbox]]
- [ ] Схема события: Avro/Protobuf + Schema Registry, только совместимые изменения (новое поле с дефолтом); compaction и tombstone. → [[Kafka#Схема событий и compaction]]
- [ ] Redis: структуры под задачи; cache-aside с `DEL` после записи; stampede/penetration/avalanche; блокировка `SET NX PX` + токен + fencing; RDB vs AOF; eviction policy; Cluster и hash tags. → [[Redis]]
- [ ] RabbitMQ: exchange → binding → queue; publisher confirms + durable/quorum + manual ack + prefetch; retry через DLX + TTL; requeue без задержки = горячий цикл; когда Rabbit, а когда Kafka. → [[RabbitMQ]]
- [ ] Celery: по умолчанию early ack (at-most-once) → `acks_late` + идемпотентность; `on_commit` для `delay()`; retry только временных ошибок с backoff + jitter; один beat; отдельные очереди по критичности. → [[Celery]]

## Вопросы, которые стоит задать в ответ на системную задачу

Они показывают, что ты думаешь о продукте, а не только о технологиях:

- Что хуже для бизнеса — дубль или потеря?
- Какая задержка допустима (секунды, минуты, час)?
- Нужен ли строгий порядок и в рамках чего (заказ, клиент, всё)?
- Какие объёмы сейчас и через 2 года?
- Что видит пользователь, пока система в промежуточном состоянии?
- Кто и за какое время разбирает DLQ и инциденты?
