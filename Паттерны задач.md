## Быстрый выбор: от условия к алгоритму

Иди сверху вниз: сначала тип условия, потом уточняющие признаки. В конце ветки — ссылка на паттерн. Ветки сворачиваются.

- **Массив или строка, нужно найти значение, позицию или границу**
	- элементы делятся на «плохие, хорошие», «минимальное или максимальное X, при котором…» → [[#Бинарный поиск по предикату (хорошие и плохие)|бинарный поиск по предикату]]
	- нужен диапазон значений (первое и последнее вхождение) или два поиска подряд, сначала подготовительный → [[#Двойной бинарный поиск]]
	- иначе: найти значение или место вставки в отсортированном → [[#Базовый бинарный поиск]]
- **Массив или строка, нужно найти пару, сравнить, изменить**
	- один отсортированный массив, пара элементов, палиндром → [[#Навстречу друг другу]]
	- два массива, общие или отличные элементы → [[#Каждому по указателю]]
	- изменить массив in-place, сохранив порядок → [[#Быстрый и медленный]]
- **Подряд идущие элементы (подмассив, подстрока)**
	- в условии задан размер окна k → [[#Окно фиксированной длины]]
	- подряд идущие группы, каждый элемент только в одной → [[#Непересекающиеся окна]]
	- самый длинный или короткий подотрезок, пока выполняется условие → [[#Пересекающиеся окна]]
- **Суммы и другие величины на подотрезках, много запросов**
	- много запросов «сумма на отрезке» → [[#Префиксные суммы]]
	- посчитать подмассивы с заданной суммой → [[#Префикс и хеш-таблица]]
	- ответ для элемента зависит от всего слева и всего справа → [[#Префикс и суффикс]]
	- много операций «прибавить на отрезке», результат нужен в конце → [[#Разностный массив]]
- **Нужно посчитать или запомнить элементы**
	- частоты, анаграммы, «видел ли раньше», поиск пары по значению, majority → [[#Техника подсчёта]]
	- сортировка по частоте, top-k → [[#KV-VK]]
- **Отрезки, интервалы, события во времени**
	- дано два списка отрезков → [[#Два указателя на отрезках]]
	- в одном списке: объединить, найти пересечения, проверить пересечение → [[#Метод отрезков]]
	- сколько событий одновременно, минимум ресурсов, состояние в момент времени → [[#Метод точек]]
- **Односвязный список**
	- цикл, середина, k-й элемент с конца → [[#Черепаха и заяц]]
	- развернуть список или его часть → [[#Разворот списка]]
	- переставить узлы «первый, последний, второй, предпоследний…» → [[#Разворот части и слияние]]
	- слить, собрать новый список, удалить узлы (в том числе голову) → [[#Фиктивный узел]]
- **Все варианты: подмножества, перестановки, сочетания, расстановки**
	- кандидатов можно породить сразу и проверить каждого → [[#Полный перебор]]
	- кандидата строим по шагам, неподходящее начало можно отсечь → [[#Поиск с возвратом]]
	- подмножества, `n` до 20, нужны быстрые проверки пересечений → [[#Перебор битовых масок]]
- **Бинарное дерево**
	- ответ зависит от пути от корня (глубина, сумма, границы) → [[#Обход сверху вниз]]
	- ответ зависит от ответов детей (высота, баланс, диаметр, общий предок) → [[#Обход снизу вверх]]
	- по уровням, ближайший к корню, кратчайший путь по рёбрам → [[#Обход по уровням]]
	- левое меньше, правое больше, искать или вставлять → [[#Дерево поиска]]
	- названы прямой, симметричный или обратный порядок, k-й по порядку → [[#Порядки обхода]]
	- даны обходы или массив, построить дерево, сериализация → [[#Построение дерева]]
- **Граф, сетка, зависимости**
	- обойти всё достижимое, посчитать компоненты или острова → [[#Обход в глубину]]
	- минимум шагов при одинаковой цене хода → [[#Обход в ширину]]
	- порядок, зависимости, цикл в ориентированном графе → [[#Топологическая сортировка]]
	- рёбра добавляются по одному, «в одной ли группе», лишнее ребро → [[#Система непересекающихся множеств]]
	- рёбра с разными весами, кратчайший путь → [[#Алгоритм Дейкстры]]
	- отрицательные веса или лимит «не больше k рёбер» → [[#Алгоритм Беллмана — Форда]]
	- связать все вершины с минимальной суммой весов → [[#Минимальное остовное дерево]]
	- разбить на две группы, «враги не вместе», нечётный цикл → [[#Двудольность]]
- **Количество способов, минимум или максимум, «можно ли», подзадачи повторяются**
	- выбор «взять или пропустить», зависит от нескольких предыдущих → [[#Линейная ДП]]
	- набор предметов и лимит, набрать сумму → [[#Рюкзак]]
	- сетка, ходы вправо и вниз → [[#ДП по сетке]]
	- две строки или два массива, сопоставить → [[#ДП на двух последовательностях]]
	- одна последовательность, смотрим на все предыдущие элементы → [[#ДП на подпоследовательностях]]
	- по дням, у процесса есть режим (кулдаун, держу или не держу) → [[#ДП с состояниями]]
	- порядок заполнения неочевиден, проще рекурсия → [[#Рекурсия с запоминанием]]
- **Скобки, выражения, вложенность, «ближайший»**
	- нужен **ближайший** наибольший или наименьший элемент → [[#Монотонный стек]]
	- похоже на стековую, но нужен только размер стека (один вид скобок, глубина) → [[#Псевдостек]]
	- вычислить выражение, скобки разных видов, вложенные структуры, «хранить промежуточные результаты» → [[#Стек промежуточных результатов]]

> [!info] Шаблон паттерна
> Каждый паттерн — заголовок `###` и одни и те же поля:
> **Суть** · **Когда** · **Сложность** · **Шаблон** · **Задачи**.
> Если задача не ложится на шаблон один в один, рядом с ней есть пометка «нюанс»: что в шаблоне поменять.
> Копируй пустой блок из конца файла.

## Два указателя

Алгоритмы, где используются строго два указателя.

> [!tip] Как выбрать паттерн
> - Несколько массивов → **каждому по указателю**
> - Нужно менять массив in-place → **быстрый и медленный**
> - Иначе → пробуй **навстречу друг другу** или другой тип задач

### Навстречу друг другу

- **Суть:** один указатель в начале коллекции, другой в конце, двигаются навстречу. Нужно определить, когда двигаем левый, а когда правый.
- **Схема:** отсортированный `[1, 3, 4, 6, 8, 11]`, ищем пару с суммой 10.
	```mermaid
	flowchart LR
	    a0["1"] --- a1["3"] --- a2["4"] --- a3["6"] --- a4["8"] --- a5["11"]
	    L(["l"]) -.-> a0
	    R(["r"]) -.-> a5
	```
	Сумма `1 + 11 = 12` больше цели, двигаем правый указатель влево. `1 + 8 = 9` меньше цели, двигаем левый вправо. `3 + 8 = 11`, снова правый влево. `3 + 6 = 9`, левый вправо. `4 + 6 = 10`, нашли. Каждый шаг отбрасывает один конец, поэтому не больше n шагов.
- **Когда:**
	- один **отсортированный** массив
	- поиск палиндрома, то есть сужение диапазона с двух сторон
- **Сложность:** T: O(n) · S: O(1)
- **Шаблон:**
	```python
	l, r = 0, len(a) - 1
	while l < r:
	    s = a[l] + a[r]          # условие зависит от задачи
	    if s == target:
	        return [l, r]
	    if s < target:
	        l += 1               # нужно больше → двигаем левый
	    else:
	        r -= 1               # нужно меньше → двигаем правый
	```
- **Задачи:**
	- [Valid Palindrome](https://leetcode.com/problems/valid-palindrome/) · Easy
	- [Reverse String](https://leetcode.com/problems/reverse-string/) · Easy
	- [Two Sum II - Input Array Is Sorted](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/) · Easy

### Каждому по указателю

- **Суть:** два массива, в каждом по указателю. Нужно понять, когда двигаем первый, а когда второй.
- **Когда:**
	- несколько массивов
	- нужно найти общие / отличные элементы массивов
- **Сложность:** T: O(n + m) · S: O(1), без учёта результата
- **Шаблон:**
	```python
	i = j = 0
	while i < len(a) and j < len(b):
	    if a[i] == b[j]:
	        res.append(a[i])
	        i += 1
	        j += 1
	    elif a[i] < b[j]:
	        i += 1
	    else:
	        j += 1
	# при слиянии не забыть хвосты: a[i:], b[j:]
	```
- **Задачи:**
	- [Merge Sorted Array](https://leetcode.com/problems/merge-sorted-array/) · Easy · нюанс: сливать надо в `nums1` с конца, справа налево, иначе затрёшь элементы, которые ещё не прочитал
	- [Intersection of Two Arrays II](https://leetcode.com/problems/intersection-of-two-arrays-ii/) · Easy · нюанс: массивы не отсортированы, поэтому сначала `sort()` (или посчитай частоты в `dict`)
	- [Is Subsequence](https://leetcode.com/problems/is-subsequence/) · Easy · нюанс: здесь нет сортировки и сравнений «меньше/больше»: указатель по `t` идёт всегда, а по `s` — только при совпадении символа

### Быстрый и медленный

> [!warning] Не путать
> Это запись in-place в массиве. Поиск цикла в связном списке (черепаха и заяц, где быстрый шагает на 2) — другая техника, см. [[#Черепаха и заяц]].

- **Суть:** два указателя на один массив: быстрый двигается на каждом шаге, медленный — только когда нужно записать элемент.
- **Когда:**
	- модификация in-place
	- нужно сохранить порядок элементов
- **Сложность:** T: O(n) · S: O(1)
- **Шаблон:**
	```python
	# Пример: Move Zeroes — сдвинуть нули в конец, не меняя порядок остальных.
	# nums = [0, 1, 0, 3, 12] → [1, 3, 12, 0, 0]
	slow = 0                                         # куда встанет следующий ненулевой элемент
	for fast in range(len(nums)):                    # fast читает все элементы подряд
	    if nums[fast] != 0:
	        nums[slow], nums[fast] = nums[fast], nums[slow]   # ненулевой ставим на место slow, нуль уезжает вперёд
	        slow += 1
	# слева от slow — уже собранные ненулевые, от slow до fast — только нули
	# если нули не нужно сохранять (Remove Element), вместо swap хватит nums[slow] = nums[fast], а ответ — slow
	```
- **Задачи:**
	- [Remove Duplicates from Sorted Array](https://leetcode.com/problems/remove-duplicates-from-sorted-array/) · Easy
	- [Move Zeroes](https://leetcode.com/problems/move-zeroes/) · Easy · нюанс: это пример из шаблона
	- [Remove Element](https://leetcode.com/problems/remove-element/) · Easy · нюанс: оставляем всё, что `!= val`, пишем без swap (`nums[slow] = nums[fast]`), ответ — `slow`

## Плавающее окно

Смотрим на элементы массива через «окно», которое двигаем.

> [!tip] Как выбрать паттерн
> - В условии фиксированная длина окна → **фиксированное окно**
> - Группы элементов пересекаются → **пересекающиеся окна**
> - Иначе → **непересекающиеся окна**

### Окно фиксированной длины

- **Суть:** берём первые k элементов в «окно» и сдвигаем его на один шаг: добавляем новый элемент справа, убираем старый слева.
- **Схема:** `[2, 1, 5, 1, 3, 2]`, окно длины 3.
	```mermaid
	flowchart LR
	    w1["[2 1 5]<br/>сумма 8"] -- "+1 −2" --> w2["[1 5 1]<br/>сумма 7"] -- "+3 −1" --> w3["[5 1 3]<br/>сумма 9"] -- "+2 −5" --> w4["[1 3 2]<br/>сумма 6"]
	```
	Сумму не пересчитываем: добавляем вошедший справа и вычитаем вышедший слева. Один шаг сдвига — O(1).
- **Когда:**
	- в условии задан размер окна k
	- нужна работа с подряд идущими элементами
- **Сложность:** T: O(n) · S: O(1), если состояние окна — число; O(k), если множество или словарь
- **Шаблон:**
	```python
	window = sum(a[:k])              # первое окно
	best = window
	for i in range(k, len(a)):
	    window += a[i] - a[i - k]    # добавили справа, убрали слева
	    best = max(best, window)
	# состояние-множество: add(a[i]); remove(a[i - k]) вместо суммы
	```
- **Задачи:**
	- [Maximum Average Subarray I](https://leetcode.com/problems/maximum-average-subarray-i/) · Easy
	- [Contains Duplicate II](https://leetcode.com/problems/contains-duplicate-ii/) · Easy · нюанс: в окне хранится не сумма, а множество, поэтому памяти уходит O(k)

### Непересекающиеся окна

- **Суть:** расширяем правую границу окна, обрабатываем результат и переходим к следующему, пока не дойдём до конца массива.
- **Когда:**
	- нужна работа с подряд идущими группами элементов
	- элемент может быть только в одной группе, то есть группы не пересекаются
- **Сложность:** T: O(n) · S: O(1), без учёта результата
- **Шаблон:**
	```python
	# Пример: Consecutive Characters — самая длинная серия одинаковых символов подряд.
	# s = "leetcode" → 2 («ee»)
	best = 0
	i = 0
	while i < len(s):
	    j = i
	    while j < len(s) and s[j] == s[i]:   # расширяем правую границу, пока символ такой же, как первый
	        j += 1
	    best = max(best, j - i)              # окно [i, j) — одна серия, её длина j - i
	    i = j                                # следующая серия начинается там, где закончилась эта
	```
- **Задачи:**
	- [Max Consecutive Ones](https://leetcode.com/problems/max-consecutive-ones/) · Easy
	- [Consecutive Characters](https://leetcode.com/problems/consecutive-characters/) · Easy · нюанс: это пример из шаблона
	- [Longest Continuous Increasing Subsequence](https://leetcode.com/problems/longest-continuous-increasing-subsequence/) · Easy

### Пересекающиеся окна

- **Суть:** определяем состояние окна, при этом и расширяем, и сужаем окно.
- **Когда:**
	- нужна работа с подряд идущими группами элементов
	- элемент может быть в любой группе, то есть группы пересекаются
- **Сложность:** T: O(n) · S: O(1), если состояние окна — счётчик; O(k), если множество или словарь
- **Шаблон:**
	```python
	# Пример 1, самое ДЛИННОЕ допустимое окно: Longest Substring Without Repeating Characters.
	# s = "abcabcbb" → 3 («abc»). Окно допустимо, пока в нём нет повторяющихся символов.
	seen = set()                     # символы, которые сейчас в окне
	l = best = 0
	for r, ch in enumerate(s):
	    while ch in seen:            # новый символ уже есть в окне → сужаем слева, пока не уберём его
	        seen.remove(s[l])
	        l += 1
	    seen.add(ch)                 # расширили вправо
	    best = max(best, r - l + 1)  # длину считаем после сужения: окно уже допустимо

	# Пример 2, самое КОРОТКОЕ допустимое окно: Minimum Size Subarray Sum.
	# target = 7, nums = [2, 3, 1, 2, 4, 3] → 2 («4, 3»). Окно допустимо, когда сумма в нём >= target.
	total = l = 0
	best = float("inf")
	for r, x in enumerate(nums):
	    total += x                   # расширили вправо
	    while total >= target:       # окно допустимо → пробуем сузить, пока оно ещё допустимо
	        best = min(best, r - l + 1)   # длину считаем внутри цикла: до сужения окно допустимо
	        total -= nums[l]
	        l += 1
	return 0 if best == float("inf") else best
	```
- **Задачи:**
	- [Best Time to Buy and Sell Stock](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/) · Easy · нюанс: когда цена упала, окно начинается заново (`l = r`). Проще не мудрить с окном, а хранить минимальную цену слева
	- [Longest Substring Without Repeating Characters](https://leetcode.com/problems/longest-substring-without-repeating-characters/) · Medium · нюанс: это первый пример
	- [Minimum Size Subarray Sum](https://leetcode.com/problems/minimum-size-subarray-sum/) · Medium · нюанс: нужно самое короткое окно, это второй пример

## Хеш-таблица

Таблица вида ключ-значение, где ключом может быть любой hashable тип данных, то есть неизменяемый (число, строка, кортеж), но не список. Самое сложное — понять, что будет ключом, а что значением.

> [!tip] Как выбрать паттерн
> - Сортировка по частоте или top-k → **KV-VK**
> - Посчитать частоты или сравнить количества → **техника подсчёта**
> - Иначе → придумываем ключ сами

### Техника подсчёта

- **Суть:** пытаемся поместить условие задачи в хеш-таблицу, определяем ключ, затем считаем повторы / совпадения ключей.
- **Когда:**
	- задачи на анаграммы
	- работа с частотой элементов, например подсчёт количества элементов
- **Сложность:** T: O(n) · S: O(k), где k — количество уникальных ключей в таблице
- **Шаблон:**
	```python
	# Пример: Valid Anagram. Подсчёт пишем сами, без collections.Counter
	def count(items):
	    cnt = {}                              # ключ → сколько раз встретился
	    for x in items:
	        cnt[x] = cnt.get(x, 0) + 1
	    return cnt

	def is_anagram(a, b):
	    return len(a) == len(b) and count(a) == count(b)   # словари сравниваются по содержимому

	# «видел ли раньше»: seen = set(); if x in seen: ...

	# Пример: Two Sum. Ключ — значение, значение — индекс
	def two_sum(nums, target):
	    seen = {}
	    for i, x in enumerate(nums):
	        if target - x in seen:
	            return [seen[target - x], i]
	        seen[x] = i
	    return []

	# Пример: Majority Element (элемент, который встречается больше n/2 раз)
	# Вариант 1: подсчёт, S: O(n). Первое, что приходит в голову
	def majority_count(nums):
	    cnt = {}
	    for x in nums:
	        cnt[x] = cnt.get(x, 0) + 1
	        if cnt[x] > len(nums) // 2:
	            return x

	# Вариант 2: Boyer-Moore, S: O(1). Исключение из техники: таблица не нужна
	def majority_vote(nums):
	    cand, balance = None, 0
	    for x in nums:
	        if balance == 0:
	            cand = x                      # прежняя пара «взаимно уничтожилась»
	        balance += 1 if x == cand else -1
	    return cand                           # если majority не гарантирован, вторым проходом проверь count(cand) > n/2
	```
- **Задачи:**
	- [Valid Anagram](https://leetcode.com/problems/valid-anagram/) · Easy
	- [Ransom Note](https://leetcode.com/problems/ransom-note/) · Easy
	- [First Unique Character in a String](https://leetcode.com/problems/first-unique-character-in-a-string/) · Easy
	- [Two Sum](https://leetcode.com/problems/two-sum/) · Easy · нюанс: тут не подсчёт, а поиск пары: ключ — число, значение — его индекс, ищем `target - x`
	- [Majority Element](https://leetcode.com/problems/majority-element/) · Easy · нюанс: подсчёт работает за O(n) памяти, но оптимум — голосование Boyer-Moore за O(1): пары разных элементов взаимно уничтожаются, а majority на них не хватает. Для «больше n/3» то же с двумя кандидатами ([Majority Element II](https://leetcode.com/problems/majority-element-ii/), Medium), в общем случае k−1 кандидатов (Misra-Gries)

### KV-VK

- **Суть:** делаем подсчёт методом выше, затем инвертируем таблицу: значения становятся ключами, ключи — значениями.
- **Когда:**
	- сортировка по частоте
	- поиск top-k элементов
- **Сложность:** T: O(n) · S: O(n)
- **Шаблон:**
	```python
	# Пример: Top K Frequent Elements. Всё пишем сами, без Counter и defaultdict
	def top_k_frequent(items, k):
	    cnt = {}                              # KV: элемент → частота
	    for x in items:
	        cnt[x] = cnt.get(x, 0) + 1

	    by_freq = {}                          # VK: частота → элементы
	    for item, freq in cnt.items():
	        if freq not in by_freq:
	            by_freq[freq] = []
	        by_freq[freq].append(item)

	    res = []
	    for freq in range(len(items), 0, -1): # от частых к редким, без sort
	        for item in by_freq.get(freq, []):
	            res.append(item)
	            if len(res) == k:
	                return res
	    return res
	```
- **Задачи:**
	- [Sort Array by Increasing Frequency](https://leetcode.com/problems/sort-array-by-increasing-frequency/) · Easy · нюанс: при равной частоте числа идут по убыванию. Тут проще не корзины, а `sorted(key=lambda x: (cnt[x], -x))`
	- [Top K Frequent Elements](https://leetcode.com/problems/top-k-frequent-elements/) · Medium
	- [Sort Characters By Frequency](https://leetcode.com/problems/sort-characters-by-frequency/) · Medium

## Точки и отрезки

Отрезки и точки на них, как в школе. В коде это обычно списки пар координат `[start, end]`. Могут интерпретироваться и как «временные отрезки», например встречи или бронирования.

> [!tip] Как выбрать паттерн
> - Даны 2 списка отрезков → **два указателя на отрезках**
> - Нужно найти что-то в момент времени (сколько отрезков покрывают точку) → **метод точек**
> - Иначе → **метод отрезков**

> [!note] Базовые формулы
> - **Пересечение:** два отрезка пересекаются, если у них есть общие точки. Формула: `max(start1, start2) <= min(end1, end2)`. Сам отрезок пересечения — `[max(start1, start2), min(end1, end2)]`.
> - **Объединение:** пересекающиеся отрезки можно объединить. У объединённого начало — `min` из двух начал, конец — `max` из двух концов.
> - **Граничный случай:** касание (`end1 == start2`) — пересечение или нет, зависит от условия. Проверь, закрытые отрезки или полуоткрытые (`<=` или `<`).

### Метод отрезков

- **Суть:** сортируем отрезки по начальной точке, проходим по ним и формируем ответ, сравнивая текущий отрезок с последним в ответе. Главное — понять, как сформировать ответ.
- **Когда:**
	- нужно объединить или найти пересечение в одном списке отрезков
	- нужно проверить, есть ли пересечения вообще
- **Сложность:** T: O(n log n) · S: O(n)
- **Шаблон:**
	```python
	intervals.sort(key=lambda x: x[0])
	res = [intervals[0][:]]                    # копия, чтобы не менять входные данные
	for start, end in intervals[1:]:
	    if start <= res[-1][1]:                    # пересекается с последним в ответе
	        res[-1][1] = max(res[-1][1], end)      # расширяем конец
	    else:
	        res.append([start, end])               # разрыв → новый отрезок
	```
- **Задачи:**
	- [Summary Ranges](https://leetcode.com/problems/summary-ranges/) · Easy · нюанс: на самом деле это два указателя по отсортированным числам, отрезков тут нет
	- [Teemo Attacking](https://leetcode.com/problems/teemo-attacking/) · Easy
	- [Meeting Rooms](https://leetcode.com/problems/meeting-rooms/) · Easy · 🔒 premium
	- [Merge Intervals](https://leetcode.com/problems/merge-intervals/) · Medium
	- [Insert Interval](https://leetcode.com/problems/insert-interval/) · Medium · нюанс: список уже отсортирован, сортировать не нужно. Идём в три шага: копируем отрезки до нового, сливаем пересекающиеся, копируем остаток
	- [Non-overlapping Intervals](https://leetcode.com/problems/non-overlapping-intervals/) · Medium · нюанс: жадный алгоритм, отрезки сортируем по концу, а не по началу
	- [Minimum Number of Arrows to Burst Balloons](https://leetcode.com/problems/minimum-number-of-arrows-to-burst-balloons/) · Medium · нюанс: жадный алгоритм, отрезки сортируем по концу

### Два указателя на отрезках

- **Суть:** дано более одного списка отрезков, на каждый выделяем свой указатель и обходим как в паттерне «Каждому по указателю». Главное — найти логику движения указателей: двигаем тот, чей отрезок закончился раньше.
- **Когда:**
	- несколько списков отрезков, каждый уже отсортирован и без пересечений внутри
	- нужно найти пересечения или общее свободное время
- **Сложность:** T: O(n + m), где n, m — длины списков · S: O(1) без учёта результата
- **Шаблон:**
	```python
	i = j = 0
	while i < len(a) and j < len(b):
	    lo = max(a[i][0], b[j][0])
	    hi = min(a[i][1], b[j][1])
	    if lo <= hi:                       # есть пересечение
	        res.append([lo, hi])
	    if a[i][1] < b[j][1]:              # двигаем тот, что закончился раньше
	        i += 1
	    else:
	        j += 1
	```
- **Задачи:**
	- [Interval List Intersections](https://leetcode.com/problems/interval-list-intersections/) · Medium
	- [Meeting Scheduler](https://leetcode.com/problems/meeting-scheduler/) · Medium · 🔒 premium

### Метод точек

- **Суть:** превращаем отрезки в набор точек-событий (начало: +1, конец: −1), сортируем их и проходим со счётчиком для формирования ответа. Главное — верно сформировать ответ и порядок событий в одной координате.
- **Когда:**
	- нужно найти максимальное число одновременных событий
	- нужно узнать минимальное число ресурсов (комнат, касс, машин)
	- нужно узнать состояние в конкретный момент времени
- **Сложность:** T: O(n log n) · S: O(n)
- **Шаблон:**
	```python
	events = []
	for start, end in intervals:
	    events.append((start, 1))
	    events.append((end, -1))
	events.sort()          # при равной координате (-1) раньше (+1): конец раньше начала

	cur = best = 0
	for _, delta in events:
	    cur += delta
	    best = max(best, cur)
	```
	Порядок «конец раньше начала» подходит для полуоткрытых отрезков `[start, end)`: там касание не считается пересечением. Если отрезки закрытые и касание — это пересечение, начало должно идти раньше конца:
	```python
	events = []
	for start, end in intervals:
	    events.append((start, 0))      # 0 < 1: при равной координате начало обрабатывается раньше конца
	    events.append((end, 1))
	events.sort()

	cur = best = 0
	for _, kind in events:
	    if kind == 0:
	        cur += 1
	        best = max(best, cur)
	    else:
	        cur -= 1
	```
- **Задачи:**
	- [Maximum Population Year](https://leetcode.com/problems/maximum-population-year/) · Easy
	- [Meeting Rooms II](https://leetcode.com/problems/meeting-rooms-ii/) · Medium · 🔒 premium

	- [Corporate Flight Bookings](https://leetcode.com/problems/corporate-flight-bookings/) · Medium

## Бинарный поиск

Поиск за O(log n): на каждом шаге отбрасываем половину того, где ищем. Искать можно не только в массиве, но и в диапазоне возможных ответов (числа от `lo` до `hi`).

> [!tip] Как выбрать паттерн
> - Элементы можно поделить на «хорошие и плохие» (`bad bad bad good good`) → это точно бинарный поиск, **по предикату**
> - Нужно найти диапазон значений, или задачу можно решить двумя бинарными поисками — подготовительным и основным → **двойной бинарный поиск**
> - Иначе → **базовый бинарный поиск**

> [!note] Какие границы брать
> - **`while lo <= hi`** и `hi = mid - 1` — когда ищем конкретное значение и сразу выходим, как нашли. Если не нашли, `lo` — место, куда его вставить.
> - **`while lo < hi`** и `hi = mid` — когда ищем границу (первого «хорошего»). Цикл заканчивается на `lo == hi`, ответ лежит в `lo`.
> - **Последний «хороший»:** берём `mid = (lo + hi + 1) // 2`. Без `+ 1` цикл не закончится.
> - **Короткий путь:** `bisect.bisect_left(a, x)` вернёт первую позицию, где элемент `>= x`, а `bisect.bisect_right(a, x)` — первую, где элемент `> x`.

### Базовый бинарный поиск

- **Суть:** массив отсортирован, ищем конкретный элемент или место вставки. Сравниваем середину с целью и отбрасываем половину.
- **Когда:**
	- отсортированный массив и нужно найти значение
	- нужно найти позицию для вставки
- **Сложность:** T: O(log n) · S: O(1)
- **Шаблон:**
	```python
	lo, hi = 0, len(nums) - 1
	while lo <= hi:
	    mid = (lo + hi) // 2
	    if nums[mid] == target:
	        return mid
	    if nums[mid] < target:
	        lo = mid + 1
	    else:
	        hi = mid - 1
	return lo                          # не нашли: lo — позиция вставки
	# то же одной строкой: bisect.bisect_left(nums, target)
	```
- **Задачи:**
	- [Binary Search](https://leetcode.com/problems/binary-search/) · Easy
	- [Search Insert Position](https://leetcode.com/problems/search-insert-position/) · Easy

### Бинарный поиск по предикату (хорошие и плохие)

- **Суть:** в задаче есть ответ-граница: слева от неё все значения «плохие» (не подходят под условие), справа — все «хорошие» (подходят): `плохо плохо плохо хорошо хорошо`. Пишем проверку «подходит ли значение» и двоичным поиском находим, где «плохо» сменяется «хорошо». Главное — правильно написать проверку и выбрать границы: `lo` — самое маленькое значение, которое ещё может быть ответом, `hi` — самое большое.
- **Когда:**
	- в условии «минимальное X, при котором…» — ищем первого «хорошего»
	- в условии «максимальное X, при котором…» — ищем последнего «хорошего»
	- ответ — число из диапазона, и проверить конкретное значение проще, чем вычислить ответ напрямую
	- искать нужно среди индексов массива (`lo, hi = 0, len(nums) - 1`), а не среди значений
- **Сложность:** T: O(log(hi − lo) · C), где C — стоимость одной проверки · S: O(1)
- **Шаблон:**
	```python
	# Пример 1, первый «хороший»: Koko Eating Bananas.
	# Кучи бананов piles, охранники вернутся через h часов. Какая минимальная скорость k (бананов в час), чтобы успеть?
	from math import ceil

	def can_finish(k):                     # «хорошая» скорость: при ней успеваем за h часов
	    return sum(ceil(p / k) for p in piles) <= h

	lo, hi = 1, max(piles)                 # меньше 1 нельзя; на max(piles) точно успеем, значит hi «хороший»
	while lo < hi:
	    mid = (lo + hi) // 2
	    if can_finish(mid):                # успеваем: ответ mid или меньше (mid оставляем, вдруг он и есть минимум)
	        hi = mid
	    else:                              # не успеваем: ответ строго больше mid
	        lo = mid + 1
	return lo                              # lo == hi: границы сошлись на минимальной скорости

	# Пример 2, последний «хороший»: Sqrt(x).
	# Нужно наибольшее целое r, при котором r * r <= n.
	lo, hi = 0, n                          # r = 0 подходит всегда, значит lo «хороший»
	while lo < hi:
	    mid = (lo + hi + 1) // 2           # +1, иначе при lo + 1 == hi цикл не закончится
	    if mid * mid <= n:                 # mid подходит: ответ mid или больше
	        lo = mid
	    else:                              # не подходит: ответ строго меньше mid
	        hi = mid - 1
	return lo
	```
- **Задачи:**
	- [First Bad Version](https://leetcode.com/problems/first-bad-version/) · Easy · нюанс: проверка уже дана, это `isBadVersion(mid)`; `lo, hi = 1, n`
	- [Sqrt(x)](https://leetcode.com/problems/sqrtx/) · Easy · нюанс: нужен последний «хороший», берём второй пример
	- [Find Minimum in Rotated Sorted Array](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/) · Medium · нюанс: ищем по индексам, `lo, hi = 0, len(nums) - 1`, «хороший» индекс — тот, где `nums[i] <= nums[-1]`
	- [Koko Eating Bananas](https://leetcode.com/problems/koko-eating-bananas/) · Medium · нюанс: это первый пример
	- [Capacity To Ship Packages Within D Days](https://leetcode.com/problems/capacity-to-ship-packages-within-d-days/) · Medium · нюанс: «хорошая» вместимость — при которой все грузы вывезем за `days` дней; `lo, hi = max(weights), sum(weights)`

### Двойной бинарный поиск

- **Суть:** бинарный поиск запускаем дважды. Либо отдельно для левой и правой границы диапазона значений, либо так: сначала подготовительный поиск (находит точку разрыва, нужную строку или границу), потом основной — он уже ищет сам ответ.
- **Когда:**
	- нужно найти диапазон значений (первое и последнее вхождение)
	- решение раскладывается на два бинарных поиска — подготовительный и основной: найти pivot в повёрнутом массиве и искать в нужной половине, выбрать строку в матрице и искать в ней
- **Сложность:** T: O(log n) · S: O(1)
- **Шаблон:**
	```python
	# вариант А: диапазон значений = две границы
	# Пример: nums = [5, 7, 7, 8, 8, 10], target = 8 → ответ [3, 4] (первое и последнее вхождение)
	def bound(nums, target, first):
	    lo, hi, res = 0, len(nums) - 1, -1
	    while lo <= hi:
	        mid = (lo + hi) // 2
	        if nums[mid] == target:
	            res = mid
	            if first:
	                hi = mid - 1           # нашли, ищем ещё левее
	            else:
	                lo = mid + 1           # нашли, ищем ещё правее
	        elif nums[mid] < target:
	            lo = mid + 1
	        else:
	            hi = mid - 1
	    return res

	left, right = bound(nums, target, True), bound(nums, target, False)   # -1, -1, если значения нет
	# то же через bisect: l = bisect_left(nums, target); r = bisect_right(nums, target) - 1; значения нет → l > r

	# вариант Б: подготовительный поиск + основной (Search in Rotated Sorted Array)
	# Пример: nums = [4, 5, 6, 7, 0, 1, 2], target = 0 → ответ 4. Массив — это отсортированный, сдвинутый по кругу
	n = len(nums)
	lo, hi = 0, n - 1
	while lo < hi:                         # 1) подготовительный: ищем индекс минимума (pivot), здесь это 4
	    mid = (lo + hi) // 2
	    if nums[mid] <= nums[-1]:
	        hi = mid
	    else:
	        lo = mid + 1
	pivot = lo

	lo, hi = pivot, pivot + n - 1          # 2) основной: обычный поиск по «развёрнутому» массиву
	while lo <= hi:
	    mid = (lo + hi) // 2
	    v = nums[mid % n]
	    if v == target:
	        return mid % n
	    if v < target:
	        lo = mid + 1
	    else:
	        hi = mid - 1
	return -1
	```
- **Задачи:**
	- [Find First and Last Position of Element in Sorted Array](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/) · Medium · вариант А
	- [Search in Rotated Sorted Array](https://leetcode.com/problems/search-in-rotated-sorted-array/) · Medium · вариант Б
	- [Search a 2D Matrix](https://leetcode.com/problems/search-a-2d-matrix/) · Medium · нюанс: сначала ищем строку (сравнивая с её первым и последним элементом), потом ищем в этой строке. Можно и одним поиском по номеру `i`: элемент — `matrix[i // m][i % m]`

## Стек

Структура LIFO: последний добавленный элемент достаётся первым. В Python это обычный список: `append` и `pop` за O(1). Главное — понять, что именно хранить в стеке: значения, индексы или промежуточные результаты.

> [!tip] Как выбрать паттерн
> - Нужно искать **ближайший** (ключевое слово) наибольший или наименьший элемент по какому-то признаку → **монотонный стек**
> - Задача в целом похожа на стековую, но стек нужен только чтобы измерить его размер, а не содержимое: в него кладутся одинаковые элементы, и стек можно заменить счётчиком → **псевдостек**
> - Нужно вычислить выражение, или работа со скобками и иными вложенными структурами, или в условии прямо сказано хранить промежуточные результаты (взять стек) → **стек промежуточных результатов**

### Монотонный стек

> [!note] Направление стека
> - Ищем ближайший **больший** — выталкиваем, пока верхушка **меньше** нового (`nums[stack[-1]] < x`). Стек получается невозрастающим снизу вверх.
> - Ищем ближайший **меньший** — выталкиваем, пока верхушка **больше** нового (`nums[stack[-1]] > x`). Стек получается неубывающим.
> - Когда элемент вытолкнули, ближайший справа для него — новый элемент, а ближайший слева — тот, что остался под ним в стеке.

- **Суть:** держим в стеке элементы (чаще индексы) в монотонном порядке. Когда приходит новый элемент, выталкиваем из стека всех, кто нарушает порядок: для них новый элемент и есть искомый «ближайший больший/меньший». Главное — выбрать направление монотонности и что хранить.
- **Когда:**
	- нужно найти ближайший (ключевое слово) наибольший или наименьший элемент по какому-то признаку
	- «следующий больший / меньший элемент», «сколько дней / элементов до…»
	- наибольшая площадь, диапазон, где элемент — минимум или максимум (ближайшие меньшие слева и справа)
- **Сложность:** T: O(n), каждый элемент входит и выходит один раз · S: O(n)
- **Шаблон:**
	```python
	res = [-1] * len(nums)
	stack = []                                 # индексы; значения не возрастают
	for i, x in enumerate(nums):
	    while stack and nums[stack[-1]] < x:   # x — «следующий больший» для верхушки
	        j = stack.pop()
	        res[j] = i                         # индекс большего; значение nums[i], расстояние i - j
	    stack.append(i)
	# в стеке остались те, у кого следующего большего нет

	# по кругу (Next Greater Element II): идём 2n шагов, кладём в стек только первый круг
	# for i in range(2 * n): x = nums[i % n] ... if i < n: stack.append(i)

	# ближайшие меньшие с двух сторон (гистограмма): в конец кладём сторож 0
	heights.append(0)
	stack, best = [], 0
	for i, h in enumerate(heights):
	    while stack and heights[stack[-1]] >= h:
	        height = heights[stack.pop()]
	        left = stack[-1] if stack else -1  # ближайший меньший слева
	        best = max(best, height * (i - left - 1))   # справа — i
	    stack.append(i)
	```
- **Задачи:**
	- [Next Greater Element I](https://leetcode.com/problems/next-greater-element-i/) · Easy
	- [Daily Temperatures](https://leetcode.com/problems/daily-temperatures/) · Medium · нюанс: ответом нужно расстояние `i - j`, а не само значение
	- [Next Greater Element II](https://leetcode.com/problems/next-greater-element-ii/) · Medium · нюанс: массив по кругу, поэтому смотри второй блок шаблона
	- [Remove K Digits](https://leetcode.com/problems/remove-k-digits/) · Medium · нюанс: жадный алгоритм со счётчиком `k`: пока `k` не кончился и верхушка больше текущей цифры, убираем верхушку и уменьшаем `k`. В конце, если `k` остался, отрезаем столько цифр с хвоста и убираем ведущие нули
	- [Largest Rectangle in Histogram](https://leetcode.com/problems/largest-rectangle-in-histogram/) · Hard · нюанс: смотри третий блок шаблона, нужны обе границы

### Псевдостек

- **Суть:** задача в целом похожа на стековую (скобки, вложенность), но стек нужен только затем, чтобы знать его размер, а не содержимое. Раз в него кладутся одинаковые элементы, достаточно счётчика.
- **Когда:**
	- задача похожа на стековую, но важен только размер стека, а не то, что в нём лежит
	- в стек кладутся только одинаковые элементы (например, один вид скобок)
	- нужна глубина вложенности или число лишних скобок
- **Сложность:** T: O(n) · S: O(1)
- **Шаблон:**
	```python
	depth = best = extra = 0
	for ch in s:
	    if ch == "(":
	        depth += 1                 # аналог push
	        best = max(best, depth)    # максимальная глубина
	    elif depth > 0:
	        depth -= 1                 # аналог pop
	    else:
	        extra += 1                 # «)» без пары
	return extra + depth               # лишние «)» + незакрытые «(»
	```
- **Задачи:**
	- [Maximum Nesting Depth of the Parentheses](https://leetcode.com/problems/maximum-nesting-depth-of-the-parentheses/) · Easy · нюанс: ответом будет `best`
	- [Remove Outermost Parentheses](https://leetcode.com/problems/remove-outermost-parentheses/) · Easy · нюанс: внешняя скобка — та, что открывается при `depth == 0` или после закрытия возвращает `depth` в 0; её в ответ не берём
	- [Minimum Add to Make Parentheses Valid](https://leetcode.com/problems/minimum-add-to-make-parentheses-valid/) · Medium · нюанс: ответом будет `extra + depth`
	- [Score of Parentheses](https://leetcode.com/problems/score-of-parentheses/) · Medium · нюанс: когда встретили `()`, прибавляем `1 << depth`, где `depth` — глубина после закрытия скобки

### Стек промежуточных результатов

- **Суть:** кладём в стек то, что пока нельзя обработать, и возвращаемся к этому, когда приходит закрывающий элемент или операция. Главное — определить, что лежит в стеке (символ, число, пара «строка + множитель») и что делаем при pop.
- **Когда:**
	- нужно вычислить выражение (калькулятор, обратная польская запись)
	- работа со скобками и иными вложенными структурами (парные скобки разных видов, декодирование, путь)
	- в условии буквально сказано использовать стек или хранить промежуточные результаты
	- нужно вернуться к состоянию «до», например при удалении соседних дубликатов
- **Сложность:** T: O(n) · S: O(n)
- **Шаблон:**
	```python
	# скобки разных видов
	pairs = {")": "(", "]": "[", "}": "{"}
	stack = []
	for ch in s:
	    if ch in pairs:                          # закрывающая: сверяем с верхушкой
	        if not stack or stack.pop() != pairs[ch]:
	            return False
	    else:
	        stack.append(ch)                     # открывающая: откладываем
	return not stack

	# вычисление выражения (обратная польская запись)
	from operator import add, sub, mul
	ops = {"+": add, "-": sub, "*": mul, "/": lambda a, b: int(a / b)}   # деление с усечением к нулю
	stack = []
	for t in tokens:
	    if t in ops:
	        b, a = stack.pop(), stack.pop()      # сначала правый операнд
	        stack.append(ops[t](a, b))
	    else:
	        stack.append(int(t))
	return stack[0]
	```

## Префиксный массив

Массив, в котором для каждой позиции заранее посчитан результат по всем элементам до неё. Один раз тратим O(n) на подготовку, потом любой запрос по отрезку отвечает за O(1). Обычно пригождается, когда в условии много запросов или надо считать подмассивы.

> [!tip] Как выбрать паттерн
> - Много запросов «сумма на отрезке» или нужно быстро получить значение по отрезку → **префиксные суммы**
> - Нужно посчитать подмассивы с заданной суммой (или другим свойством префикса) → **префикс и хеш-таблица**
> - Значение для элемента зависит от всего, что слева, и от всего, что справа → **префикс и суффикс**
> - Много обновлений «прибавить на отрезке», а результат нужен только в конце → **разностный массив**

### Префиксные суммы

- **Суть:** заранее считаем `prefix[i]` — сумму первых `i` элементов. Тогда сумма на любом отрезке — разность двух значений: `prefix[r + 1] - prefix[l]`. Главное — сделать массив на один элемент длиннее, с нулём в начале, чтобы не разбирать отдельно отрезки с нулевого индекса.
- **Когда:**
	- много запросов «сумма на отрезке `[l, r]`»
	- нужно сравнить сумму слева и справа от позиции
- **Сложность:** T: O(n) на подготовку, потом O(1) на запрос · S: O(n)
- **Шаблон:**
	```python
	# Пример: Range Sum Query — много раз спрашивают сумму на отрезке. nums = [2, 4, 1, 3]
	prefix = [0]                          # prefix[i] — сумма первых i элементов
	for x in nums:
	    prefix.append(prefix[-1] + x)     # prefix = [0, 2, 6, 7, 10]

	# сумма nums[l..r] включительно
	total = prefix[r + 1] - prefix[l]     # l = 1, r = 2 → 7 - 2 = 5 (это 4 + 1)
	```
- **Задачи:**
	- [Running Sum of 1d Array](https://leetcode.com/problems/running-sum-of-1d-array/) · Easy
	- [Range Sum Query - Immutable](https://leetcode.com/problems/range-sum-query-immutable/) · Easy
	- [Find Pivot Index](https://leetcode.com/problems/find-pivot-index/) · Easy · нюанс: сумма слева равна `total - left - nums[i]`, второй массив не нужен

### Префикс и хеш-таблица

- **Суть:** идём по массиву и копим префиксную сумму `cur`. Подмассив, который заканчивается здесь и имеет сумму `k`, существует, если раньше был префикс `cur - k`. Все встреченные префиксы храним в хеш-таблице.
- **Когда:**
	- нужно посчитать или найти подмассивы с заданной суммой
	- условие можно свести к «разность двух префиксов равна X»
- **Сложность:** T: O(n) · S: O(n)
- **Шаблон:**
	```python
	# Пример: Subarray Sum Equals K. nums = [1, 2, 3], k = 3 → 2 (подмассивы [1, 2] и [3])
	count = cur = 0
	seen = {0: 1}                          # пустой префикс с суммой 0 встретился один раз
	for x in nums:
	    cur += x                           # префиксная сумма до текущего элемента
	    count += seen.get(cur - k, 0)      # сколько раньше было префиксов cur - k, столько подмассивов с суммой k заканчиваются здесь
	    seen[cur] = seen.get(cur, 0) + 1   # запоминаем только после подсчёта
	```
- **Задачи:**
	- [Subarray Sum Equals K](https://leetcode.com/problems/subarray-sum-equals-k/) · Medium
	- [Contiguous Array](https://leetcode.com/problems/contiguous-array/) · Medium · нюанс: заменяем `0` на `-1`, ищем самый длинный подмассив с суммой 0, в таблице хранится первый индекс префикса
	- [Continuous Subarray Sum](https://leetcode.com/problems/continuous-subarray-sum/) · Medium · нюанс: в таблице хранится `cur % k`, а не сам префикс

### Префикс и суффикс

- **Суть:** для каждого элемента считаем результат по всему, что слева от него (префикс), и по всему, что справа (суффикс), и склеиваем. Сам элемент в оба результата не входит. Левую часть записываем в ответ первым проходом, правую домножаем вторым проходом справа налево, так лишний массив не нужен.
- **Когда:**
	- ответ для элемента зависит от всех остальных элементов
	- делить на сумму или произведение нельзя или не хочется
- **Сложность:** T: O(n) · S: O(1), без учёта результата
- **Шаблон:**
	```python
	# Пример: Product of Array Except Self. nums = [1, 2, 3, 4] → [24, 12, 8, 6]
	n = len(nums)
	res = [1] * n

	left = 1
	for i in range(n):                    # слева направо
	    res[i] = left                     # произведение всего слева от i
	    left *= nums[i]

	right = 1
	for i in range(n - 1, -1, -1):        # справа налево
	    res[i] *= right                   # домножаем на произведение всего справа от i
	    right *= nums[i]
	```
- **Задачи:**
	- [Product of Array Except Self](https://leetcode.com/problems/product-of-array-except-self/) · Medium
	- [Trapping Rain Water](https://leetcode.com/problems/trapping-rain-water/) · Hard · нюанс: слева и справа считаем не сумму, а максимум, вода над столбиком — `min(max_left, max_right) - height[i]`

### Разностный массив

- **Суть:** это обратная операция к префиксным суммам. Чтобы прибавить число на всём отрезке `[l, r]`, не трогаем каждый элемент, а меняем две точки: `+x` в начале и `-x` сразу после конца. В конце один раз считаем префиксные суммы по разностному массиву и получаем итог.
- **Когда:**
	- много операций «прибавить число на отрезке», а результат нужен только после всех
	- задачу на отрезки можно решить без сортировки событий, если координаты небольшие
- **Сложность:** T: O(n + q), где q — число операций · S: O(n)
- **Шаблон:**
	```python
	# Пример: Corporate Flight Bookings. Бронь [first, last, seats] добавляет места на рейсы от first до last (рейсы с 1).
	# bookings = [[1, 2, 10], [2, 3, 20], [2, 5, 25]], n = 5 → [10, 55, 45, 25, 25]
	diff = [0] * (n + 1)
	for first, last, seats in bookings:
	    diff[first - 1] += seats          # с этого рейса начинаем прибавлять
	    diff[last] -= seats               # сразу после последнего рейса перестаём

	res, cur = [], 0
	for i in range(n):
	    cur += diff[i]                    # префиксные суммы по diff дают итог
	    res.append(cur)
	```
- **Задачи:**
	- [Corporate Flight Bookings](https://leetcode.com/problems/corporate-flight-bookings/) · Medium
	- [Car Pooling](https://leetcode.com/problems/car-pooling/) · Medium · нюанс: пассажиры выходят на `to`, поэтому `-passengers` ставим в `diff[to]`
	- [Range Addition](https://leetcode.com/problems/range-addition/) · Medium · 🔒 premium

## Односвязный список

Цепочка узлов, где у каждого есть значение и ссылка `next` на следующий. Назад ходить нельзя, к элементу по индексу не обратиться, нужно идти от головы. В коде обычно `ListNode` с полями `val` и `next`. Главная ловушка — потерять остаток списка, когда переписываешь `next`, поэтому сначала запомни следующий узел.

> [!tip] Как выбрать паттерн
> - Нужен цикл, середина или k-й элемент с конца → **черепаха и заяц**
> - Нужно развернуть список или его часть → **разворот списка**
> - Нужно переставить узлы «первый, последний, второй, предпоследний…» → **разворот части и слияние**
> - Иначе (слить, удалить, собрать новый список, особенно если может измениться голова) → **фиктивный узел**

### Черепаха и заяц

- **Суть:** два указателя идут от головы с разной скоростью: медленный на один шаг, быстрый на два. Если есть цикл, быстрый догонит медленного. Если цикла нет, то к моменту, когда быстрый дошёл до конца, медленный стоит в середине.
- **Схема:** список с циклом `1 → 2 → 3 → 4 → 5 → 3`.
	```mermaid
	flowchart LR
	    n1((1)) --> n2((2)) --> n3((3)) --> n4((4)) --> n5((5))
	    n5 --> n3
	```
	Черепаха шагает на 1, заяц на 2. Внутри цикла заяц догоняет черепаху на один шаг за ход, поэтому они обязательно встретятся. Нет цикла — заяц дойдёт до `None`.
- **Когда:**
	- нужно понять, есть ли цикл в списке
	- нужно найти середину списка
	- нужно найти k-й элемент с конца: быстрому дают фору в k шагов, потом идут с одной скоростью
- **Сложность:** T: O(n) · S: O(1)
- **Шаблон:**
	```python
	# Пример: Linked List Cycle — есть ли в списке цикл
	slow = fast = head
	while fast and fast.next:             # fast ходит через узел, поэтому проверяем и fast, и fast.next
	    slow = slow.next                  # один шаг
	    fast = fast.next.next             # два шага
	    if slow is fast:                  # встретились, значит есть цикл
	        return True
	return False

	# середина списка: тот же цикл без проверки на встречу.
	# Когда fast дошёл до конца, slow стоит в середине (при чётной длине — на втором из двух средних)
	```
- **Задачи:**
	- [Middle of the Linked List](https://leetcode.com/problems/middle-of-the-linked-list/) · Easy
	- [Linked List Cycle](https://leetcode.com/problems/linked-list-cycle/) · Easy
	- [Remove Nth Node From End of List](https://leetcode.com/problems/remove-nth-node-from-end-of-list/) · Medium · нюанс: быстрый начинает на `n` шагов впереди, медленный стартует с фиктивного узла
	- [Linked List Cycle II](https://leetcode.com/problems/linked-list-cycle-ii/) · Medium · нюанс: после встречи один указатель возвращаем в голову, и дальше оба идут по одному шагу до новой встречи, это начало цикла
	- [Palindrome Linked List](https://leetcode.com/problems/palindrome-linked-list/) · Easy · нюанс: найти середину, развернуть вторую половину, сравнить

### Разворот списка

- **Суть:** идём по списку и у каждого узла перенаправляем `next` на предыдущий. Для этого нужны три переменные: предыдущий, текущий и следующий, который мы запоминаем до переписывания, чтобы не потерять остаток.
- **Когда:**
	- нужно развернуть список целиком или его часть
	- нужно прочитать список с конца без дополнительной памяти
- **Сложность:** T: O(n) · S: O(1)
- **Шаблон:**
	```python
	# Пример: Reverse Linked List. 1 → 2 → 3 → None превращаем в 3 → 2 → 1 → None
	prev = None
	cur = head
	while cur:
	    nxt = cur.next                    # запомнили следующий, иначе потеряем остаток списка
	    cur.next = prev                   # развернули ссылку назад
	    prev, cur = cur, nxt              # сдвинулись вперёд
	return prev                           # prev — новая голова
	```
- **Задачи:**
	- [Reverse Linked List](https://leetcode.com/problems/reverse-linked-list/) · Easy
	- [Swap Nodes in Pairs](https://leetcode.com/problems/swap-nodes-in-pairs/) · Medium · нюанс: разворачиваем кусками по два, нужен фиктивный узел перед головой
	- [Reverse Linked List II](https://leetcode.com/problems/reverse-linked-list-ii/) · Medium · нюанс: сначала дойти до узла перед отрезком, развернуть отрезок, потом сшить концы

### Фиктивный узел

- **Суть:** перед головой ставим пустой узел `dummy`. Тогда у первого узла тоже есть предыдущий, и не нужно отдельно разбирать случаи «удаляем или добавляем в голову». В конце возвращаем `dummy.next`.
- **Когда:**
	- нужно слить или собрать новый список
	- нужно удалить узлы, и удалиться может сама голова
- **Сложность:** T: O(n) · S: O(1), без учёта нового списка (узлы переиспользуются)
- **Шаблон:**
	```python
	# Пример: Merge Two Sorted Lists. 1 → 2 → 4 и 1 → 3 → 4 сливаем в 1 → 1 → 2 → 3 → 4 → 4
	dummy = tail = ListNode()             # tail — последний узел собранного списка
	while a and b:
	    if a.val <= b.val:
	        tail.next = a
	        a = a.next
	    else:
	        tail.next = b
	        b = b.next
	    tail = tail.next
	tail.next = a or b                    # дописываем остаток от того списка, где ещё что-то осталось
	return dummy.next                     # голова собранного списка
	```

### Разворот части и слияние

- **Суть:** составная техника из трёх шагов, которые уже есть выше. Находим середину (черепаха и заяц), разворачиваем вторую половину, потом сшиваем две половины по очереди: узел из первой, узел из второй. Так получается порядок «первый, последний, второй, предпоследний…» без дополнительной памяти.
- **Когда:**
	- дана голова списка, нужно переставить узлы в порядке «первый, последний, второй, предпоследний и так далее»
	- нужно сравнивать или складывать узлы с начала и с конца одновременно
- **Сложность:** T: O(n) · S: O(1)
- **Шаблон:**
	```python
	# Пример: Reorder List. 1 → 2 → 3 → 4 → 5 превращаем в 1 → 5 → 2 → 4 → 3
	# 1) находим середину
	slow = fast = head
	while fast and fast.next:
	    slow = slow.next
	    fast = fast.next.next

	# 2) разворачиваем вторую половину и отрезаем её от первой
	prev, cur = None, slow.next
	slow.next = None                      # первая половина теперь заканчивается на slow
	while cur:
	    nxt = cur.next
	    cur.next = prev
	    prev, cur = cur, nxt
	second = prev                         # голова развёрнутой второй половины (5 → 4)

	# 3) сшиваем по очереди: узел из первой половины, узел из второй
	first = head
	while second:
	    n1, n2 = first.next, second.next  # запомнили продолжения обеих половин
	    first.next = second
	    second.next = n1
	    first, second = n1, n2
	```

## Перебор комбинаций

Нужно найти все варианты или лучший из них: подмножества, перестановки, сочетания, расстановки. Быстрого трюка нет, ответ получается перебором, поэтому первым делом смотри на ограничения. Если `n` до 20 (подмножества) или до 8–10 (перестановки), перебор укладывается в лимит. Если `n` в тысячах, это не перебор, ищи другой паттерн.

> [!tip] Как выбрать паттерн
> - Кандидатов можно породить сразу, все они равноправны, остаётся проверить или посчитать → **полный перебор**
> - Кандидата строим по шагам и по неподходящему началу видно, что продолжать нет смысла (сумма уже больше цели, ферзь под боем) → **поиск с возвратом**
> - Нужны все подмножества, элементов до 20, и надо быстро проверять пересечения или хранить, что уже занято → **перебор битовых масок**
> - Нужно только посчитать количество или лучшее значение, а подзадачи повторяются → это уже [[#Динамическое программирование]], не перебор

### Полный перебор

- **Суть:** порождаем все кандидаты без отсечений, вложенными циклами или рекурсией, и для каждого проверяем условие. Просто и надёжно, пока вариантов немного.
- **Когда:**
	- нужно вернуть все комбинации, а размер каждой фиксирован и известен заранее
	- ограничения малы, и проверка одного кандидата дешёвая
	- нужен рабочий вариант, оптимизация которого потом не нужна или будет отдельным шагом
- **Сложность:** T: O(число кандидатов × проверка), например O(k^n) для декартова произведения, O(n!) для перестановок, O(C(n, k)) для сочетаний · S: O(n) без учёта ответа
- **Шаблон:**
	```python
	# Пример: Letter Combinations of a Phone Number. "23" → ["ad", "ae", "af", "bd", "be", "bf", "cd", "ce", "cf"]
	# Декартово произведение вручную: на каждой цифре дописываем к каждой готовой строке каждую букву
	letters = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl",
	           "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"}
	if not digits:
	    return []                             # без цифр ответ пустой, а не [""]
	res = [""]
	for d in digits:
	    nxt = []
	    for prefix in res:
	        for ch in letters[d]:
	            nxt.append(prefix + ch)
	    res = nxt
	return res
	```

	- [Combinations](https://leetcode.com/problems/combinations/) · Medium · нюанс: сочетания собираем рекурсией, это поиск с возвратом, см. шаблон ниже

### Поиск с возвратом

- **Суть:** строим кандидата по шагам. На каждом шаге выбираем элемент, идём глубже, а вернувшись, отменяем выбор и пробуем следующий. Главное отличие от полного перебора: если начало уже не годится, всю ветку отрезаем и дальше не идём.
- **Схема:** подмножества `[2, 3, 4]` с суммой 5, берём элементы по возрастанию.
	```mermaid
	flowchart TD
	    r["[] · 0"] --> a["[2] · 2"]
	    r --> b["[3] · 3"]
	    r --> c["[4] · 4"]
	    a --> a1["[2, 3] · 5 ✓"]
	    a --> a2["[2, 4] · 6 ✗"]
	    b --> b1["[3, 4] · 7 ✗"]
	```
	В узле набранный кандидат и его сумма. Сумма уже больше 5, значит ветку отрезаем и не расширяем. Нашли `[2, 3]`, вернулись и отменили выбор. Перебор без отсечений дошёл бы до всех подмножеств.
- **Когда:**
	- нужно найти все решения, удовлетворяющие условию (сумма, расстановка, разбиение)
	- условие можно проверить на неполном кандидате и отбросить раньше
	- длина ответа заранее не известна
- **Сложность:** T: в худшем случае как полный перебор (экспонента), на практике сильно меньше за счёт отсечений · S: O(глубина рекурсии)
- **Шаблон:**
	```python
	# Пример: Combination Sum. candidates = [2, 3, 6, 7], target = 7 → [[2, 2, 3], [7]]
	candidates.sort()                         # нужна для отсечения: дальше будут только большие числа
	res, path = [], []

	def go(start, rest):
	    if rest == 0:                         # собрали ответ
	        res.append(path[:])               # копия: path дальше будет меняться
	        return
	    for i in range(start, len(candidates)):
	        if candidates[i] > rest:          # отсечение: остальные ещё больше
	            break
	        path.append(candidates[i])        # выбрали
	        go(i, rest - candidates[i])       # i, а не i + 1: число можно брать повторно
	        path.pop()                        # отменили выбор и пробуем следующее

	go(0, target)
	return res
	```

	- [Permutations](https://leetcode.com/problems/permutations/) · Medium · нюанс: `start` не нужен, цикл идёт по всем индексам, занятые отмечаем в массиве `used` и пропускаем; после возврата снимаем отметку
	- [Combination Sum II](https://leetcode.com/problems/combination-sum-ii/) · Medium · нюанс: числа не повторяются, поэтому рекурсия с `i + 1`; чтобы не было одинаковых наборов, после сортировки пропускаем `candidates[i] == candidates[i - 1]`, если `i > start`
	- [Generate Parentheses](https://leetcode.com/problems/generate-parentheses/) · Medium · нюанс: отсечение по счётчикам, `(` можно, пока открытых меньше `n`, `)` можно, пока закрытых меньше открытых
	- [Word Search](https://leetcode.com/problems/word-search/) · Medium · нюанс: поле вместо списка, выбор — соседняя клетка; пройденную клетку временно помечаем и после возврата восстанавливаем

### Перебор битовых масок

- **Суть:** подмножество из `n` элементов хранится как число от `0` до `2^n - 1`. Бит `i` включён, значит элемент `i` в подмножестве. Перебрать все подмножества можно обычным циклом, а пересечение, объединение и проверка «уже занято» делаются побитовыми операциями.
- **Когда:**
	- нужно перебрать все подмножества, и `n` не больше 20
	- нужно быстро проверять, что два набора не пересекаются (например, наборы букв)
	- состояние «что использовано» помещается в одно число
- **Сложность:** T: O(2^n × n) · S: O(1) без учёта ответа
- **Шаблон:**
	```python
	# Пример: Subsets. [1, 2, 3] → [[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]
	n = len(nums)
	res = []
	for mask in range(1 << n):                # 1 << n == 2^n, каждое число — одно подмножество
	    res.append([nums[i] for i in range(n) if mask >> i & 1])   # берём элементы с включённым битом
	return res

	# проверки на масках:
	# mask >> i & 1       — есть ли элемент i в наборе
	# a & b               — общие элементы двух наборов (0 — не пересекаются)
	# a | b               — объединение наборов
	```
- **Задачи:**
	- [Subsets](https://leetcode.com/problems/subsets/) · Medium
	- [Maximum Length of a Concatenated String with Unique Characters](https://leetcode.com/problems/maximum-length-of-a-concatenated-string-with-unique-characters/) · Medium · нюанс: каждое слово превращаем в маску букв; слово с повторами отбрасываем, слова с `a & b != 0` вместе брать нельзя
	- [Maximum Product of Word Lengths](https://leetcode.com/problems/maximum-product-of-word-lengths/) · Medium · нюанс: подмножества не перебираем, маска нужна только для проверки «нет общих букв» у пары слов

## Деревья

Бинарное дерево: у каждого узла есть значение и до двух детей, `left` и `right`. Почти все задачи решаются рекурсивным обходом, поэтому сначала реши, в какую сторону течёт информация. Либо мы несём её вниз от корня (глубина, сумма на пути, границы), либо собираем наверх из детей (высота, размер, ответ для поддерева). Третий случай — когда важны уровни, тогда идём не вглубь, а вширь.

> [!tip] Как выбрать паттерн
> - Ответ для узла зависит от того, что было на пути от корня (глубина, сумма, максимум, границы, путь) → **обход сверху вниз**
> - Ответ для узла зависит от ответов для его детей (высота, баланс, диаметр, общий предок) → **обход снизу вверх**
> - Нужны уровни, ближайший к корню узел или кратчайший путь по рёбрам → **обход по уровням**
> - Дерево поиска (левое меньше, правое больше), нужно искать, вставлять, удалять → **дерево поиска**
> - В условии названы прямой, симметричный или обратный порядок, нужен k-й элемент по порядку → **порядки обхода**
> - Даны обходы или массив, нужно собрать дерево, либо превратить дерево в строку → **построение дерева**
> - Нужны оба направления сразу: параметр вниз, результат вверх. Это обход снизу вверх с дополнительным аргументом, шаблон тот же

### Обход сверху вниз

- **Суть:** рекурсивная функция получает аргументы от родителя, дополняет их данными текущего узла и передаёт детям. К моменту, когда мы дошли до узла, всё нужное о пути от корня уже лежит в аргументах. Результат либо накапливается в общей переменной, либо суммируется из возвращаемых значений.
- **Когда:**
	- в условии есть «на пути от корня», «предки», «от корня до листа»
	- нужно знать глубину, накопленную сумму или максимум на пути
	- у поддерева есть ограничение, пришедшее сверху (например, границы значений в дереве поиска)
- **Сложность:** T: O(n) · S: O(h), где h — высота дерева (в худшем случае n)
- **Шаблон:**
	```python
	# Пример: Count Good Nodes in Binary Tree. Узел хороший, если на пути от корня нет значения больше него
	def go(node, max_so_far):                 # max_so_far — то, что мы принесли сверху
	    if not node:
	        return 0
	    count = 1 if node.val >= max_so_far else 0
	    max_so_far = max(max_so_far, node.val)           # обновили для детей
	    return count + go(node.left, max_so_far) + go(node.right, max_so_far)

	return go(root, float("-inf"))
	```

	- [Path Sum](https://leetcode.com/problems/path-sum/) · Easy · нюанс: передаём вниз остаток суммы `target - node.val`, на листе сравниваем остаток с нулём

### Обход снизу вверх

- **Суть:** сначала рекурсивно спрашиваем у обоих детей, потом считаем ответ для текущего узла из того, что они вернули. Пустое поддерево — базовый случай. Если нужный ответ шире, чем то, что мы возвращаем родителю (например, путь, который изгибается в узле), его копим в общей переменной, а наверх отдаём только то, что нужно родителю.
- **Когда:**
	- нужно что-то посчитать про поддерево целиком: высоту, размер, сумму, баланс
	- решение в узле принимается, когда известны ответы слева и справа
	- нужно найти узел, обладающий свойством относительно своего поддерева (общий предок, корень совпавшего поддерева)
- **Сложность:** T: O(n) · S: O(h)
- **Шаблон:**
	```python
	# Пример: Diameter of Binary Tree. Диаметр — самый длинный путь между двумя узлами, в рёбрах
	best = 0

	def height(node):                         # возвращаем родителю высоту поддерева
	    nonlocal best
	    if not node:
	        return 0
	    left = height(node.left)
	    right = height(node.right)
	    best = max(best, left + right)        # путь, который изгибается в этом узле: ответ копим отдельно
	    return 1 + max(left, right)           # наверх можно отдать только одну ветку

	height(root)
	return best
	```

### Обход по уровням

- **Суть:** очередь, в которой лежит один уровень дерева. На каждом шаге берём столько узлов, сколько было в очереди в начале шага, это ровно один уровень, и добавляем в очередь их детей. Дерево обходится по слоям от корня вниз.
- **Когда:**
	- в условии «по уровням», «по слоям», «справа», «в каждой строке»
	- нужен ближайший к корню узел с некоторым свойством или кратчайший путь по рёбрам
	- ответ считается отдельно для каждого уровня (среднее, максимум, крайний узел)
- **Сложность:** T: O(n) · S: O(w), где w — максимальная ширина дерева
- **Шаблон:**
	```python
	# Пример: Binary Tree Level Order Traversal. Значения по уровням: [[3], [9, 20], [15, 7]]
	from collections import deque

	if not root:
	    return []
	res = []
	q = deque([root])
	while q:
	    level = []
	    for _ in range(len(q)):               # len(q) берём один раз, до добавления детей: это размер уровня
	        node = q.popleft()
	        level.append(node.val)
	        if node.left:
	            q.append(node.left)
	        if node.right:
	            q.append(node.right)
	    res.append(level)
	return res

	# олимпиадный вариант очереди: список и индекс головы, deque не нужен
	q, head = [root], 0
	while head < len(q):
	    end = len(q)                          # граница уровня: всё до end — текущий уровень
	    level = []
	    while head < end:
	        node = q[head]
	        head += 1
	        level.append(node.val)
	        if node.left:
	            q.append(node.left)
	        if node.right:
	            q.append(node.right)
	    res.append(level)
	```

### Дерево поиска

- **Суть:** в двоичном дереве поиска всё в левом поддереве меньше значения узла, а всё в правом больше. Поэтому поиск, вставка и удаление идут по одной ветке: сравнили, свернули влево или вправо. Симметричный обход такого дерева выдаёт значения по возрастанию.
- **Когда:**
	- в условии «дерево поиска», «BST», «отсортированный порядок»
	- нужно найти, вставить или удалить значение, не обходя всё дерево
	- нужно использовать отсортированность: k-й по величине, ближайшее значение, диапазон
- **Сложность:** T: O(h), где h — высота (в среднем log n, в худшем n) · S: O(h)
- **Шаблон:**
	```python
	# Пример: Insert into a Binary Search Tree. Новое значение всегда становится листом
	def insert(node, val):
	    if not node:
	        return TreeNode(val)              # дошли до пустого места, здесь и ставим
	    if val < node.val:
	        node.left = insert(node.left, val)     # идём только в одну сторону
	    else:
	        node.right = insert(node.right, val)
	    return node                           # возвращаем узел, чтобы родитель сохранил ссылку

	return insert(root, val)
	```

> [!note] Для эрудиции: сбалансированные деревья и родственники
> Если вставлять в дерево поиска значения по возрастанию, оно выродится в список и операции станут O(n). Чтобы этого не было, дерево подправляют после каждой вставки и удаления. Основной инструмент — **поворот**: локальная перестановка двух узлов, которая сохраняет порядок значений, но меняет высоту. Реализации на собеседованиях почти не просят, спрашивают «что это и зачем».
>
> - **AVL-дерево.** Высоты левого и правого поддерева любого узла отличаются не больше чем на 1. Это самое строгое условие, поэтому дерево самое низкое и поиск быстрый, но вставка и удаление делают больше поворотов. Подходит, когда читают чаще, чем пишут.
> - **Красно-чёрное дерево.** У каждого узла есть цвет (красный или чёрный). Правила: корень чёрный; у красного узла оба ребёнка чёрные; на всех путях от узла до пустого места одинаковое число чёрных узлов. Из этого следует, что самый длинный путь не больше чем вдвое длиннее самого короткого, то есть высота ≤ 2·log n. Условие мягче, чем у AVL: дерево чуть выше, зато при вставке и удалении поворотов мало (до 2 и до 3). Используется как стандартное упорядоченное множество и словарь: `std::map` и `std::set` в C++ (стандарт дерево не требует, но основные реализации берут именно его), `TreeMap` в Java; в Java 8 из таких деревьев ещё и состоят корзины `HashMap`, в которых много коллизий. Цвет здесь служебная метка, с раскраской графа это не связано.
> - **B-дерево и B+-дерево.** У узла много детей (сотни), дерево получается очень низким. Нужно там, где узел читают целиком одним обращением к диску: индексы в базах данных, файловые системы. В B+-дереве значения лежат только в листьях, а листья связаны списком, поэтому диапазон `между a и b` читается подряд.
> - **Декартово дерево (treap) и список с пропусками (skip list).** Балансируются случайностью, а не поворотами по строгим правилам. Проще в коде. Skip list используется в упорядоченных множествах Redis.
> - **Splay-дерево.** Недавно использованный узел поворотами поднимается к корню. Хорошо для кэшей и неравномерных запросов, но на отдельную операцию гарантии O(log n) нет, только в среднем.
>
> Рядом стоят структуры, которые похожи на дерево, но деревом поиска не являются:
> - **Куча** (heap): двоичное дерево в массиве, где родитель не больше детей. Быстро достаёт минимум, искать по значению не умеет. На ней работает `heapq` в Python и очередь в алгоритме Дейкстры.
> - **Префиксное дерево** (trie): по рёбрам идут буквы, путь от корня — слово. Для поиска по префиксу и автодополнения.
> - **Дерево отрезков и дерево Фенвика**: суммы или минимумы на отрезке с изменением элементов, продолжение темы префиксных сумм, когда значения меняются.
>
> В Python сбалансированного дерева в стандартной библиотеке нет. Хватает отсортированного списка с `bisect` (поиск быстрый, вставка O(n)).

### Порядки обхода

- **Суть:** три способа обойти дерево в глубину, отличаются моментом, когда мы «обрабатываем» узел. Прямой (preorder): узел, левое, правое. Симметричный (inorder): левое, узел, правое. Обратный (postorder): левое, правое, узел. Обратный даёт обход снизу вверх, прямой — сверху вниз, а симметричный на дереве поиска выдаёт отсортированный порядок. Рекурсия записывается тремя строками в разном порядке, но на собеседовании часто просят вариант со стеком.
- **Когда:**
	- в условии прямо названо, в каком порядке выдать значения
	- нужен k-й по порядку элемент дерева поиска или следующий за заданным
	- нужно остановиться на середине обхода, не обходя всё дерево
- **Сложность:** T: O(n) · S: O(h)
- **Шаблон:**
	```python
	# Пример: Kth Smallest Element in a BST. Симметричный обход со стеком, остановка на k-м узле
	stack = []
	node = root
	while stack or node:
	    while node:                           # спускаемся влево до упора, запоминая путь
	        stack.append(node)
	        node = node.left
	    node = stack.pop()                    # самый левый непосещённый узел
	    k -= 1
	    if k == 0:
	        return node.val
	    node = node.right                     # потом правое поддерево

	# те же три порядка рекурсивно:
	# preorder:  res.append(node.val); go(node.left); go(node.right)
	# inorder:   go(node.left); res.append(node.val); go(node.right)
	# postorder: go(node.left); go(node.right); res.append(node.val)
	```

### Построение дерева

- **Суть:** по результатам обходов восстанавливаем дерево. В прямом обходе корень первый, в обратном последний. В симметричном корень делит значения на левое и правое поддерево. Берём корень из прямого обхода, находим его в симметричном и рекурсивно строим левую и правую части.
- **Когда:**
	- даны два обхода (прямой и симметричный, либо симметричный и обратный), нужно построить дерево
	- дерево нужно превратить в строку и обратно (сериализация)
	- дан отсортированный массив, нужно построить сбалансированное дерево поиска
- **Сложность:** T: O(n) при словаре индексов · S: O(n)
- **Шаблон:**
	```python
	# Пример: Construct Binary Tree from Preorder and Inorder Traversal
	idx = {v: i for i, v in enumerate(inorder)}       # где значение стоит в симметричном обходе
	it = iter(preorder)                               # корни выдаём по очереди в прямом порядке

	def build(lo, hi):                        # lo..hi — границы поддерева в inorder
	    if lo > hi:
	        return None
	    val = next(it)                        # следующий корень в preorder
	    mid = idx[val]
	    node = TreeNode(val)
	    node.left = build(lo, mid - 1)        # левое строим раньше правого: в preorder оно идёт первым
	    node.right = build(mid + 1, hi)
	    return node

	return build(0, len(inorder) - 1)
	```

	- [Construct Binary Tree from Inorder and Postorder Traversal](https://leetcode.com/problems/construct-binary-tree-from-inorder-and-postorder-traversal/) · Medium · нюанс: корни берём с конца обратного обхода, поэтому правое поддерево строим раньше левого

## Графы

Граф — это вершины и рёбра между ними. В задачах он часто спрятан: сетка из клеток (соседи сверху, снизу, слева, справа), курсы с зависимостями, слова, которые отличаются на одну букву. Первым делом решай, как хранить граф. Чаще всего это словарь списков смежности `graph[u] = [v, ...]`, а для сетки соседей считают по координатам. Вторая ловушка — циклы: без множества посещённых вершин обход зациклится.

> [!tip] Как выбрать паттерн
> - Нужно обойти всё достижимое: посчитать компоненты, острова, понять, можно ли дойти → **обход в глубину**
> - Нужно кратчайшее число шагов, ходы одинаковой стоимости → **обход в ширину**
> - В условии «порядок», «зависит от», «сначала… потом», нужно понять, есть ли цикл зависимостей → **топологическая сортировка**
> - Связи добавляются по одной, нужно быстро отвечать «в одной ли группе», или найти ребро, замкнувшее цикл → **система непересекающихся множеств**
> - Рёбра с разными весами, нужен кратчайший путь → **алгоритм Дейкстры**
> - Есть отрицательные веса или лимит «не больше k рёбер» → **алгоритм Беллмана — Форда**
> - Нужно связать все вершины с минимальной суммой весов → **минимальное остовное дерево**
> - Нужно разбить вершины на две группы так, чтобы связанные оказались в разных → **двудольность**

### Обход в глубину

- **Суть:** из вершины идём в соседа, оттуда в его соседа и так до тупика, потом возвращаемся. Посещённые вершины помечаем, чтобы не ходить по кругу. Одним запуском обходим целую компоненту связности, поэтому число запусков из непосещённых вершин равно числу компонент.
- **Схема:** граф, который обходим из вершины 1 (соседи в порядке номеров).
	```mermaid
	flowchart TD
	    n1((1)) --- n2((2))
	    n1 --- n3((3))
	    n2 --- n4((4))
	    n2 --- n5((5))
	    n3 --- n6((6))
	```
	Порядок посещения в глубину: `1, 2, 4, 5, 3, 6`. Идём до тупика, возвращаемся и берём следующего соседа. В ширину тот же граф даёт `1, 2, 3, 4, 5, 6`, см. [[#Обход в ширину]].
- **Когда:**
	- нужно посчитать компоненты связности или острова на сетке
	- нужно понять, достижима ли вершина из другой
	- нужно пометить или залить область, найти размер области
- **Сложность:** T: O(V + E), для сетки O(строки × столбцы) · S: O(V), на глубину рекурсии
- **Шаблон:**
	```python
	# Пример: Number of Islands. Остров — группа соседних единиц, считаем острова на сетке
	rows, cols = len(grid), len(grid[0])
	count = 0

	def dfs(r, c):
	    if not (0 <= r < rows and 0 <= c < cols) or grid[r][c] != "1":
	        return                            # вышли за сетку или это вода, или уже были
	    grid[r][c] = "0"                      # помечаем посещённой, обнуляя клетку
	    dfs(r + 1, c)
	    dfs(r - 1, c)
	    dfs(r, c + 1)
	    dfs(r, c - 1)

	for r in range(rows):
	    for c in range(cols):
	        if grid[r][c] == "1":             # нашли новый остров
	            count += 1
	            dfs(r, c)                     # затираем весь остров целиком
	return count

	# для обычного графа вместо сетки: visited = set(), соседи — graph[u]
	```

### Обход в ширину

- **Суть:** очередь вершин. Берём вершину, кладём в очередь её непосещённых соседей. Вершины обрабатываются по расстоянию от старта, поэтому первое попадание в цель — кратчайший путь по числу рёбер. Посещённой вершину помечаем при добавлении в очередь, а не при извлечении, иначе она попадёт туда несколько раз.
- **Когда:**
	- нужно минимальное число шагов, ходов, пересадок, когда каждый шаг стоит одинаково
	- старт и цель заданы, путь нужно найти, а не просто проверить достижимость
	- стартовых вершин несколько (например, все гнилые апельсины): кладём их в очередь сразу
- **Сложность:** T: O(V + E) · S: O(V)
- **Шаблон:**
	```python
	# Пример: Shortest Path in Binary Matrix. Из (0,0) в правый нижний угол по нулям, ходы в 8 сторон
	from collections import deque

	n = len(grid)
	if grid[0][0] or grid[n - 1][n - 1]:
	    return -1
	q = deque([(0, 0, 1)])                    # клетка и длина пути до неё (в клетках)
	seen = {(0, 0)}
	while q:
	    r, c, d = q.popleft()
	    if (r, c) == (n - 1, n - 1):
	        return d                          # первый приход в цель — кратчайший
	    for dr in (-1, 0, 1):
	        for dc in (-1, 0, 1):
	            nr, nc = r + dr, c + dc
	            if 0 <= nr < n and 0 <= nc < n and grid[nr][nc] == 0 and (nr, nc) not in seen:
	                seen.add((nr, nc))        # помечаем сейчас, до извлечения из очереди
	                q.append((nr, nc, d + 1))
	return -1

	# олимпиадный вариант очереди: q = [(0, 0, 1)]; head = 0
	# while head < len(q): r, c, d = q[head]; head += 1; ...   (q.append остаётся как есть)
	```

### Топологическая сортировка

- **Суть:** порядок вершин ориентированного графа, в котором каждое ребро ведёт слева направо. Алгоритм Кана: считаем для каждой вершины число входящих рёбер, вершины с нулём кладём в очередь. Достаём вершину, добавляем в ответ и уменьшаем счётчики её соседей, новые нули снова в очередь. Если в ответ попали не все вершины, в графе есть цикл.
- **Когда:**
	- есть зависимости «A нужно сделать до B»: курсы, задачи, сборка пакетов
	- нужно выдать допустимый порядок или понять, что его нет
	- нужно обнаружить цикл в ориентированном графе
- **Сложность:** T: O(V + E) · S: O(V + E)
- **Шаблон:**
	```python
	# Пример: Course Schedule II. prerequisites[i] = [a, b] значит, что курс b нужно пройти до a
	from collections import deque

	graph = [[] for _ in range(numCourses)]   # graph[b] — курсы, которые открываются после b (на LeetCode можно defaultdict(list))
	indeg = [0] * numCourses                  # сколько курсов нужно пройти до каждого
	for a, b in prerequisites:
	    graph[b].append(a)
	    indeg[a] += 1

	q = deque(i for i in range(numCourses) if indeg[i] == 0)
	order = []
	while q:
	    x = q.popleft()
	    order.append(x)
	    for y in graph[x]:
	        indeg[y] -= 1
	        if indeg[y] == 0:                 # все требования для y выполнены
	            q.append(y)
	return order if len(order) == numCourses else []   # не все вершины попали в порядок — значит цикл

	# олимпиадный вариант очереди: q = [i for i in range(numCourses) if indeg[i] == 0]; head = 0
	# while head < len(q): x = q[head]; head += 1; ...   (q.append остаётся как есть)
	```

	- [Course Schedule II](https://leetcode.com/problems/course-schedule-ii/) · Medium
	- [Find Eventual Safe States](https://leetcode.com/problems/find-eventual-safe-states/) · Medium · нюанс: рёбра разворачиваем, стартуем с вершин без исходящих рёбер

### Система непересекающихся множеств

- **Суть:** храним для каждой вершины ссылку на родителя в её группе. `find` поднимается до корня и возвращает представителя группы, `union` склеивает две группы, подвешивая один корень к другому. Сжатие путей в `find` делает операции почти константными.
- **Когда:**
	- рёбра приходят по одному, нужно быстро знать, в одной ли группе две вершины
	- нужно посчитать число групп после объединений
	- нужно найти ребро, которое замыкает цикл в неориентированном графе
- **Сложность:** T: почти O(α(n)) на операцию, на практике считай O(1) · S: O(n)
- **Шаблон:**
	```python
	# Пример: Redundant Connection. Дерево плюс одно лишнее ребро, нужно найти это ребро
	parent = list(range(len(edges) + 1))      # вершины от 1 до n, изначально каждая сама себе корень

	def find(x):
	    while parent[x] != x:
	        parent[x] = parent[parent[x]]     # сжатие пути: подтягиваем к дедушке
	        x = parent[x]
	    return x

	for a, b in edges:
	    ra, rb = find(a), find(b)
	    if ra == rb:                          # уже в одной группе, ребро замыкает цикл
	        return [a, b]
	    parent[ra] = rb                       # склеиваем группы
	```
- **Задачи:**

	- [Number of Provinces](https://leetcode.com/problems/number-of-provinces/) · Medium · нюанс: считаем число групп, в начале `n`, на каждом успешном `union` уменьшаем на 1
	- [Graph Valid Tree](https://leetcode.com/problems/graph-valid-tree/) · Medium · 🔒 premium · нюанс: дерево, если рёбер ровно `n - 1` и ни одно не замкнуло цикл

### Алгоритм Дейкстры

- **Суть:** кратчайшие пути от одной вершины, когда у рёбер есть неотрицательные веса. Держим кучу пар «расстояние, вершина». Достаём вершину с наименьшим расстоянием: оно уже окончательное. Обновляем расстояния до её соседей и кладём их в кучу. Это обход в ширину, где очередь заменена приоритетной.
- **Схема:** граф с весами, старт в `A`.
	```mermaid
	flowchart LR
	    A((A)) -- 4 --> B((B))
	    A -- 1 --> C((C))
	    C -- 2 --> B
	    B -- 1 --> D((D))
	    C -- 5 --> D
	```
	Из кучи по очереди достаём `A` (0), `C` (1), `B` (3, а не 4: через `C` короче), `D` (4). Кратчайший путь до `D` — `A → C → B → D`. Расстояние до `B` в куче сначала было 4, потом появилось 3, старая запись 4 при извлечении пропускается.
- **Когда:**
	- рёбра имеют разные веса (время, цена, расстояние), все веса неотрицательные
	- нужно минимальное время, цена, усилие от одной вершины до остальных или до цели
	- с отрицательными весами Дейкстра неприменима, нужен алгоритм Беллмана — Форда
- **Сложность:** T: O(E log V) · S: O(V + E)
- **Шаблон:**
	```python
	# Пример: Network Delay Time. times[i] = [u, v, w], сигнал идёт из k, сколько времени до всех узлов?
	import heapq

	graph = [[] for _ in range(n + 1)]         # вершины 1..n (на LeetCode можно defaultdict(list))
	for u, v, w in times:
	    graph[u].append((v, w))

	dist = {}                                 # окончательные расстояния
	heap = [(0, k)]                           # (расстояние, вершина)
	while heap:
	    d, u = heapq.heappop(heap)
	    if u in dist:                         # уже обработана с меньшим расстоянием
	        continue
	    dist[u] = d
	    for v, w in graph[u]:
	        if v not in dist:
	            heapq.heappush(heap, (d + w, v))

	return max(dist.values()) if len(dist) == n else -1   # если дошли не до всех, то -1

	# олимпиадный вариант кучи: h = MinHeap() из [[Структуры данных#Куча]]
	# h.push((0, k)); while len(h): d, u = h.pop(); ...; h.push((d + w, v))
	```
- **Задачи:**
	- [Network Delay Time](https://leetcode.com/problems/network-delay-time/) · Medium
	- [Path with Maximum Probability](https://leetcode.com/problems/path-with-maximum-probability/) · Medium · нюанс: ищем максимум произведения вместо минимума суммы, в куче кладём `-вероятность`
	- [Path With Minimum Effort](https://leetcode.com/problems/path-with-minimum-effort/) · Medium · нюанс: сетка, «длина» пути — максимальная разница на одном шаге: вместо `d + w` берём `max(d, w)`
	- [Cheapest Flights Within K Stops](https://leetcode.com/problems/cheapest-flights-within-k-stops/) · Medium · нюанс: ограничение на число пересадок, поэтому в куче хранят ещё и число шагов, а «вершина обработана» уже не годится

### Алгоритм Беллмана — Форда

- **Суть:** кратчайшие пути, когда у рёбер могут быть отрицательные веса или когда число рёбер в пути ограничено. Расстояния до всех вершин улучшаем, перебирая все рёбра. После `i` раундов известны кратчайшие пути, в которых не больше `i` рёбер. Всего нужно не больше `V - 1` раундов, и если вершины ещё улучшаются на следующем раунде, в графе есть цикл с отрицательным весом.
- **Когда:**
	- есть отрицательные веса, Дейкстра неприменима
	- в условии «не больше k рёбер», «не больше k пересадок»
	- нужно обнаружить отрицательный цикл
- **Сложность:** T: O(V × E) · S: O(V)
- **Шаблон:**
	```python
	# Пример: Cheapest Flights Within K Stops. Самый дешёвый путь из src в dst не больше чем с k пересадками
	INF = float("inf")
	dist = [INF] * n
	dist[src] = 0
	for _ in range(k + 1):                    # k пересадок — это не больше k + 1 перелётов
	    nxt = dist[:]                         # обновляем по копии, иначе за раунд пройдём больше одного ребра
	    for u, v, w in flights:
	        if dist[u] + w < nxt[v]:
	            nxt[v] = dist[u] + w
	    dist = nxt
	return -1 if dist[dst] == INF else dist[dst]
	```
- **Задачи:**
	- [Cheapest Flights Within K Stops](https://leetcode.com/problems/cheapest-flights-within-k-stops/) · Medium
	- [Network Delay Time](https://leetcode.com/problems/network-delay-time/) · Medium · нюанс: отрицательных весов нет, поэтому Дейкстра быстрее, но Беллман — Форд тоже проходит
	- [Path with Maximum Probability](https://leetcode.com/problems/path-with-maximum-probability/) · Medium · нюанс: ищем максимум произведения вместо минимума суммы

### Минимальное остовное дерево

- **Суть:** выбрать из рёбер связного графа такие, чтобы все вершины были связаны и общий вес был минимальным. Алгоритм Краскала: сортируем рёбра по весу и по одному добавляем в ответ, если ребро соединяет две разные группы. Проверку делает система непересекающихся множеств.
- **Когда:**
	- нужно соединить все точки или узлы с минимальной суммарной стоимостью
	- в условии «минимальная стоимость, чтобы всё было связано»
	- нужно найти «лишние» рёбра, без которых граф остаётся связным
- **Сложность:** T: O(E log E) · S: O(V)
- **Шаблон:**
	```python
	# Пример: Min Cost to Connect All Points. Стоимость ребра — манхэттенское расстояние между точками
	n = len(points)
	edges = []
	for i in range(n):
	    for j in range(i + 1, n):
	        w = abs(points[i][0] - points[j][0]) + abs(points[i][1] - points[j][1])
	        edges.append((w, i, j))
	edges.sort()                              # самые дешёвые рёбра идут первыми

	parent = list(range(n))

	def find(x):
	    while parent[x] != x:
	        parent[x] = parent[parent[x]]
	        x = parent[x]
	    return x

	total = used = 0
	for w, a, b in edges:
	    ra, rb = find(a), find(b)
	    if ra != rb:                          # ребро соединяет разные группы, берём
	        parent[ra] = rb
	        total += w
	        used += 1
	        if used == n - 1:                 # остов из n вершин имеет n - 1 ребро
	            break
	return total
	```
- **Задачи:**
	- [Min Cost to Connect All Points](https://leetcode.com/problems/min-cost-to-connect-all-points/) · Medium
	- [Connecting Cities With Minimum Cost](https://leetcode.com/problems/connecting-cities-with-minimum-cost/) · Medium · 🔒 premium · нюанс: рёбра уже заданы; если `used < n - 1`, граф не связан, возвращаем `-1`
	- [Optimize Water Distribution in a Village](https://leetcode.com/problems/optimize-water-distribution-in-a-village/) · Hard · 🔒 premium · нюанс: колодец в доме — ребро от фиктивной вершины 0 с ценой колодца

### Двудольность

- **Суть:** раскрашиваем вершины в два цвета так, чтобы у каждого ребра концы были разных цветов. Обходом (в ширину или в глубину) красим соседа в противоположный цвет. Если встретили соседа того же цвета, раскраски нет. Граф с циклом нечётной длины двудольным быть не может.
- **Когда:**
	- нужно разделить элементы на две группы так, чтобы «враги» не оказались вместе
	- в условии «две команды», «нельзя вместе»
	- нужно проверить, что в графе нет цикла нечётной длины
- **Сложность:** T: O(V + E) · S: O(V)
- **Шаблон:**
	```python
	# Пример: Is Graph Bipartite? graph[u] — соседи вершины u
	from collections import deque

	color = {}
	for start in range(len(graph)):           # граф может быть несвязным, запускаем из каждой компоненты
	    if start in color:
	        continue
	    color[start] = 0
	    q = deque([start])
	    while q:
	        u = q.popleft()
	        for v in graph[u]:
	            if v not in color:
	                color[v] = 1 - color[u]   # красим в противоположный цвет
	                q.append(v)
	            elif color[v] == color[u]:    # сосед того же цвета, раскраски нет
	                return False
	return True

	# олимпиадный вариант очереди: q = [start]; head = 0
	# while head < len(q): u = q[head]; head += 1; ...   (q.append остаётся как есть)
	```

## Динамическое программирование

Задача разбивается на подзадачи, подзадачи повторяются, поэтому ответ на каждую считаем один раз и запоминаем. Признак: нужно найти количество способов, минимум или максимум, или ответить «можно ли», а полный перебор слишком долгий. Перед кодом ответь на пять вопросов, ответы на них и есть решение:
1. **Состояние:** что значит `dp[i]` (или `dp[i][j]`), одной фразой, например «лучший ответ на первых `i` элементах».
2. **Переход:** как `dp[i]` выражается через меньшие состояния.
3. **База:** чему равны самые маленькие состояния (пустая строка, ноль монет).
4. **Порядок:** в каком порядке считать, чтобы нужные состояния уже были готовы.
5. **Ответ:** какая клетка таблицы является ответом (не всегда последняя).

Есть два способа записи. **Снизу вверх**: заполняем таблицу циклами от базы. **Сверху вниз**: пишем рекурсию и запоминаем результаты в своём словаре `memo`. Результат одинаковый, рекурсия проще, когда порядок заполнения неочевиден.

> [!tip] Как выбрать паттерн
> - Ответ для `i` зависит от нескольких предыдущих («или взять, или пропустить», «пришёл из `i-1` или `i-2`») → **линейная ДП**
> - Есть набор предметов и лимит (сумма, вес, количество), каждый берут или не берут → **рюкзак**
> - Сетка, ходы только вправо и вниз → **ДП по сетке**
> - Даны две строки или два массива, нужно их сопоставить (общая подпоследовательность, расстояние редактирования) → **ДП на двух последовательностях**
> - Одна последовательность, для каждого `i` нужно просмотреть все `j < i` → **ДП на подпоследовательностях**
> - Идём по дням или шагам, и у процесса есть режим (держу или не держу, отдых после продажи) → **ДП с состояниями**
> - Состояния — это позиции или значения, порядок заполнения неочевиден, рекурсия записывается проще → **рекурсия с запоминанием**
> - Нужен лучший выбор на каждом шаге без возвратов, и можно доказать, что локальный лучший даёт глобальный → это жадный алгоритм, ДП не нужна

### Линейная ДП

- **Суть:** идём по массиву слева направо, `dp[i]` — ответ для первых `i` элементов. Он считается из одного-двух предыдущих значений. Поэтому всю таблицу хранить не нужно: хватает двух переменных.
- **Когда:**
	- на каждом шаге есть выбор вида «взять элемент или пропустить», «шагнуть на 1 или на 2»
	- соседние элементы нельзя использовать вместе (House Robber)
	- нужно посчитать число способов дойти до конца
- **Сложность:** T: O(n) · S: O(1) со сжатием, O(n) с таблицей
- **Шаблон:**
	```python
	# Пример: House Robber. Нельзя грабить соседние дома, нужна максимальная сумма
	# dp[i] = max(dp[i - 1], dp[i - 2] + nums[i]): пропускаем дом или грабим его и берём лучшее до предыдущего
	prev2 = prev1 = 0                         # dp[i - 2] и dp[i - 1]
	for x in nums:
	    prev2, prev1 = prev1, max(prev1, prev2 + x)
	return prev1
	```
- **Задачи:**
	- [Climbing Stairs](https://leetcode.com/problems/climbing-stairs/) · Easy · нюанс: `dp[i] = dp[i - 1] + dp[i - 2]`, это числа Фибоначчи
	- [Min Cost Climbing Stairs](https://leetcode.com/problems/min-cost-climbing-stairs/) · Easy · нюанс: минимум вместо суммы, ответ — `min(dp[n - 1], dp[n - 2])`
	- [House Robber](https://leetcode.com/problems/house-robber/) · Medium
	- [House Robber II](https://leetcode.com/problems/house-robber-ii/) · Medium · нюанс: дома по кругу, значит дважды запускаем обычный вариант: без первого дома и без последнего
	- [Decode Ways](https://leetcode.com/problems/decode-ways/) · Medium · нюанс: `dp[i]` прибавляет `dp[i - 1]`, если последняя цифра не `0`, и `dp[i - 2]`, если последние две цифры дают число от 10 до 26
	- [Maximum Subarray](https://leetcode.com/problems/maximum-subarray/) · Medium · нюанс: `dp[i] = max(nums[i], dp[i - 1] + nums[i])`, ответ — максимум по всем `i`

### Рюкзак

- **Суть:** есть предметы и лимит (вес, сумма, число монет). `dp[s]` хранит лучший ответ (или «достижимо ли») для лимита `s`. Для каждого предмета обновляем таблицу. Если предмет можно брать только один раз (0/1), сумму идём в обратную сторону, чтобы не использовать предмет дважды. Если предмет можно брать сколько угодно, идём вперёд.
- **Когда:**
	- в условии «набрать сумму», «разбить на две равные части», «минимум монет»
	- есть набор чисел и целевое значение
	- нужно посчитать число способов набрать сумму
- **Сложность:** T: O(n × S), где S — целевая сумма · S: O(S)
- **Шаблон:**
	```python
	# Пример: Coin Change. Минимум монет на сумму amount, монет каждого вида сколько угодно
	INF = float("inf")
	dp = [0] + [INF] * amount                 # dp[a] — минимум монет на сумму a, на сумму 0 нужно 0 монет
	for a in range(1, amount + 1):
	    for c in coins:
	        if c <= a and dp[a - c] + 1 < dp[a]:
	            dp[a] = dp[a - c] + 1         # берём монету c и добавляем лучшее для остатка
	return dp[amount] if dp[amount] != INF else -1

	# вариант 0/1: каждый предмет только один раз. Пример: Partition Equal Subset Sum
	# dp = [True] + [False] * target
	# for x in nums:
	#     for s in range(target, x - 1, -1):  # назад, иначе x засчитается несколько раз
	#         dp[s] = dp[s] or dp[s - x]
	```
- **Задачи:**

### ДП по сетке

- **Суть:** `dp[r][c]` — ответ для клетки `(r, c)`. Клетка получает ответ из соседей, откуда в неё можно прийти (сверху и слева, если ходы вправо и вниз). Заполняем строка за строкой.
- **Схема:** число путей из левого верхнего угла в клетку при ходах вправо и вниз.
	| 1 | 1 | 1 |
	|---|---|---|
	| 1 | 2 | 3 |
	| 1 | 3 | 6 |
	Первая строка и первый столбец — по одному пути. Остальные клетки: `dp[r][c] = dp[r-1][c] + dp[r][c-1]`, например `6 = 3 + 3`. Ответ — правая нижняя клетка.
- **Когда:**
	- сетка, ходы разрешены в одну-две стороны (вправо и вниз)
	- нужно посчитать число путей или минимальную цену пути
	- в клетках есть препятствия или веса
- **Сложность:** T: O(строки × столбцы) · S: O(строки × столбцы), можно сжать до одной строки
- **Шаблон:**
	```python
	# Пример: Minimum Path Sum. Путь из левого верхнего угла в правый нижний, шаги вправо и вниз, минимальная сумма
	rows, cols = len(grid), len(grid[0])
	dp = [[0] * cols for _ in range(rows)]
	for r in range(rows):
	    for c in range(cols):
	        if r == 0 and c == 0:
	            dp[r][c] = grid[0][0]
	        elif r == 0:
	            dp[r][c] = dp[r][c - 1] + grid[r][c]      # в первую строку можно прийти только слева
	        elif c == 0:
	            dp[r][c] = dp[r - 1][c] + grid[r][c]      # в первый столбец только сверху
	        else:
	            dp[r][c] = min(dp[r - 1][c], dp[r][c - 1]) + grid[r][c]
	return dp[rows - 1][cols - 1]
	```
- **Задачи:**

### ДП на двух последовательностях

- **Суть:** `dp[i][j]` — ответ для первых `i` символов первой строки и первых `j` символов второй. Смотрим на последние символы. Если они совпали, продолжаем оба префикса. Если нет, отбрасываем символ из первой строки, из второй или заменяем.
- **Когда:**
	- даны две строки или два массива, нужно найти общую часть или расстояние между ними
	- в условии «общая подпоследовательность», «преобразовать одну в другую», «сколько операций»
	- слово «подпоследовательность» (не обязательно подряд) вместо «подстрока» (подряд)
- **Сложность:** T: O(n × m) · S: O(n × m), можно сжать до O(min(n, m))
- **Шаблон:**
	```python
	# Пример: Longest Common Subsequence. "abcde" и "ace" → 3 ("ace")
	m, n = len(text1), len(text2)
	dp = [[0] * (n + 1) for _ in range(m + 1)]        # нулевая строка и столбец — пустой префикс
	for i in range(1, m + 1):
	    for j in range(1, n + 1):
	        if text1[i - 1] == text2[j - 1]:
	            dp[i][j] = dp[i - 1][j - 1] + 1       # последние символы совпали, берём их оба
	        else:
	            dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])  # отбрасываем символ из одной из строк
	return dp[m][n]
	```
- **Задачи:**
	- [Longest Common Subsequence](https://leetcode.com/problems/longest-common-subsequence/) · Medium
	- [Edit Distance](https://leetcode.com/problems/edit-distance/) · Medium · нюанс: при несовпадении `1 + min` из трёх: вставка `dp[i][j - 1]`, удаление `dp[i - 1][j]`, замена `dp[i - 1][j - 1]`; база: `dp[i][0] = i`, `dp[0][j] = j`
	- [Delete Operation for Two Strings](https://leetcode.com/problems/delete-operation-for-two-strings/) · Medium · нюанс: ответ `m + n - 2 × LCS`

### ДП на подпоследовательностях

- **Суть:** `dp[i]` — ответ для последовательности, которая заканчивается ровно на элементе `i`. Чтобы его найти, просматриваем все предыдущие `j < i`, которые можно присоединить к `i`. Ответ — максимум по всем `i`, а не последний элемент.
- **Когда:**
	- нужна самая длинная подпоследовательность с условием между соседними элементами (возрастание, делимость)
	- решение в `i` зависит от всех предыдущих элементов, а не от двух ближайших
	- слово можно собрать из кусков слов словаря (проверка всех разбиений)
- **Сложность:** T: O(n²) · S: O(n)
- **Шаблон:**
	```python
	# Пример: Longest Increasing Subsequence. [10, 9, 2, 5, 3, 7, 101, 18] → 4 (2, 3, 7, 101)
	dp = [1] * len(nums)                      # dp[i] — длина лучшей цепочки, заканчивающейся на nums[i]
	for i in range(len(nums)):
	    for j in range(i):
	        if nums[j] < nums[i]:             # nums[i] можно дописать в конец цепочки, которая кончается на nums[j]
	            dp[i] = max(dp[i], dp[j] + 1)
	return max(dp)                            # цепочка может закончиться где угодно

	# быстрее, O(n log n): держим список tails, где tails[k] — наименьшее окончание цепочки длины k + 1,
	# каждое число ставим через bisect_left на своё место
	```
- **Задачи:**

	- [Number of Longest Increasing Subsequence](https://leetcode.com/problems/number-of-longest-increasing-subsequence/) · Medium · нюанс: рядом с длиной храним число цепочек такой длины

### ДП с состояниями

- **Суть:** в каждый момент процесс находится в одном из нескольких состояний (держу акцию, только что продал, свободен). Для каждого состояния храним лучший ответ и на каждом шаге пересчитываем все состояния по правилам переходов. Переходы удобно сначала нарисовать стрелками.
- **Когда:**
	- шаги идут по дням или позициям, а действия зависят от режима (после продажи день отдыха, ограничено число сделок)
	- одной переменной `dp[i]` не хватает, нужно знать, в каком режиме мы пришли
	- в условии «кулдаун», «комиссия», «не более k сделок»
- **Сложность:** T: O(n × число состояний) · S: O(число состояний)
- **Шаблон:**
	```python
	# Пример: Best Time to Buy and Sell Stock with Cooldown. После продажи день отдыха, акций больше одной не держим
	hold, sold, rest = -prices[0], 0, 0
	# hold — максимум денег, если сейчас держим акцию
	# sold — максимум денег, если акцию продали сегодня
	# rest — максимум денег, если акции нет и мы не продавали сегодня
	for p in prices[1:]:
	    hold, sold, rest = (
	        max(hold, rest - p),              # продолжаем держать или покупаем (покупать можно только из rest)
	        hold + p,                         # продаём то, что держали
	        max(rest, sold),                  # отдыхаем: из rest остаёмся, из sold выходим на следующий день
	    )
	return max(sold, rest)
	```
- **Задачи:**
	- [Best Time to Buy and Sell Stock with Cooldown](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-cooldown/) · Medium
	- [Best Time to Buy and Sell Stock with Transaction Fee](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-transaction-fee/) · Medium · нюанс: два состояния (держу, не держу), комиссию вычитаем при продаже
	- [Best Time to Buy and Sell Stock II](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/) · Medium · нюанс: те же два состояния без комиссии; решается и жадно, суммой всех подъёмов
	- [Best Time to Buy and Sell Stock IV](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-iv/) · Hard · нюанс: состояние растёт на число сделок, `dp[j][держу или нет]` для `j` от 1 до `k`

### Рекурсия с запоминанием

- **Суть:** пишем рекурсию, которая отвечает на вопрос для данного состояния, и запоминаем ответ на каждое состояние. Повторный вызов вернёт готовый результат, а не пересчитает. Это та же ДП, но писать таблицу и думать о порядке заполнения не нужно. Запоминать можно только функцию без побочных эффектов, и состояние должно быть хешируемым (числа, кортежи).
- **Когда:**
	- переход очевиден, а порядок заполнения таблицы нет (граф без циклов, сетка с произвольными ходами)
	- достижимы не все состояния, и таблица из всех комбинаций была бы лишней
	- нужно быстро получить рабочее решение, а потом при необходимости переписать в таблицу
- **Сложность:** T: O(число состояний × число переходов) · S: O(число состояний) плюс глубина рекурсии
- **Шаблон:**
	```python
	# Пример: Longest Increasing Path in a Matrix. Ходим вверх-вниз-влево-вправо по строго возрастающим значениям
	rows, cols = len(matrix), len(matrix[0])
	memo = {}                                 # (r, c) → уже посчитанный ответ

	def go(r, c):                             # длина лучшего пути, который начинается в клетке (r, c)
	    if (r, c) in memo:
	        return memo[(r, c)]
	    best = 1
	    for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
	        nr, nc = r + dr, c + dc
	        if 0 <= nr < rows and 0 <= nc < cols and matrix[nr][nc] > matrix[r][c]:
	            best = max(best, 1 + go(nr, nc))
	    memo[(r, c)] = best
	    return best                           # циклов нет: значения только растут, поэтому visited не нужен

	return max(go(r, c) for r in range(rows) for c in range(cols))
	```
- **Задачи:**
	- [Longest Increasing Path in a Matrix](https://leetcode.com/problems/longest-increasing-path-in-a-matrix/) · Hard
	- [Climbing Stairs](https://leetcode.com/problems/climbing-stairs/) · Easy · нюанс: первое упражнение на запоминание в `memo`: `go(n) = go(n - 1) + go(n - 2)`
	- [Word Break](https://leetcode.com/problems/word-break/) · Medium · нюанс: `go(start)` — можно ли разбить суффикс с позиции `start`
	- [Target Sum](https://leetcode.com/problems/target-sum/) · Medium · нюанс: состояние — пара `(индекс, текущая сумма)`
	- [Out of Boundary Paths](https://leetcode.com/problems/out-of-boundary-paths/) · Medium · нюанс: состояние — тройка `(строка, столбец, оставшиеся ходы)`
