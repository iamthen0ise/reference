title: Агрегация
---

Агрегатные функции (`count`, `sum`, `avg`, `min`, `max`) сворачивают много строк в одно значение.

## GROUP BY и HAVING

`WHERE` фильтрует строки до группировки, `HAVING` фильтрует группы после неё. Условие по агрегату (`count(*) > 2`) в `WHERE` писать нельзя: на этом шаге групп ещё нет.

```sql
SELECT customer_id, count(*) AS n, sum(amount) AS s
FROM orders
GROUP BY customer_id
HAVING count(*) > 2;   -- клиенты 1, 2, 4
```

Всё, что есть в `SELECT` и не завёрнуто в агрегатную функцию, должно быть перечислено в `GROUP BY`. Исключение: столбцы, однозначно определяемые первичным ключом, который указан в `GROUP BY` (`GROUP BY c.id` разрешает выбирать `c.name`). Я всё равно перечисляю оба столбца: так запрос переносимее между СУБД (системами управления базами данных: PostgreSQL, MySQL и другими).

## COUNT(*), COUNT(col), COUNT(DISTINCT col)

```sql
SELECT count(*) AS all_rows,                       -- 9: все строки
       count(amount) AS non_null,                  -- 8: только строки, где amount не NULL
       count(DISTINCT customer_id) AS customers    -- 3: число разных клиентов, NULL не считается
FROM orders;
```

Ловушка: `count(col)` пропускает `NULL`, а `count(*)` считает строки целиком. После `LEFT JOIN` считай `count(o.id)`, а не `count(*)`: для клиента без заказов `count(*)` вернёт 1 (одна строка, в которой справа `NULL`), а `count(o.id)` вернёт 0, как и должно быть.

## Условная агрегация и FILTER

Условие: по каждому клиенту число заказов по статусам и сумма оплаченных. Такую раскладку называют pivot (сводная таблица: значения статуса превращаются в столбцы).

```sql
SELECT customer_id,
       count(*) FILTER (WHERE status = 'paid')      AS paid,
       count(*) FILTER (WHERE status = 'new')       AS new,
       count(*) FILTER (WHERE status = 'cancelled') AS cancelled,
       sum(amount) FILTER (WHERE status = 'paid')   AS paid_sum
FROM orders
GROUP BY customer_id
ORDER BY customer_id;
-- порядок значений: paid / new / cancelled / paid_sum
-- клиент 1: 2 / 0 / 1 / 150.00,  клиент 2: 2 / 1 / 0 / 320.00,  клиент 4: 2 / 1 / 0 / 450.00
```

`FILTER (WHERE ...)` после агрегата говорит: учитывай только строки, подходящие под условие. Это один проход по таблице вместо трёх отдельных `GROUP BY`, склеенных через `JOIN`.

Классический вариант без `FILTER` — `sum(CASE WHEN status = 'paid' THEN amount END)`. Результат тот же, он работает в любой СУБД, но выглядит шумнее. Для `count` через `CASE` пиши `THEN 1` без `ELSE 0`: иначе `count` посчитает и нули, ведь он пропускает только `NULL`.

## NULL в агрегатах

- `sum`, `avg`, `min`, `max` игнорируют `NULL`.
- `sum` по пустому набору строк возвращает `NULL`, а не 0.
- `avg(col)` делит на число ненулевых значений, а не на число строк.

```sql
SELECT sum(amount) FROM orders WHERE status = 'refunded';                 -- NULL
SELECT coalesce(sum(amount), 0) FROM orders WHERE status = 'refunded';    -- 0

-- у Dan три заказа, у одного amount равен NULL
SELECT avg(amount)               AS avg_skip_null,   -- 225: (300 + 150) / 2
       sum(amount) / count(*)    AS sum_over_all,    -- 150: (300 + 150) / 3
       avg(coalesce(amount, 0))  AS avg_zero         -- 150
FROM orders WHERE customer_id = 4;
```

`coalesce(x, 0)` подставляет 0 вместо `NULL`. Что считать «средним заказом», когда есть заказ без суммы, — вопрос к бизнесу, и решение должно быть осознанным. `coalesce` ставь снаружи агрегата, если нужен результат для пустой группы. Внутрь агрегата его ставь, если `NULL` по смыслу означает ноль.

## Доля и целочисленное деление

Условие: процент оплаченных заказов.

```sql
SELECT count(*) FILTER (WHERE status = 'paid') / count(*)                     AS bad,    -- 0
       round(100.0 * count(*) FILTER (WHERE status = 'paid') / count(*), 1)   AS pct     -- 66.7
FROM orders;
```

`count` возвращает `bigint` (целое число), и `6 / 9` для целых — целочисленное деление, то есть 0. Домножь на `100.0` или приведи значение к `numeric` до деления. Порядок важен: выражение `count(*) FILTER (...) / count(*) * 100.0` даст 0, потому что деление уже выполнилось над целыми.

## ROLLUP, CUBE и GROUPING SETS: промежуточные итоги

Условие: выручка по клиентам и месяцам, под каждым клиентом — его итог, а в самом конце — общий итог. Обычный `GROUP BY` даёт только одну детализацию. Можно склеить три запроса через `UNION ALL`, но тогда таблица читается три раза. `ROLLUP` делает это за один проход.

```sql
WITH p AS (
    SELECT customer_id, date_trunc('month', created_at)::date AS month, amount
    FROM orders
    WHERE status = 'paid'
)
SELECT customer_id, month, sum(amount) AS revenue, grouping(customer_id, month) AS lvl
FROM p
GROUP BY ROLLUP (customer_id, month)
ORDER BY customer_id NULLS LAST, month NULLS LAST;
```

| customer_id | month | revenue | lvl |
| --- | --- | --- | --- |
| 1 | 2025-01-01 | 150.00 | 0 |
| 1 | NULL | 150.00 | 1 |
| 2 | 2025-01-01 | 200.00 | 0 |
| 2 | 2025-02-01 | 120.00 | 0 |
| 2 | NULL | 320.00 | 1 |
| 4 | 2025-02-01 | 300.00 | 0 |
| 4 | 2025-04-01 | 150.00 | 0 |
| 4 | NULL | 450.00 | 1 |
| NULL | NULL | 920.00 | 3 |

`GROUP BY ROLLUP (customer_id, month)` — сокращение для `GROUPING SETS ((customer_id, month), (customer_id), ())`: сначала группировка по обоим столбцам, потом только по клиенту, потом по всей таблице. В строках итогов столбец, по которому не группировали, заполнен `NULL`. `CUBE (customer_id, month)` строит все сочетания, то есть добавляет ещё итоги по каждому месяцу без разбивки по клиентам; на наших данных вышло бы 12 строк вместо 9. А в `GROUPING SETS` нужные наборы перечисляют вручную.

Ловушка — отличить `NULL`, который означает «это строка итога», от `NULL`, который был в данных. Для этого есть функция `grouping(...)`. Она возвращает битовую маску, где единица значит «этот столбец в данной строке свёрнут». Здесь `lvl = 0` — обычная строка, `1` — итог по клиенту (свёрнут месяц), `3` — общий итог (свёрнуты оба столбца). По ней же удобно подписывать итоги: `CASE grouping(month) WHEN 1 THEN 'итого' END`.
