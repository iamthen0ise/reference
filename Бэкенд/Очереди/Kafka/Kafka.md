Конспект к собеседованию по Kafka: от устройства журнала до рецептов с реальным выводом. Слои те же, что в [[PostgreSQL]]: суть, техника и рецепты, бизнес-кейс, что спросят дальше. Выводы в блоках «Вывод» получены запуском на одиночном брокере Apache Kafka 4.1.0 (режим KRaft, без ZooKeeper), клиентский код — на Python 3.13: основной клиент `aiokafka` 0.15.0, там, где он чего-то не умеет (кооперативная ребалансировка, транзакции с метаданными группы, выбор партиционера), — `confluent-kafka` 2.16.2 (обёртка над библиотекой librdkafka 2.16.0). Консольные скрипты — из образа `apache/kafka`.

## Суть за две минуты

Kafka — это распределённый **журнал** (commit log): сообщения дописываются в конец и не удаляются после чтения, а живут, пока не истечёт срок хранения или не наступит сжатие по ключу. Поэтому сообщение можно прочитать повторно, а читателей у одного потока может быть сколько угодно: каждый помнит собственную позицию.

- **Топик** (topic) — именованный поток, например `orders.order.paid`. Он делится на **партиции** (partition): каждая партиция — отдельный упорядоченный журнал. Порядок гарантирован только внутри партиции, а партицию для сообщения выбирает ключ (хеш ключа делится на число партиций), поэтому все события одного заказа должны идти с одним ключом.
- **Offset** — порядковый номер сообщения в партиции, с нуля. Зафиксированный offset группы — это «следующее сообщение к чтению»: последнее обработанное плюс один.
- **Consumer group** (группа консьюмеров) — набор процессов с общим именем группы. Каждую партицию читает ровно один процесс группы, поэтому параллелизм чтения упирается в число партиций. Позиции чтения группа хранит в служебном топике `__consumer_offsets`.
- **Реплики.** У каждой партиции есть лидер (принимает записи и отдаёт чтение) и последователи, которые копируют журнал. **ISR** (In-Sync Replicas) — реплики, не отставшие от лидера. Продюсер с `acks=all` получает подтверждение, когда запись есть на всех репликах из ISR, а `min.insync.replicas` задаёт нижнюю границу ISR, при которой запись ещё принимается. Для важных данных стандарт — `acks=all`, replication factor (фактор репликации, число копий) 3 и `min.insync.replicas=2`.
- **KRaft** (Kafka Raft) — встроенный протокол, которым брокеры-контроллеры хранят метаданные кластера и выбирают лидеров. С Kafka 4.0 ZooKeeper убран совсем, а на одиночном брокере из примеров один процесс играет обе роли (`process.roles=broker,controller`).

Из этого устройства вытекают все остальные темы страниц: доставка «минимум один раз» (из-за повторной выдачи после сбоя или ребаланса), идемпотентность обработчика, outbox для записи в Kafka вместе с базой, retry-топики и DLQ для сообщений, которые не удаётся обработать.

## Как читать выводы

Каждый рецепт построен по одной схеме: задача, код, вывод, грабли. Вывод снят реальным запуском, не по памяти; где вывод зависит от времени (пропускная способность, секунды на таймерах), числа ориентировочные и меняются от запуска к запуску, а порядок событий и логика остаются прежними. Топики в примерах создаются заранее, потому что автосоздание топика при первой отправке даёт топик с партициями и сроками хранения по умолчанию, см. [[Эксплуатация Kafka и CLI]].
