title: Деревья
---

Бинарное дерево: у каждого узла есть значение и до двух детей, `left` и `right`. Почти все задачи решаются рекурсивным обходом, поэтому сначала реши, в какую сторону течёт информация. Либо мы несём её вниз от корня (глубина, сумма на пути, границы), либо собираем наверх из детей (высота, размер, ответ для поддерева). Третий случай — важны уровни: тогда идём не вглубь, а вширь.

> [!tip] Как выбрать паттерн
> - Ответ для узла зависит от того, что было на пути от корня (глубина, сумма, максимум, границы, путь) → **обход сверху вниз**
> - Ответ для узла зависит от ответов для его детей (высота, баланс, диаметр, общий предок) → **обход снизу вверх**
> - Нужны уровни, ближайший к корню узел или кратчайший путь по рёбрам → **обход по уровням**
> - Дерево поиска (слева меньше, справа больше), нужно искать, вставлять, удалять → **дерево поиска**
> - В условии названы прямой, симметричный или обратный порядок, нужен `k`-й элемент по порядку → **порядки обхода**
> - Даны обходы или массив и нужно собрать дерево, или нужно превратить дерево в строку и обратно → **построение дерева**
> - Нужны оба направления сразу: параметр вниз, результат вверх → **обход снизу вверх** с дополнительным аргументом, шаблон тот же

## Обход сверху вниз

- **Суть:** рекурсивная функция получает аргументы от родителя, дополняет их данными текущего узла и передаёт детям. К моменту, когда мы дошли до узла, всё нужное о пути от корня уже лежит в аргументах. Результат либо накапливается в общей переменной, либо собирается из возвращаемых значений.
- **Когда:**
	- в условии есть «на пути от корня», «предки», «от корня до листа»
	- нужно знать глубину, накопленную сумму или максимум на пути
	- у поддерева есть ограничение, пришедшее сверху (например, границы значений в дереве поиска)
- **Сложность:** T: O(n) · S: O(h), где h — высота дерева (в худшем случае n)
- **Шаблон:**
	```python
	# Пример: Count Good Nodes in Binary Tree. Узел хороший, если на пути от корня нет значения больше него
	def go(node, max_so_far):                 # max_so_far — то, что мы принесли сверху
	    if not node:
	        return 0
	    count = 1 if node.val >= max_so_far else 0
	    max_so_far = max(max_so_far, node.val)           # обновили для детей
	    return count + go(node.left, max_so_far) + go(node.right, max_so_far)

	return go(root, float("-inf"))
	```

	- [Path Sum](https://leetcode.com/problems/path-sum/) · Easy · нюанс: передаём вниз остаток суммы `target - node.val`, на листе сравниваем остаток с нулём
	- [Count Good Nodes in Binary Tree](https://leetcode.com/problems/count-good-nodes-in-binary-tree/) · Medium
	- [Validate Binary Search Tree](https://leetcode.com/problems/validate-binary-search-tree/) · Medium · нюанс: вниз идёт пара границ `(low, high)`, для левого ребёнка `high = node.val`, для правого `low = node.val`

## Обход снизу вверх

- **Суть:** сначала рекурсивно получаем ответы от обоих детей, потом считаем ответ для текущего узла из того, что они вернули. Пустое поддерево — базовый случай. Если нужный ответ шире, чем то, что мы возвращаем родителю (например, путь, который изгибается в узле), его копим в общей переменной, а наверх отдаём только то, что нужно родителю.
- **Когда:**
	- посчитать что-то про поддерево целиком: высоту, размер, сумму, баланс
	- решение в узле принимается, когда известны ответы слева и справа
	- найти узел с особым свойством относительно своего поддерева (общий предок, корень совпавшего поддерева)
- **Сложность:** T: O(n) · S: O(h)
- **Шаблон:**
	```python
	# Пример: Diameter of Binary Tree. Диаметр — самый длинный путь между двумя узлами, в рёбрах
	best = 0

	def height(node):                         # возвращаем родителю высоту поддерева
	    nonlocal best
	    if not node:
	        return 0
	    left = height(node.left)
	    right = height(node.right)
	    best = max(best, left + right)        # путь, который изгибается в этом узле: ответ копим отдельно
	    return 1 + max(left, right)           # наверх можно отдать только одну ветку

	height(root)
	return best
	```

## Обход по уровням

- **Суть:** в очереди лежит текущий уровень дерева. На каждом шаге берём из неё столько узлов, сколько было в начале шага (это ровно один уровень), и добавляем в очередь их детей. Дерево обходится по слоям от корня вниз.
- **Когда:**
	- в условии «по уровням», «по слоям», «вид справа», «в каждой строке»
	- нужен ближайший к корню узел с заданным свойством или кратчайший путь по рёбрам
	- ответ считается отдельно для каждого уровня (среднее, максимум, крайний узел)
- **Сложность:** T: O(n) · S: O(w), где w — максимальная ширина дерева
- **Шаблон:**
	```python
	# Пример: Binary Tree Level Order Traversal. Значения по уровням: [[3], [9, 20], [15, 7]]
	from collections import deque

	if not root:
	    return []
	res = []
	q = deque([root])
	while q:
	    level = []
	    for _ in range(len(q)):               # len(q) берём один раз, до добавления детей: это размер уровня
	        node = q.popleft()
	        level.append(node.val)
	        if node.left:
	            q.append(node.left)
	        if node.right:
	            q.append(node.right)
	    res.append(level)
	return res

	# олимпиадный вариант очереди: список и индекс головы, deque не нужен
	q, head = [root], 0
	while head < len(q):
	    end = len(q)                          # граница уровня: всё до end — текущий уровень
	    level = []
	    while head < end:
	        node = q[head]
	        head += 1
	        level.append(node.val)
	        if node.left:
	            q.append(node.left)
	        if node.right:
	            q.append(node.right)
	    res.append(level)
	```

	- [Average of Levels in Binary Tree](https://leetcode.com/problems/average-of-levels-in-binary-tree/) · Easy · нюанс: вместо списка считаем сумму и делим на размер уровня

## Дерево поиска

- **Суть:** в бинарном дереве поиска всё в левом поддереве меньше значения узла, а всё в правом больше. Поэтому поиск, вставка и удаление идут по одной ветке: сравнили, свернули влево или вправо. Симметричный обход такого дерева выдаёт значения по возрастанию.
- **Когда:**
	- в условии «дерево поиска», «BST», «отсортированный порядок»
	- найти, вставить или удалить значение, не обходя всё дерево
	- пригодится отсортированность: `k`-й по величине, ближайшее значение, диапазон
- **Сложность:** T: O(h), где h — высота (в среднем log n, в худшем n) · S: O(h)
- **Шаблон:**
	```python
	# Пример: Insert into a Binary Search Tree. Новое значение всегда становится листом
	def insert(node, val):
	    if not node:
	        return TreeNode(val)              # дошли до пустого места, здесь и ставим
	    if val < node.val:
	        node.left = insert(node.left, val)     # идём только в одну сторону
	    else:
	        node.right = insert(node.right, val)
	    return node                           # возвращаем узел, чтобы родитель сохранил ссылку

	return insert(root, val)
	```
- **Задачи:**
	- [Search in a Binary Search Tree](https://leetcode.com/problems/search-in-a-binary-search-tree/) · Easy
	- [Insert into a Binary Search Tree](https://leetcode.com/problems/insert-into-a-binary-search-tree/) · Medium
	- [Lowest Common Ancestor of a Binary Search Tree](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-search-tree/) · Medium · нюанс: пока оба значения меньше узла, идём влево, пока оба больше — вправо; иначе текущий узел и есть ответ
	- [Delete Node in a BST](https://leetcode.com/problems/delete-node-in-a-bst/) · Medium · нюанс: если ребёнок один, поднимаем его на место узла; если два — ставим в узел наименьшее значение правого поддерева и удаляем его оттуда
	- [Range Sum of BST](https://leetcode.com/problems/range-sum-of-bst/) · Easy · нюанс: поддерево, которое целиком вне диапазона, пропускаем
	- [Validate Binary Search Tree](https://leetcode.com/problems/validate-binary-search-tree/) · Medium · нюанс: проверка границ, см. [[#Обход сверху вниз]]

> [!note] Для эрудиции: сбалансированные деревья и родственники
> Если вставлять в дерево поиска значения по возрастанию, оно выродится в список и операции станут O(n). Чтобы этого не было, дерево подправляют после каждой вставки и удаления. Основной инструмент — **поворот**: локальная перестановка двух узлов, которая сохраняет порядок значений, но меняет высоту. Реализации на собеседованиях почти не просят, спрашивают «что это и зачем».
>
> - **AVL-дерево.** Высоты левого и правого поддеревьев любого узла отличаются не больше чем на 1. Условие самое строгое из перечисленных, поэтому дерево самое низкое и поиск быстрый, но вставка и удаление делают больше поворотов. Подходит, когда читают чаще, чем пишут.
> - **Красно-чёрное дерево.** У каждого узла есть цвет (красный или чёрный). Правила: корень чёрный; у красного узла оба ребёнка чёрные; на всех путях от узла до пустого места одинаковое число чёрных узлов. Отсюда самый длинный путь не больше чем вдвое длиннее самого короткого, а высота не больше 2·log(n + 1). Условие мягче, чем у AVL: дерево чуть выше, зато поворотов мало — не больше 2 при вставке и 3 при удалении. Используется как стандартное упорядоченное множество и словарь: `std::map` и `std::set` в C++ (стандарт дерево не требует, но основные реализации берут именно его), `TreeMap` в Java. Начиная с Java 8 в такое дерево превращается корзина `HashMap`, в которой много коллизий. Цвет здесь — служебная метка, с раскраской графа это не связано.
> - **B-дерево и B+-дерево.** У узла много детей (сотни), дерево получается очень низким. Нужны там, где узел читают целиком за одно обращение к диску: индексы в базах данных, файловые системы. В B+-дереве значения лежат только в листьях, а листья связаны списком, поэтому диапазон «от a до b» читается подряд.
> - **Декартово дерево (treap) и список с пропусками (skip list).** Баланс держится на случайности, а не на строгих правилах: у treap случайные приоритеты узлов (повороты по ним всё равно есть), у skip list — случайная высота узла. Проще в коде. Skip list лежит в основе упорядоченных множеств (sorted set) в Redis.
> - **Splay-дерево.** Недавно использованный узел поворотами поднимается к корню. Хорошо для кэшей и неравномерных запросов, но на отдельную операцию гарантии O(log n) нет, только амортизированная — в сумме по последовательности операций.
>
> Рядом стоят структуры, которые похожи на дерево, но деревом поиска не являются:
> - **Куча** (heap): двоичное дерево в массиве, где родитель не больше детей. Быстро достаёт минимум, искать по значению не умеет. На ней построены `heapq` в Python и очередь с приоритетом в алгоритме Дейкстры.
> - **Префиксное дерево** (trie): по рёбрам идут буквы, путь от корня — слово. Для поиска по префиксу и автодополнения.
> - **Дерево отрезков и дерево Фенвика**: суммы или минимумы на отрезке, когда элементы меняются. Продолжение темы [[Префиксный массив|префиксных сумм]].
>
> В стандартной библиотеке Python сбалансированного дерева нет. Обычно хватает отсортированного списка с `bisect`: поиск за O(log n), вставка за O(n).

## Порядки обхода

- **Суть:** три способа обойти дерево в глубину; отличаются тем, когда «обрабатываем» узел. Прямой (preorder): узел, левое, правое. Симметричный (inorder): левое, узел, правое. Обратный (postorder): левое, правое, узел. Обратный даёт обход снизу вверх, прямой — сверху вниз, а симметричный на дереве поиска выдаёт отсортированный порядок. Рекурсивно это три строки, которые отличаются только порядком, но на собеседовании часто просят вариант со стеком.
- **Когда:**
	- в условии прямо названо, в каком порядке выдать значения
	- нужен `k`-й по порядку элемент дерева поиска или следующий за заданным
	- остановиться посреди обхода, не проходя всё дерево
- **Сложность:** T: O(n) · S: O(h)
- **Шаблон:**
	```python
	# Пример: Kth Smallest Element in a BST. Симметричный обход со стеком, остановка на k-м узле
	stack = []
	node = root
	while stack or node:
	    while node:                           # спускаемся влево до упора, запоминая путь
	        stack.append(node)
	        node = node.left
	    node = stack.pop()                    # самый левый непосещённый узел
	    k -= 1
	    if k == 0:
	        return node.val
	    node = node.right                     # потом правое поддерево

	# те же три порядка рекурсивно:
	# preorder:  res.append(node.val); go(node.left); go(node.right)
	# inorder:   go(node.left); res.append(node.val); go(node.right)
	# postorder: go(node.left); go(node.right); res.append(node.val)
	```
- **Задачи:**
	- [Binary Tree Inorder Traversal](https://leetcode.com/problems/binary-tree-inorder-traversal/) · Easy
	- [Binary Tree Preorder Traversal](https://leetcode.com/problems/binary-tree-preorder-traversal/) · Easy · нюанс: со стеком проще всего: достали узел, записали, положили правого ребёнка, затем левого (левый окажется сверху)
	- [Binary Tree Postorder Traversal](https://leetcode.com/problems/binary-tree-postorder-traversal/) · Easy · нюанс: обход «узел, правое, левое» со стеком, затем ответ разворачиваем

## Построение дерева

- **Суть:** по результатам обходов восстанавливаем дерево. В прямом обходе корень первый, в обратном последний. В симметричном корень делит значения на левое и правое поддеревья. Берём корень из прямого обхода, находим его в симметричном и рекурсивно строим левую и правую части.
- **Когда:**
	- даны два обхода (прямой и симметричный либо симметричный и обратный), построить дерево
	- превратить дерево в строку и обратно (сериализация)
	- по отсортированному массиву построить сбалансированное дерево поиска
- **Сложность:** T: O(n) при словаре индексов · S: O(n)
- **Шаблон:**
	```python
	# Пример: Construct Binary Tree from Preorder and Inorder Traversal
	idx = {v: i for i, v in enumerate(inorder)}       # где значение стоит в симметричном обходе
	it = iter(preorder)                               # корни выдаём по очереди в прямом порядке

	def build(lo, hi):                        # lo..hi — границы поддерева в inorder
	    if lo > hi:
	        return None
	    val = next(it)                        # следующий корень в preorder
	    mid = idx[val]
	    node = TreeNode(val)
	    node.left = build(lo, mid - 1)        # левое строим раньше правого: в preorder оно идёт первым
	    node.right = build(mid + 1, hi)
	    return node

	return build(0, len(inorder) - 1)
	```
