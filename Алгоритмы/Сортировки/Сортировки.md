Классические сортировки: как работают, сколько стоят, когда какую брать. Рядом лежат [[Структуры данных]] (куча, массив, хеш-таблица) и шпаргалка по задачам [[Паттерны задач]]. Здесь только сами алгоритмы, а к какому паттерну сводится задача, смотри в шпаргалке.

Разделы: [[#Сортировка выбором]] · [[#Сортировка вставками]] · [[#Пузырьковая сортировка]] · [[#Сортировка слиянием]] · [[#Быстрая сортировка]] · [[#Сортировка кучей]] · [[#Сортировка подсчётом]] · [[Сортировки для эрудиции]]

## Что нужно знать до алгоритмов

- **Сравнение или нет.** Выбор, вставки, пузырёк, слияние, быстрая и куча — это сортировки сравнением, они узнают порядок, сравнивая пары элементов. Для них доказана нижняя граница: быстрее O(n log n) в худшем случае нельзя. Подсчёт её обходит, потому что не сравнивает элементы, а использует их значения как индексы, но работает только на целых числах из небольшого диапазона.
- **Устойчивость.** Сортировка устойчива, если элементы с равными ключами остаются в исходном порядке. Это важно, когда сортируют записи по нескольким полям по очереди: сначала по имени, потом по возрасту, и при равном возрасте имена должны остаться упорядоченными.
- **In-place.** Сортировка на месте не требует массива такого же размера. Рекурсия тоже занимает память (стек вызовов), поэтому у быстрой сортировки память O(log n), а не O(1).
- **Лучший, средний, худший.** Для быстрой сортировки худший случай O(n²) встречается на неудачном выборе опорного элемента, поэтому его берут случайным. Для вставок лучший случай O(n) возникает на уже отсортированных данных.

| Алгоритм | Лучший | Средний | Худший | Память | Устойчивая |
|---|---|---|---|---|---|
| Выбором | O(n²) | O(n²) | O(n²) | O(1) | нет |
| Вставками | O(n) | O(n²) | O(n²) | O(1) | да |
| Пузырьком | O(n) | O(n²) | O(n²) | O(1) | да |
| Слиянием | O(n log n) | O(n log n) | O(n log n) | O(n) | да |
| Быстрая | O(n log n) | O(n log n) | O(n²) | O(log n) | нет |
| Кучей | O(n log n) | O(n log n) | O(n log n) | O(1) | нет |
| Подсчётом | O(n + k) | O(n + k) | O(n + k) | O(n + k) | да |

`k` в подсчёте — размер диапазона значений (максимум минус минимум плюс один).

> [!tip] Как выбрать сортировку
> - Пишешь на Python и нет особых условий → встроенные `sorted()` и `list.sort()`, они устойчивые и быстрые (см. [[Сортировки для эрудиции]])
> - Мало элементов (десятки) или массив почти отсортирован → **вставками**
> - Нужна устойчивость и гарантия O(n log n), память не жалко → **слиянием**
> - Нужна гарантия O(n log n) без дополнительной памяти → **кучей**
> - Нужна скорость в среднем на случайных данных, устойчивость не нужна → **быстрая**
> - Целые числа в небольшом диапазоне (оценки, возраст, символы) → **подсчётом**
> - Нужен только k-й по величине или k лучших, а не весь порядок → не сортируй целиком, см. [[Сортировки для эрудиции]]
> - **Выбором** и **пузырьком** на практике не берут, их спрашивают, чтобы проверить, что ты понимаешь базу

Для каждого массива ниже пример один и тот же: `[5, 2, 4, 1, 3]`.

## Сортировка выбором

- **Суть:** на каждом шаге находим минимум среди ещё не отсортированных элементов и меняем его местами с первым из них. Слева растёт отсортированная часть, справа остаётся неотсортированный хвост.
- **Как идёт:** `[5, 2, 4, 1, 3]` → минимум 1 меняем с 5: `[1, 2, 4, 5, 3]` → минимум хвоста 2 уже на месте → минимум 3 меняем с 4: `[1, 2, 3, 5, 4]` → `[1, 2, 3, 4, 5]`.
- **Схема:** `[5, 2, 4, 1, 3]`, слева растёт отсортированная часть.
	```mermaid
	flowchart LR
	    s0["[5 2 4 1 3]"] -- "мин 1 ↔ 5" --> s1["[1 | 2 4 5 3]"] -- "мин 2 на месте" --> s2["[1 2 | 4 5 3]"] -- "мин 3 ↔ 4" --> s3["[1 2 3 | 5 4]"] -- "мин 4 ↔ 5" --> s4["[1 2 3 4 5]"]
	```
	Черта отделяет отсортированный префикс от хвоста. Каждый шаг ищет минимум по всему хвосту, поэтому n²/2 сравнений при любых данных.
- **Сложность:** T: O(n²) всегда, даже на отсортированных данных · S: O(1). Обменов не больше n − 1, это единственный плюс: если запись в память дорогая, выбор делает её меньше всех.
- **Устойчивость:** нет. Обмен переносит элемент через весь хвост. Пример: у `[2a, 2b, 1c]` результат `[1c, 2b, 2a]`, две «двойки» поменялись местами.
- **Когда:** почти никогда в реальном коде. Спрашивают на собеседованиях как самый простой пример.
- **Шаблон:**
	```python
	def selection_sort(a):
	    n = len(a)
	    for i in range(n - 1):
	        m = i                             # индекс минимума в хвосте a[i:]
	        for j in range(i + 1, n):
	            if a[j] < a[m]:
	                m = j
	        a[i], a[m] = a[m], a[i]           # ставим минимум на позицию i
	```

## Сортировка вставками

- **Суть:** слева лежит отсортированный префикс. Берём следующий элемент и вставляем его на своё место в префиксе, сдвигая бо́льшие элементы вправо. Как раскладывают карты в руке.
- **Как идёт:** `[5, 2, 4, 1, 3]` → вставили 2: `[2, 5, 4, 1, 3]` → 4: `[2, 4, 5, 1, 3]` → 1: `[1, 2, 4, 5, 3]` → 3: `[1, 2, 3, 4, 5]`.
- **Схема:** `[5, 2, 4, 1, 3]`, префикс слева всегда отсортирован.
	```mermaid
	flowchart LR
	    s0["[5 | 2 4 1 3]"] -- "вставили 2" --> s1["[2 5 | 4 1 3]"] -- "вставили 4" --> s2["[2 4 5 | 1 3]"] -- "вставили 1" --> s3["[1 2 4 5 | 3]"] -- "вставили 3" --> s4["[1 2 3 4 5]"]
	```
	Новый элемент сдвигает бо́льшие вправо, пока не найдёт место. На почти отсортированных данных сдвигов мало, поэтому там O(n).
- **Сложность:** T: O(n) в лучшем (уже отсортирован), O(n²) в среднем и худшем · S: O(1). Число сдвигов равно числу инверсий (пар, стоящих не по порядку), поэтому на почти отсортированных данных алгоритм быстрый.
- **Устойчивость:** да, если сдвигаем только строго бо́льшие элементы (`a[j] > x`).
- **Когда:**
	- мало элементов (до нескольких десятков), накладные расходы сложных алгоритмов не окупаются
	- массив почти отсортирован
	- данные приходят по одному, и нужно держать их упорядоченными
	- как «довод» внутри быстрой сортировки и Timsort для коротких кусков
- **Шаблон:**
	```python
	def insertion_sort(a):
	    for i in range(1, len(a)):
	        x = a[i]                          # элемент, который вставляем в префикс a[:i]
	        j = i - 1
	        while j >= 0 and a[j] > x:        # строго больше: равные не двигаем, поэтому сортировка устойчива
	            a[j + 1] = a[j]               # сдвигаем бо́льший вправо
	            j -= 1
	        a[j + 1] = x                      # ставим на освободившееся место
	```
- **Задачи:**
	- [Insertion Sort List](https://leetcode.com/problems/insertion-sort-list/) · Medium · нюанс: список, а не массив, вставка идёт ссылками, нужен фиктивный узел, см. [[Односвязный список#Фиктивный узел]]
	- [Merge Sorted Array](https://leetcode.com/problems/merge-sorted-array/) · Easy · нюанс: сливаем с конца, чтобы не затирать значения первого массива

## Пузырьковая сортировка

- **Суть:** проходим по массиву и меняем местами соседние элементы, стоящие не по порядку. После первого прохода самый большой элемент «всплывает» в конец, после второго второй по величине и так далее.
- **Как идёт:** `[5, 2, 4, 1, 3]` → после прохода 1: `[2, 4, 1, 3, 5]` → прохода 2: `[2, 1, 3, 4, 5]` → прохода 3: `[1, 2, 3, 4, 5]`. Четвёртый проход обменов не делает, и цикл завершается.
- **Схема:** `[5, 2, 4, 1, 3]`, после каждого прохода максимум оказывается в конце.
	```mermaid
	flowchart LR
	    s0["[5 2 4 1 3]"] -- "проход 1" --> s1["[2 4 1 3 | 5]"] -- "проход 2" --> s2["[2 1 3 | 4 5]"] -- "проход 3" --> s3["[1 2 | 3 4 5]"] -- "проход 4: обменов нет" --> s4["[1 2 3 4 5]"]
	```
	Справа от черты элементы уже на местах, поэтому каждый следующий проход короче на один. Нет обменов за проход — массив отсортирован, можно выходить.
- **Сложность:** T: O(n) в лучшем (с флагом «были обмены»), O(n²) в среднем и худшем · S: O(1).
- **Устойчивость:** да, меняем только строго неупорядоченные соседние пары.
- **Когда:** учебный пример. В реальных задачах вставки делают то же самое лучше.
- **Шаблон:**
	```python
	def bubble_sort(a):
	    n = len(a)
	    for end in range(n - 1, 0, -1):       # a[end + 1:] уже на своих местах
	        swapped = False
	        for j in range(end):
	            if a[j] > a[j + 1]:
	                a[j], a[j + 1] = a[j + 1], a[j]
	                swapped = True
	        if not swapped:                   # обменов не было, массив уже отсортирован
	            break
	```

## Сортировка слиянием

- **Суть:** делим массив пополам, рекурсивно сортируем половины и сливаем два отсортированных массива в один за линейное время. Это «разделяй и властвуй». Слияние — тот же приём «каждому по указателю», что и в [[Два указателя#Каждому по указателю]].
- **Схема:** `[5, 2, 4, 1, 3]`, вниз идём делением, наверх — слиянием.
	```mermaid
	flowchart TD
	    r["[5, 2, 4, 1, 3]<br/>→ [1, 2, 3, 4, 5]"] --> a["[5, 2]<br/>→ [2, 5]"]
	    r --> b["[4, 1, 3]<br/>→ [1, 3, 4]"]
	    a --> a1["[5]"]
	    a --> a2["[2]"]
	    b --> b1["[4]"]
	    b --> b2["[1, 3]<br/>→ [1, 3]"]
	    b2 --> c1["[1]"]
	    b2 --> c2["[3]"]
	```
	В каждом узле сверху то, что пришло на вход, снизу — результат слияния его половин. Листья из одного элемента уже отсортированы. Уровней деления log n, на каждом слияния суммарно n шагов.
- **Сложность:** T: O(n log n) всегда (log n уровней деления, на каждом линейное слияние) · S: O(n) под вспомогательные массивы.
- **Устойчивость:** да, если при равных значениях берём элемент из левой половины (`<=`).
- **Когда:**
	- нужна устойчивость и гарантия O(n log n)
	- сортируется связный список: слиянию не нужен произвольный доступ, и память O(1) на ссылках
	- данные не помещаются в память: сортируем куски отдельно, потом сливаем (внешняя сортировка)
	- по ходу слияния нужно считать пары «левый больше правого» (инверсии)
- **Шаблон:**
	```python
	def merge_sort(a):
	    if len(a) <= 1:
	        return a
	    mid = len(a) // 2
	    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
	    res = []
	    i = j = 0
	    while i < len(left) and j < len(right):
	        if left[i] <= right[j]:           # <=: при равных берём левый, порядок сохраняется
	            res.append(left[i]); i += 1
	        else:
	            res.append(right[j]); j += 1
	    res.extend(left[i:])                  # остаток одного из массивов
	    res.extend(right[j:])
	    return res
	```
- **Задачи:**
	- [Sort an Array](https://leetcode.com/problems/sort-an-array/) · Medium · нюанс: слияние или куча проходят по времени на любых входах, быстрая без случайного опорного и без трёх частей получит TLE на повторах
	- [Sort List](https://leetcode.com/problems/sort-list/) · Medium · нюанс: середину находим черепахой и зайцем, половины сливаем как в Merge Two Sorted Lists, см. [[Односвязный список#Черепаха и заяц]] и [[Односвязный список#Фиктивный узел]]
	- [Merge Sorted Array](https://leetcode.com/problems/merge-sorted-array/) · Easy
	- [Count of Smaller Numbers After Self](https://leetcode.com/problems/count-of-smaller-numbers-after-self/) · Hard · нюанс: при слиянии считаем, сколько элементов правой половины ушло вперёд, это и есть счётчик; сортируем индексы, а не значения
	- [Reverse Pairs](https://leetcode.com/problems/reverse-pairs/) · Hard · нюанс: перед слиянием двумя указателями считаем пары `left[i] > 2 × right[j]`

## Быстрая сортировка

- **Суть:** выбираем опорный элемент и раскладываем массив на три части: меньше опорного, равные, больше. Меньшие и большие сортируем рекурсивно, равные уже на месте. Работа делается при разбиении, а не при сборке, поэтому памяти почти не нужно.
- **Схема:** один шаг разбиения `[3, 6, 2, 3, 8, 1]` по опорному `3`.
	```mermaid
	flowchart TD
	    r["[3, 6, 2, 3, 8, 1]<br/>опорный 3"] --> l["меньше: [2, 1]<br/>сортируем рекурсивно"]
	    r --> e["равные: [3, 3]<br/>уже на месте"]
	    r --> g["больше: [6, 8]<br/>сортируем рекурсивно"]
	```
	Итог: левая часть, равные, правая часть. Порядок внутри частей после разбиения произвольный, поэтому сортировка не устойчивая.
- **Сложность:** T: O(n log n) в среднем, O(n²) в худшем (опорный каждый раз оказывается минимумом или максимумом, например первый элемент на отсортированных данных) · S: O(log n) на стек рекурсии. Случайный опорный делает худший случай практически невозможным.
- **Устойчивость:** нет, разбиение переставляет элементы через большие расстояния.
- **Когда:**
	- нужна быстрая сортировка в среднем, дополнительная память важна
	- нужен k-й по величине элемент: тот же приём, но идём только в одну часть (быстрый отбор, см. [[Сортировки для эрудиции]])
	- разбиение на три части (флаг Дейкстры) в одной из задач-классик: `0`, `1`, `2`
- **Шаблон:**
	```python
	import random

	def quick_sort(a, lo=0, hi=None):
	    if hi is None:
	        hi = len(a) - 1
	    while lo < hi:
	        pivot = a[random.randint(lo, hi)]         # случайный опорный защищает от O(n²)
	        lt, i, gt = lo, lo, hi                    # a[lo:lt] < pivot, a[lt:i] == pivot, a[gt+1:hi+1] > pivot
	        while i <= gt:
	            if a[i] < pivot:
	                a[lt], a[i] = a[i], a[lt]; lt += 1; i += 1
	            elif a[i] > pivot:
	                a[i], a[gt] = a[gt], a[i]; gt -= 1    # i не двигаем: пришёл ещё не просмотренный элемент
	            else:
	                i += 1
	        # меньшую часть сортируем рекурсивно, большую в цикле: глубина стека не больше log n
	        if lt - lo < hi - gt:
	            quick_sort(a, lo, lt - 1); lo = gt + 1
	        else:
	            quick_sort(a, gt + 1, hi); hi = lt - 1
	```
- **Задачи:**
	- [Sort Colors](https://leetcode.com/problems/sort-colors/) · Medium · нюанс: это одно разбиение на три части по опорному `1`, без рекурсии, один проход
	- [Sort an Array](https://leetcode.com/problems/sort-an-array/) · Medium · нюанс: на тестах с повторами двухчастное разбиение (Ломуто) вырождается в O(n²), поэтому три части и случайный опорный
	- [Kth Largest Element in an Array](https://leetcode.com/problems/kth-largest-element-in-an-array/) · Medium · нюанс: быстрый отбор вместо полной сортировки, идём только в ту часть, где лежит `n - k`-й индекс; либо куча размера k

## Сортировка кучей

- **Суть:** сначала превращаем массив в кучу (родитель не меньше детей, корень — максимум), потом `n - 1` раз меняем корень с последним элементом кучи, уменьшаем кучу на один и просеиваем новый корень вниз. Куча — это двоичное дерево, хранящееся в самом массиве: у элемента `i` дети `2i + 1` и `2i + 2`. Подробнее о ней — в [[Структуры данных#Куча]].
- **Схема:** куча после построения для `[4, 10, 3, 5, 1]`, в массиве это `[10, 5, 3, 4, 1]`.
	```mermaid
	flowchart TD
	    n0["10 · i=0"] --> n1["5 · i=1"]
	    n0 --> n2["3 · i=2"]
	    n1 --> n3["4 · i=3"]
	    n1 --> n4["1 · i=4"]
	```
	Первый шаг сортировки: меняем корень `10` с последним `1`, получаем `[1, 5, 3, 4 | 10]`, где `10` уже на месте. Просеиваем `1` вниз: меняем с `5`, потом с `4`, куча становится `[5, 4, 3, 1]`.
- **Сложность:** T: O(n log n) всегда (построение кучи O(n), потом n просеиваний по log n) · S: O(1), сортировка на месте.
- **Устойчивость:** нет.
- **Когда:**
	- нужна гарантия O(n log n) и нет памяти под слияние
	- нужны только `k` наибольших: не сортируем всё, держим кучу размера `k`
	- запасной вариант внутри introsort, когда быстрая начинает вырождаться
- **Шаблон:**
	```python
	def heap_sort(a):
	    n = len(a)

	    def sift_down(i, size):               # просеиваем a[i] вниз по куче размера size
	        while True:
	            big, l, r = i, 2 * i + 1, 2 * i + 2
	            if l < size and a[l] > a[big]:
	                big = l
	            if r < size and a[r] > a[big]:
	                big = r
	            if big == i:
	                return
	            a[i], a[big] = a[big], a[i]
	            i = big

	    for i in range(n // 2 - 1, -1, -1):   # строим кучу снизу вверх: листья уже кучи, начинаем с последнего родителя
	        sift_down(i, n)
	    for end in range(n - 1, 0, -1):
	        a[0], a[end] = a[end], a[0]       # максимум уходит в конец, он уже на своём месте
	        sift_down(0, end)                 # восстанавливаем кучу без последнего элемента
	```

## Сортировка подсчётом

- **Суть:** если значения — целые числа из небольшого диапазона, элементы можно не сравнивать. Считаем, сколько раз встретилось каждое значение, превращаем счётчики в накопленные суммы (позиция, до которой занято место), потом раскладываем элементы в результат.
- **Как идёт:** `[3, 1, 2, 3, 1]`: счётчики `1→2, 2→1, 3→2`, накопленные `1→2, 2→3, 3→5`, раскладываем справа налево: `[1, 1, 2, 3, 3]`.
- **Схема:** `[3, 1, 2, 3, 1]`, три этапа.
	```mermaid
	flowchart LR
	    a["вход<br/>[3 1 2 3 1]"] --> c["счётчики<br/>1→2 · 2→1 · 3→2"] --> p["накопленные<br/>1→2 · 2→3 · 3→5"] --> r["раскладка справа налево<br/>[1 1 2 3 3]"]
	```
	Накопленная сумма говорит, на какой позиции кончается место значения. Идём по входу с конца и ставим элемент на позицию на единицу левее, поэтому порядок равных сохраняется.
- **Сложность:** T: O(n + k), где k — размер диапазона значений · S: O(n + k). Если `k` намного больше `n` (например, значения до 10⁹ на сотне чисел), подсчёт проигрывает любой сортировке сравнением.
- **Устойчивость:** да, если раскладывать с конца исходного массива, как в коде.
- **Когда:**
	- целые числа с небольшим диапазоном (возраст, оценки, цифры, коды символов)
	- нужна сортировка за линейное время
	- как внутренний шаг поразрядной сортировки (см. [[Сортировки для эрудиции]])
- **Шаблон:**
	```python
	def counting_sort(a):
	    if not a:
	        return []
	    lo, hi = min(a), max(a)               # сдвиг на lo позволяет сортировать и отрицательные числа
	    count = [0] * (hi - lo + 1)
	    for x in a:
	        count[x - lo] += 1                # сколько раз встретилось каждое значение
	    for i in range(1, len(count)):
	        count[i] += count[i - 1]          # накопленная сумма: сколько элементов не больше значения i + lo
	    res = [0] * len(a)
	    for x in reversed(a):                 # с конца, чтобы равные остались в исходном порядке
	        count[x - lo] -= 1
	        res[count[x - lo]] = x
	    return res
	```
