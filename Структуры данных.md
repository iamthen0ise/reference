## Сколько стоят операции

| Структура | Доступ по индексу | Поиск по значению | Вставка | Удаление |
|---|---|---|---|---|
| Массив (`list`) | O(1) | O(n) | в конец O(1)*, в середину O(n) | с конца O(1), из середины O(n) |
| Связный список | O(n) | O(n) | после известного узла O(1) | известного узла O(1)** |
| Стек, очередь (`deque`) | только концы, O(1) | O(n) | в конец O(1) | с концов O(1) |
| Хеш-таблица (`dict`, `set`) | по ключу O(1)* | по ключу O(1)* | O(1)* | O(1)* |
| Куча (`heapq`) | минимум O(1) | O(n) | O(log n) | минимума O(log n) |
| Сбалансированное дерево | — | O(log n) | O(log n) | O(log n) |
| Префиксное дерево | — | O(длина слова) | O(длина слова) | O(длина слова) |

`*` амортизированное или среднее время: отдельная операция может быть дороже. `**` у двусвязного списка; у односвязного нужен предыдущий узел.

> [!tip] Как выбрать структуру
> - Нужен доступ по номеру, данные идут подряд → **массив**
> - Нужно быстро ответить «есть ли такой ключ» или найти значение по ключу → **хеш-таблица**
> - Нужен текущий минимум или максимум, значения добавляются и забираются → **куча**
> - Последний пришёл — первый ушёл, вложенность, откат → **стек**
> - Первый пришёл — первый ушёл, обработка в порядке прихода → **очередь**
> - Нужен порядок по значению с поиском «ближайшего», диапазоном, k-м → **дерево поиска** (в Python — отсортированный список и `bisect`)
> - Поиск по префиксу, автодополнение, словарь слов → **префиксное дерево**
> - Объекты связаны друг с другом произвольно → **граф**
> - Группы, которые объединяются, и вопрос «в одной ли они группе» → **система непересекающихся множеств**
> - Суммы или минимумы на отрезках, и значения меняются → **дерево Фенвика или отрезков**
> - Нужно хранить N самых свежих, выкидывая давно не нужные → **LRU-кэш**

## Массив

- **Суть:** элементы лежат в памяти подряд, поэтому элемент по индексу достаётся за один шаг. Динамический массив (в Python `list`) растёт, когда место кончилось: выделяет новый кусок с запасом и копирует старое. Копирование редкое, поэтому добавление в конец в среднем стоит O(1).
- **Когда:**
	- данные идут подряд, нужен доступ по номеру
	- добавляем и убираем только в конце
	- вставки и удаления в середине редки
- **Чего избегать:** `insert(0, x)`, `pop(0)` и `x in list` стоят O(n). Если нужно убирать с начала, бери `deque`, если искать, бери `set` или `dict`.
- **Python:** `list`, `array.array` для компактных числовых, срезы `a[i:j]` создают копию за O(j − i).
- **Связанные паттерны:** [[Паттерны задач#Два указателя]], [[Паттерны задач#Плавающее окно]], [[Паттерны задач#Префиксный массив]], [[Паттерны задач#Бинарный поиск]]
- **Задачи:**
	- [Insert Delete GetRandom O(1)](https://leetcode.com/problems/insert-delete-getrandom-o1/) · Medium · нюанс: массив и словарь «значение → индекс»; при удалении меняем элемент с последним и убираем последний, получается O(1)
	- [Design Circular Queue](https://leetcode.com/problems/design-circular-queue/) · Medium · нюанс: кольцевой буфер, индексы по модулю длины

## Связный список

- **Суть:** узлы хранят значение и ссылку на следующий (в двусвязном ещё и на предыдущий). Вставка и удаление известного узла быстрые, но к n-му элементу нужно идти с начала.
- **Схема:**
	```mermaid
	flowchart LR
	    head(["head (фиктивный)"]) <--> a["1"] <--> b["2"] <--> c["3"] <--> tail(["tail (фиктивный)"])
	```
	Стрелки в обе стороны: у каждого узла есть `prev` и `next`. Фиктивные голова и хвост убирают проверки на пустой список.
- **Когда:**
	- частые вставки и удаления в середине при уже известном узле
	- нужна структура без пересоздания при росте
	- внутри других структур: LRU-кэш, очередь, хеш-таблица с цепочками
- **Python:** встроенного нет, пишут `ListNode`. Ближайший родственник — `collections.deque`, это двусвязный список блоков.
- **Шаблон:**
	```python
	# Пример: двусвязный список с фиктивными головой и хвостом. Вставка и удаление узла за O(1)
	class Node:
	    def __init__(self, key=0, val=0):
	        self.key, self.val = key, val
	        self.prev = self.next = None

	class DList:
	    def __init__(self):
	        self.head, self.tail = Node(), Node()         # фиктивные границы: у настоящих узлов всегда есть соседи
	        self.head.next, self.tail.prev = self.tail, self.head

	    def add_front(self, n):                           # вставить узел сразу после головы
	        n.prev, n.next = self.head, self.head.next
	        self.head.next.prev = n
	        self.head.next = n

	    def remove(self, n):                              # вырезать узел, зная только его самого
	        n.prev.next, n.next.prev = n.next, n.prev

	    def pop_back(self):                               # убрать последний настоящий узел
	        last = self.tail.prev
	        self.remove(last)
	        return last
	```
- **Связанные паттерны:** весь раздел [[Паттерны задач#Односвязный список]], а как двусвязный список работает внутри кэша — в разделе [[#LRU-кэш]].
- **Задачи:**
	- [Design Linked List](https://leetcode.com/problems/design-linked-list/) · Medium · нюанс: фиктивная голова упрощает вставку и удаление по индексу

## Стек

- **Суть:** последним пришёл, первым вышел. Операции только с одного конца: положить, снять, посмотреть верх.
- **Когда:**
	- вложенность и парность (скобки, теги, вызовы)
	- откат к предыдущему состоянию
	- «ближайший» больший или меньший элемент
	- замена рекурсии циклом
- **Python:** `list` с `append()` и `pop()`, обе операции O(1).
- **Связанные паттерны:** [[Паттерны задач#Стек]]. Рекурсия работает на стеке вызовов, глубину которого в Python ограничивает `sys.getrecursionlimit()`.

## Очередь и дек

- **Суть:** очередь работает по принципу «первым пришёл, первым вышел»: добавляем в конец, забираем с начала. Дек (двусторонняя очередь) позволяет добавлять и забирать с обоих концов.
- **Когда:**
	- обработка в порядке прихода: обход в ширину, задачи по очереди
	- скользящее окно с максимумом: дек хранит кандидатов, монотонный по значению
	- нужно быстро работать с обоими концами
- **Чего избегать:** `list.pop(0)` стоит O(n). Очередь на списке работает медленно, нужен `deque`.
- **Python:** `collections.deque` (`append`, `appendleft`, `pop`, `popleft`, все O(1)), для потоков ещё `queue.Queue`.
- **Шаблон:**
	```python
	# Пример: Implement Queue using Stacks. Очередь на двух стеках, операции в среднем O(1)
	class MyQueue:
	    def __init__(self):
	        self.inp, self.out = [], []       # inp — куда кладём, out — откуда забираем

	    def push(self, x):
	        self.inp.append(x)

	    def pop(self):
	        self.peek()                       # гарантируем, что out не пуст
	        return self.out.pop()

	    def peek(self):
	        if not self.out:                  # переливаем только когда out кончился: порядок разворачивается
	            while self.inp:
	                self.out.append(self.inp.pop())
	        return self.out[-1]
	```

## Хеш-таблица и множество

- **Суть:** массив «корзин» и хеш-функция, которая по ключу выдаёт номер корзины. Поиск, вставка и удаление в среднем за O(1). Два разных ключа могут попасть в одну корзину (коллизия). Решают двумя способами: цепочки (в корзине список пар) и открытая адресация (ищем свободную соседнюю ячейку, так сделан `dict` в CPython). Когда таблица заполнена больше чем на заданную долю (коэффициент заполнения), её расширяют и перекладывают элементы.
- **Схема (цепочки):**
	```mermaid
	flowchart LR
	    subgraph T["массив корзин"]
	        direction TB
	        b0["0"]
	        b1["1"]
	        b2["2"]
	        b3["3"]
	    end
	    b0 --> a["'a': 1"] --> e["'e': 5"]
	    b2 --> c["'c': 3"]
	    b3 --> d["'d': 4"] --> h["'h': 8"] --> k["'k': 2"]
	```
	Ключи `'a'` и `'e'` дали один номер корзины (коллизия) и стоят в одной цепочке. Длинная цепочка в корзине 3 — то, во что вырождается таблица при плохой хеш-функции.
- **Когда:**
	- «видел ли раньше», дубликаты, частоты
	- поиск пары по значению
	- группировка по ключу
	- кеш уже посчитанного
- **Чего избегать:** ключом может быть только хешируемый (неизменяемый) объект: число, строка, кортеж, но не `list`. При плохой хеш-функции или намеренно подобранных ключах всё может попасть в одну корзину, и операции станут O(n).
- **Python:** `dict`, `set`, `collections.Counter`, `defaultdict`; `dict` с версии 3.7 хранит порядок вставки.
- **Шаблон:**
	```python
	# Пример: хеш-таблица с цепочками (как в Design HashMap). Показывает, как устроены корзины и расширение
	class HashMap:
	    def __init__(self):
	        self.buckets = [[] for _ in range(8)]     # в каждой корзине список пар (ключ, значение)
	        self.size = 0

	    def _bucket(self, key):
	        return self.buckets[hash(key) % len(self.buckets)]

	    def get(self, key, default=None):
	        for k, v in self._bucket(key):            # перебираем короткую цепочку
	            if k == key:
	                return v
	        return default

	    def put(self, key, value):
	        b = self._bucket(key)
	        for i, (k, _) in enumerate(b):
	            if k == key:
	                b[i] = (key, value)               # ключ уже есть, обновляем значение
	                return
	        b.append((key, value))
	        self.size += 1
	        if self.size > 0.75 * len(self.buckets):  # коэффициент заполнения больше 0.75, расширяем вдвое
	            self._grow()

	    def _grow(self):
	        old = [kv for b in self.buckets for kv in b]
	        self.buckets = [[] for _ in range(2 * len(self.buckets))]
	        for k, v in old:                          # номера корзин зависят от размера, перекладываем все
	            self._bucket(k).append((k, v))
	```
- **Открытая адресация:** вместо цепочек все пары лежат прямо в массиве. Если нужная ячейка занята, идём к следующей (линейное пробирование). Удалить пару нельзя просто так: цепочка проб, которая шла через эту ячейку, оборвётся, и соседние ключи станут «невидимыми». Вместо этого ставим метку-«надгробие».
	```python
	# Пример: хеш-таблица с линейным пробированием и надгробиями (так устроено семейство, в которое входит dict в CPython)
	EMPTY, DELETED = object(), object()               # две разные метки: «никогда не занято» и «было занято, удалили»

	class OpenHashMap:
	    def __init__(self):
	        self.keys = [EMPTY] * 8
	        self.vals = [None] * 8
	        self.used = 0                             # занятые ячейки вместе с надгробиями
	        self.size = 0                             # только живые пары

	    def _find(self, key):                         # (индекс, найден ли ключ)
	        n = len(self.keys)
	        i = hash(key) % n
	        first_deleted = None
	        while self.keys[i] is not EMPTY:          # идём, пока не упрёмся в по-настоящему пустую ячейку
	            if self.keys[i] is DELETED:
	                if first_deleted is None:
	                    first_deleted = i             # сюда можно будет вставить новый ключ
	            elif self.keys[i] == key:
	                return i, True
	            i = (i + 1) % n
	        return (first_deleted if first_deleted is not None else i), False

	    def get(self, key, default=None):
	        i, found = self._find(key)
	        return self.vals[i] if found else default

	    def put(self, key, value):
	        i, found = self._find(key)
	        if found:
	            self.vals[i] = value
	            return
	        if self.keys[i] is EMPTY:
	            self.used += 1
	        self.keys[i], self.vals[i] = key, value
	        self.size += 1
	        if self.used > 0.5 * len(self.keys):      # при открытой адресации заполнять сильнее половины нельзя: цепочки проб растут
	            self._grow()

	    def delete(self, key):
	        i, found = self._find(key)
	        if found:
	            self.keys[i], self.vals[i] = DELETED, None
	            self.size -= 1

	    def _grow(self):                              # перекладываем живые пары, надгробия исчезают
	        old = [(k, v) for k, v in zip(self.keys, self.vals) if k is not EMPTY and k is not DELETED]
	        self.keys = [EMPTY] * (2 * len(self.keys))
	        self.vals = [None] * len(self.keys)
	        self.used = self.size = 0
	        for k, v in old:
	            self.put(k, v)
	```
	Цепочки проще и терпимы к высокой загрузке, открытая адресация экономнее по памяти и лучше ложится на кэш процессора, так как всё лежит рядом.

## Куча

- **Суть:** двоичное дерево, которое хранится в массиве: у элемента `i` дети `2i + 1` и `2i + 2`, родитель `(i − 1) // 2`. В мин-куче родитель не больше детей, поэтому минимум всегда в корне. Добавили элемент в конец и «всплыли» вверх, пока он меньше родителя. Достали корень: поставили на его место последний и «просеяли» вниз. Обе операции идут по высоте дерева, это O(log n).
- **Схема (мин-куча):**
	```mermaid
	flowchart TD
	    n0["1 · i=0"] --> n1["3 · i=1"]
	    n0 --> n2["2 · i=2"]
	    n1 --> n3["7 · i=3"]
	    n1 --> n4["4 · i=4"]
	    n2 --> n5["5 · i=5"]
	```
	В массиве это `[1, 3, 2, 7, 4, 5]`. Родитель всегда не больше детей, но порядок между «братьями» и «двоюродными» не задан: 3 и 2 лежат на одном уровне в любом порядке.
- **Когда:**
	- нужен текущий минимум или максимум, а набор меняется
	- top-k: кучей размера k за O(n log k)
	- слияние k отсортированных последовательностей
	- «ближайший по приоритету» в планировщике, в алгоритме Дейкстры
	- медиана потока данных (две кучи)
- **Чего избегать:** искать произвольный элемент в куче за O(n), удалять его тоже. Если нужно удалять из середины, помечай устаревшие записи и пропускай при извлечении (так сделано в алгоритме Дейкстры).
- **Python:** `heapq` — только мин-куча. Максимум получают отрицанием значений. Пары `(приоритет, значение)` сравниваются по первому полю. `heapq.heapify(a)` строит кучу за O(n).
- **Шаблон:**
	```python
	# Пример: мин-куча «на пальцах». На практике бери heapq, это для понимания, как устроены push и pop
	class MinHeap:
	    def __init__(self):
	        self.a = []

	    def push(self, x):
	        a = self.a
	        a.append(x)
	        i = len(a) - 1
	        while i > 0 and a[(i - 1) // 2] > a[i]:    # всплываем, пока родитель больше
	            a[(i - 1) // 2], a[i] = a[i], a[(i - 1) // 2]
	            i = (i - 1) // 2

	    def pop(self):
	        a = self.a
	        a[0], a[-1] = a[-1], a[0]         # последний на место корня, старый корень уходит в конец
	        top = a.pop()
	        i, n = 0, len(a)
	        while True:                       # просеиваем новый корень вниз
	            small, l, r = i, 2 * i + 1, 2 * i + 2
	            if l < n and a[l] < a[small]:
	                small = l
	            if r < n and a[r] < a[small]:
	                small = r
	            if small == i:
	                break
	            a[i], a[small] = a[small], a[i]
	            i = small
	        return top
	```

## Дерево поиска

- **Суть:** двоичное дерево, где левое поддерево меньше узла, а правое больше. Поиск, вставка и удаление идут по одной ветке. Если дерево не балансировать, на отсортированных вставках оно вырождается в список; поэтому используют сбалансированные: AVL, красно-чёрное, B-дерево.
- **Когда:**
	- нужен порядок по значению вместе с быстрыми вставками и удалениями
	- «ближайшее большее или меньшее», диапазон значений, k-й по порядку
- **Python:** в стандартной библиотеке сбалансированного дерева нет. Для статичных данных или редких вставок хватает отсортированного списка и `bisect` (поиск O(log n), вставка O(n)). Если нужна упорядоченность с частыми вставками, берут `SortedList` из пакета `sortedcontainers`.
- **Подробности:** основные паттерны и сравнение AVL, красно-чёрных и B-деревьев — в [[Паттерны задач#Дерево поиска]], там же врезка для эрудиции.

### Красно-чёрное дерево

- **Суть:** дерево поиска, у каждого узла которого есть цвет. Правила: корень чёрный; у красного узла оба ребёнка чёрные; на всех путях от узла до пустого места одинаковое число чёрных узлов. Из них следует высота не больше 2·log n. Новый узел красят в красный, а если он нарушил правило «красный не бывает под красным», чинят.
- **Схема (корректное дерево):**
	```mermaid
	flowchart TD
	    r["10"]:::black --> l["5"]:::red
	    r --> rr["15"]:::black
	    l --> ll["3"]:::black
	    l --> lr["7"]:::black
	    classDef red fill:#c0392b,stroke:#7b241c,color:#fff
	    classDef black fill:#222,stroke:#000,color:#fff
	```
	Проверка: красный 5 имеет чёрных детей; на пути от корня до любого пустого места два чёрных узла (10 и 3, 10 и 7, 10 и 15).
- **Как чинится вставка** (родитель красный, «дядя» — второй ребёнок деда):
	- **дядя красный:** красим родителя и дядю в чёрный, деда в красный и повторяем проверку уже для деда
	- **дядя чёрный, узел «внутри» (колено):** поворотом превращаем в «прямую линию» и переходим к следующему случаю
	- **дядя чёрный, узел «снаружи» (прямая):** красим родителя в чёрный, деда в красный и поворачиваем деда
- **Схема (вставка, дядя чёрный, узел «снаружи»):**
	```mermaid
	flowchart LR
	    subgraph before["до: N красный под красным P"]
	        direction TB
	        G1["G"]:::black --> P1["P"]:::red
	        G1 --> U1["U"]:::black
	        P1 --> N1["N"]:::red
	    end
	    subgraph after["после: красим P, G и поворачиваем G"]
	        direction TB
	        P2["P"]:::black --> N2["N"]:::red
	        P2 --> G2["G"]:::red
	        G2 --> U2["U"]:::black
	    end
	    before --> after
	    classDef red fill:#c0392b,stroke:#7b241c,color:#fff
	    classDef black fill:#222,stroke:#000,color:#fff
	```
	Поддеревья между узлами на схеме опущены. Если дядя красный, поворота нет: красим P и U в чёрный, G в красный и проверяем дальше уже G.
- **Удаление** устроено сложнее, в шаблоне его нет: на собеседовании его не просят, достаточно знать, что оно тоже чинится перекраской и не более чем тремя поворотами.
- **Шаблон:**
	```python
	# Пример: вставка в красно-чёрное дерево (по схеме из учебника Кормена). Узлы-листья заменены общим «стражем» nil
	RED, BLACK = True, False

	class RBNode:
	    def __init__(self, key, color=RED):
	        self.key, self.color = key, color
	        self.left = self.right = self.parent = None

	class RBTree:
	    def __init__(self):
	        self.nil = RBNode(None, BLACK)            # один чёрный узел вместо всех пустых мест
	        self.root = self.nil

	    def _left_rotate(self, x):                    # x.right становится на место x, x уходит влево-вниз
	        y = x.right
	        x.right = y.left
	        if y.left is not self.nil:
	            y.left.parent = x
	        y.parent = x.parent
	        if x.parent is self.nil:
	            self.root = y
	        elif x is x.parent.left:
	            x.parent.left = y
	        else:
	            x.parent.right = y
	        y.left = x
	        x.parent = y

	    def _right_rotate(self, x):                   # зеркальный вариант
	        y = x.left
	        x.left = y.right
	        if y.right is not self.nil:
	            y.right.parent = x
	        y.parent = x.parent
	        if x.parent is self.nil:
	            self.root = y
	        elif x is x.parent.right:
	            x.parent.right = y
	        else:
	            x.parent.left = y
	        y.right = x
	        x.parent = y

	    def insert(self, key):
	        z = RBNode(key)
	        z.left = z.right = self.nil
	        parent, cur = self.nil, self.root
	        while cur is not self.nil:                # обычный спуск, как в дереве поиска
	            parent = cur
	            cur = cur.left if key < cur.key else cur.right
	        z.parent = parent
	        if parent is self.nil:
	            self.root = z
	        elif key < parent.key:
	            parent.left = z
	        else:
	            parent.right = z
	        self._fix(z)

	    def _fix(self, z):                            # чиним нарушение «красный под красным»
	        while z.parent.color == RED:
	            if z.parent is z.parent.parent.left:
	                uncle = z.parent.parent.right
	                if uncle.color == RED:            # случай 1: дядя красный, только перекраска
	                    z.parent.color = uncle.color = BLACK
	                    z.parent.parent.color = RED
	                    z = z.parent.parent
	                else:
	                    if z is z.parent.right:       # случай 2: колено, выпрямляем
	                        z = z.parent
	                        self._left_rotate(z)
	                    z.parent.color = BLACK        # случай 3: прямая, поворот деда
	                    z.parent.parent.color = RED
	                    self._right_rotate(z.parent.parent)
	            else:                                 # то же самое зеркально, когда родитель — правый ребёнок
	                uncle = z.parent.parent.left
	                if uncle.color == RED:
	                    z.parent.color = uncle.color = BLACK
	                    z.parent.parent.color = RED
	                    z = z.parent.parent
	                else:
	                    if z is z.parent.left:
	                        z = z.parent
	                        self._right_rotate(z)
	                    z.parent.color = BLACK
	                    z.parent.parent.color = RED
	                    self._left_rotate(z.parent.parent)
	        self.root.color = BLACK                   # корень всегда чёрный
	```
- **Проверка на деле:** вставка тысячи значений по возрастанию (самый плохой случай для обычного дерева поиска) даёт дерево высотой 17, при оценке 2·log₂(1001) ≈ 20.
- **Сравнение с AVL:** врезка во вводном дереве поиска в шпаргалке, [[Паттерны задач#Дерево поиска]].

## Префиксное дерево

- **Суть:** дерево, в котором по ребру идёт один символ, а путь от корня до отмеченного узла — слово. Слова с общим началом делят общий путь. Поиск слова или префикса стоит O(длина слова) и не зависит от числа слов в словаре.
- **Когда:**
	- поиск по префиксу, автодополнение
	- проверка, входит ли слово в словарь, на ходу при обходе (например, по сетке)
	- самый длинный общий префикс
- **Схема (слова car, cat, do, dog):**
	```mermaid
	flowchart TD
	    root(("корень")) -- c --> c1(("c"))
	    c1 -- a --> c2(("a"))
	    c2 -- r --> car(("r")):::fin
	    c2 -- t --> cat(("t")):::fin
	    root -- d --> d1(("d"))
	    d1 -- o --> do(("o")):::fin
	    do -- g --> dog(("g")):::fin
	    classDef fin fill:#2e7d32,stroke:#1b5e20,color:#fff
	```
	Зелёные узлы — конец слова. `car` и `cat` делят путь `c → a`; `do` — слово и одновременно префикс слова `dog`, поэтому отмечено и оно.
- **Чего избегать:** памяти уходит много, особенно на редких словах. Для небольшого словаря хватит `set` строк и `startswith`.
- **Шаблон:**
	```python
	# Пример: Implement Trie. Узел — словарь «символ → дочерний узел», признак конца слова — ключ "$"
	class Trie:
	    def __init__(self):
	        self.root = {}

	    def insert(self, word):
	        node = self.root
	        for ch in word:
	            node = node.setdefault(ch, {})        # идём по символам, создавая недостающие узлы
	        node["$"] = True                          # здесь слово заканчивается

	    def _walk(self, s):                           # спускаемся по строке s, None если пути нет
	        node = self.root
	        for ch in s:
	            if ch not in node:
	                return None
	            node = node[ch]
	        return node

	    def search(self, word):                       # слово целиком есть в словаре
	        node = self._walk(word)
	        return node is not None and "$" in node

	    def starts_with(self, prefix):                # есть слово, начинающееся с prefix
	        return self._walk(prefix) is not None
	```

## Граф

- **Суть:** вершины и рёбра между ними (ориентированные или нет, с весами или без). Способ хранения определяет цену операций:
	- **список смежности** `graph[u] = [v, ...]`: память O(V + E), перебор соседей быстрый. Стандартный выбор
	- **матрица смежности** `m[u][v]`: память O(V²), проверка «есть ли ребро» за O(1). Подходит для плотных графов и небольшого V
	- **список рёбер** `[(u, v, w), ...]`: компактный, нужен там, где важны сами рёбра (минимальное остовное дерево, алгоритм Беллмана — Форда)
- **Схема (один граф, три способа хранения):**
	```mermaid
	flowchart LR
	    v0((0)) --- v1((1))
	    v0 --- v2((2))
	    v1 --- v3((3))
	    v2 --- v3
	    v3 --- v4((4))
	```
	Список смежности: `{0: [1, 2], 1: [0, 3], 2: [0, 3], 3: [1, 2, 4], 4: [3]}`. Список рёбер: `[(0,1), (0,2), (1,3), (2,3), (3,4)]`. В матрице смежности 5×5 клеток, единицы стоят на местах рёбер симметрично.
- **Когда:**
	- связи между объектами произвольные, а не иерархические
	- сетка, игровое поле, зависимости, маршруты
- **Python:** `defaultdict(list)` для списков смежности; сетку обычно не превращают в граф, соседей считают по координатам.
- **Связанные паттерны:** весь раздел [[Паттерны задач#Графы]].
- **Задачи:** см. раздел «Графы» шпаргалки.

## Дерево Фенвика и дерево отрезков

- **Суть:** структуры для запросов на отрезках, когда значения ещё и меняются. Префиксные суммы отвечают на запрос за O(1), но любое изменение стоит O(n). Дерево Фенвика (бинарное индексное дерево) делает и запрос суммы по префиксу, и обновление одного элемента за O(log n). Дерево отрезков делает то же для любой ассоциативной операции (сумма, минимум, максимум, НОД) и умеет обновлять сразу целый отрезок, но в коде он заметно длиннее, чем дерево Фенвика, которое умеет только суммы.
- **Схема (дерево Фенвика, n = 8):**
	```mermaid
	flowchart BT
	    t1["t1 = a1"] --> t2["t2 = a1..a2"]
	    t2 --> t4["t4 = a1..a4"]
	    t3["t3 = a3"] --> t4
	    t4 --> t8["t8 = a1..a8"]
	    t5["t5 = a5"] --> t6["t6 = a5..a6"]
	    t6 --> t8
	    t7["t7 = a7"] --> t8
	```
	Узел `t[i]` хранит сумму `lowbit(i)` элементов, заканчивающихся на `i`, а родитель — это `i + lowbit(i)`. Обновление `a3` идёт вверх по цепочке `t3 → t4 → t8`. Запрос `prefix(7)` складывает `t7 + t6 + t4` (идёт вниз, отбрасывая младший бит: 7 → 6 → 4 → 0).
- **Когда:**
	- «сумма на отрезке», «минимум на отрезке» с обновлениями между запросами
	- подсчёт элементов меньше данного по ходу прохода (инверсии, рейтинг)
- **Сложность:** T: запрос и обновление O(log n), построение O(n) или O(n log n) · S: O(n)
- **Шаблон:**
	```python
	# Пример: Range Sum Query - Mutable через дерево Фенвика. Индексы в дереве начинаются с 1
	class Fenwick:
	    def __init__(self, n):
	        self.t = [0] * (n + 1)

	    def add(self, i, delta):                  # прибавить delta к элементу i
	        i += 1
	        while i < len(self.t):
	            self.t[i] += delta
	            i += i & -i                       # i & -i — младший единичный бит, переходим к следующему охватывающему узлу

	    def prefix(self, i):                      # сумма a[0..i]
	        i += 1
	        s = 0
	        while i > 0:
	            s += self.t[i]
	            i -= i & -i                       # убираем младший единичный бит
	        return s

	# сумма на отрезке [l, r]: prefix(r) - prefix(l - 1), при l = 0 вычитаем 0
	# обновление значения до x: add(i, x - a[i]) и запомнить a[i] = x
	```
- **Связанные паттерны:** [[Паттерны задач#Префиксные суммы]] (без обновлений хватает массива), [[Сортировки#Сортировка слиянием]] (другой способ посчитать инверсии)
- **Задачи:**
	- [Range Sum Query - Immutable](https://leetcode.com/problems/range-sum-query-immutable/) · Easy · нюанс: значения не меняются, хватает префиксных сумм
	- [Range Sum Query - Mutable](https://leetcode.com/problems/range-sum-query-mutable/) · Medium
	- [Count of Smaller Numbers After Self](https://leetcode.com/problems/count-of-smaller-numbers-after-self/) · Hard · нюанс: идём справа налево, значения (после сжатия до рангов) кладём в Фенвик и спрашиваем сумму по меньшим
	- [The Skyline Problem](https://leetcode.com/problems/the-skyline-problem/) · Hard · нюанс: решается кучей по событиям, но дерево отрезков с обновлением на отрезке тоже подходит

## LRU-кэш

- **Суть:** кэш фиксированного размера, который при переполнении выкидывает давно не использованный элемент. Для O(1) на всё нужны две структуры сразу: хеш-таблица «ключ → узел» для поиска и двусвязный список по давности использования. Использованный узел переносим в начало списка, лишний убираем с конца. Это классический пример, как структуры данных комбинируют.
- **Схема:**
	```mermaid
	flowchart LR
	    subgraph H["dict: ключ → узел"]
	        direction TB
	        k1["1"]
	        k2["2"]
	        k3["3"]
	    end
	    head(["head"]) <--> n3["3 : c"] <--> n1["1 : a"] <--> n2["2 : b"] <--> tail(["tail"])
	    k1 -.-> n1
	    k2 -.-> n2
	    k3 -.-> n3
	```
	Ближе к `head` — самые свежие, у `tail` — самый старый. `get(1)` находит узел через `dict` и переносит его сразу после `head`; при переполнении выкидываем узел перед `tail` и его ключ из `dict`.
- **Когда:**
	- кэширование результатов дорогих вызовов
	- структура, у которой несколько операций должны быть O(1)
- **Python:** `collections.OrderedDict` уже совмещает словарь и порядок, поэтому в задаче хватает пары вызовов. На собеседовании могут попросить собрать из `dict` и самописного двусвязного списка. Для готовых случаев есть `functools.lru_cache`.
- **Шаблон:**
	```python
	# Пример: LRU Cache на OrderedDict. Ключи лежат от самого старого к самому свежему
	from collections import OrderedDict

	class LRUCache:
	    def __init__(self, capacity):
	        self.cap = capacity
	        self.d = OrderedDict()

	    def get(self, key):
	        if key not in self.d:
	            return -1
	        self.d.move_to_end(key)               # использовали — теперь самый свежий
	        return self.d[key]

	    def put(self, key, value):
	        self.d[key] = value
	        self.d.move_to_end(key)
	        if len(self.d) > self.cap:
	            self.d.popitem(last=False)        # выбрасываем самый старый
	```
- **Без OrderedDict** (как просят на собеседовании): словарь «ключ → узел» и двусвязный список из раздела [[#Связный список]]. Самый свежий узел стоит сразу после головы, самый старый перед хвостом.
	```python
	class LRUCache:
	    def __init__(self, capacity):
	        self.cap = capacity
	        self.map = {}                             # ключ → узел списка
	        self.list = DList()                       # DList и Node из раздела про связный список

	    def get(self, key):
	        if key not in self.map:
	            return -1
	        n = self.map[key]
	        self.list.remove(n)                       # вырезали за O(1) и вставили в начало: теперь он самый свежий
	        self.list.add_front(n)
	        return n.val

	    def put(self, key, val):
	        if key in self.map:
	            n = self.map[key]
	            n.val = val
	            self.list.remove(n)
	            self.list.add_front(n)
	            return
	        n = Node(key, val)
	        self.map[key] = n
	        self.list.add_front(n)
	        if len(self.map) > self.cap:
	            last = self.list.pop_back()           # самый старый
	            del self.map[last.key]                # поэтому узлу нужен ключ: иначе непонятно, что убирать из словаря
	```
- **Задачи:**

	- [LFU Cache](https://leetcode.com/problems/lfu-cache/) · Hard · нюанс: выбрасываем наименее часто используемый, при равенстве давнего; нужен словарь «частота → упорядоченный набор ключей»

## Для эрудиции

- **Фильтр Блума.** Вероятностное множество: массив битов и несколько хеш-функций. Ответ «нет» точный, ответ «да» может быть ложным. Экономит память, когда нужно быстро отсеять заведомо отсутствующие ключи (кэши, базы данных).
- **Разреженная таблица (sparse table).** Минимум или максимум на отрезке за O(1) после построения за O(n log n). Годится, только когда массив не меняется.
- **Список с пропусками (skip list).** Упорядоченный связный список со «скоростными» уровнями. Балансируется случайностью, а не поворотами. Используется в упорядоченных множествах Redis.
- **Кольцевой буфер.** Массив фиксированной длины с двумя индексами, начало и конец «ходят по кругу». Очередь без перераспределения памяти, на нём строят потоки, сетевые буферы, логи последних событий.
- **B-дерево и B+-дерево.** Деревья с сотнями детей у узла для данных на диске. Основа индексов в базах данных. Подробнее — во врезке про сбалансированные деревья в шпаргалке.
- **LSM-дерево.** Запись идёт в память, затем сбрасывается на диск отсортированными кусками, которые фоново сливаются. Основа многих хранилищ, где записей больше, чем чтений.
- **Кучи с быстрым слиянием и уменьшением ключа.** Фибоначчиева куча даёт Дейкстре O(E + V log V), но на практике бинарная куча почти всегда быстрее из-за констант.
- **Чего нет в Python.** Нет встроенных дерева поиска, кучи с удалением по ключу и двусвязного списка. Все они пишутся руками или берутся из `sortedcontainers`.
